## 🎯 一、核心业务定位

**产品名称**：OpsBrain AI（智维大脑） - 企业级智能 DevOps 知识库与工单自动化 Agent 平台

**一句话定位**：
> 用 AI Agent 替代传统的"搜文档 + 手工开工单"流程，让运维人员通过自然语言对话，秒级获取故障解决方案并自动创建工单。

## 🔥 二、解决的真实痛点

### 痛点 1：运维文档分散，检索效率低下

**传统场景**：
- 运维人员遇到 `CrashLoopBackOff` 故障
- 需要翻阅 100+ 页 K8s 手册、Confluence、钉钉群聊天记录
- 搜索关键词可能不精准，找到的文档版本过期
- **平均耗时**：15-30 分钟，甚至更久

**OpsBrain 解决方式**：
```
用户输入：Pod 一直 CrashLoopBackOff 怎么办？

AI 自动：
1. 向量检索知识库（毫秒级）
2. 召回《K8s 故障处理手册 P14》+ 内部案例库
3. 流式输出：
   "根据《K8s 手册》P14，CrashLoopBackOff 原因可能是：
    1. 启动脚本错误（占比 60%）
    2. 镜像拉取失败（占比 25%）
    3. 资源配额不足（占比 15%）

    建议优先执行：
    kubectl logs <pod> --previous
    kubectl describe pod <pod>

    已为你创建工单 TKT-20260715-0012"
```

**效率提升**：15 分钟 → **3 秒**，提速 **300 倍**

---

### 痛点 2：工单流转繁琐，人工填写低效

**传统场景**：
- 运维人员找到故障原因后，需手动登录 JIRA/钉钉
- 填写：标题、优先级、模块、堆栈、负责人、SLA...
- 关联 Trace ID、复制日志、截图
- **平均耗时**：5-10 分钟

**OpsBrain 解决方式**：
```
AI 对话中自动识别：
- 检测到故障类型 → 自动调用 createDevOpsTicket 工具
- 从对话上下文提取：标题、优先级、模块、堆栈
- 关联当前会话的 traceId
- 自动分配负责人（根据模块规则）
- 自动生成工单号：TKT-20260715-0012
```

**效率提升**：10 分钟 → **0 秒**（全自动），节省 **100% 人力**

### 痛点 3：知识断层，新人上手慢

## 一、知识库来源渠道与可靠性保障

### 1.1 知识库来源渠道（按可靠性排序）

#### **Tier 1：企业内部沉淀（可靠性 ★★★★★）**
- **运维工单历史**：已解决的工单 + 解决方案（结构化数据）
- **Wiki/Confluence 文档**：运维手册、排障 SOP、架构图
- **事故复盘报告**：故障根因分析 + 改进措施
- **监控告警规则**：Prometheus/Grafana 规则配置 + 处理流程
- **代码仓库 + CI/CD 配置**：部署脚本、回滚脚本、健康检查脚本

**可靠性保障**：
- 企业内部数据天然适配自身技术栈，准确率最高
- 需要建立"知识审核机制"：老运维 Review 新入库的知识
- 定期清理过期知识（如旧版本 K8s 1.18 的排障方案）

---

#### **Tier 2：官方技术文档（可靠性 ★★★★☆）**
- **云厂商文档**：阿里云帮助中心、AWS 文档、Azure Docs
- **开源项目官方 Docs**：Kubernetes 官方文档、Redis 官方文档
- **数据库厂商文档**：MySQL Reference Manual、PostgreSQL Docs

**可靠性保障**：
- 通过 Web 爬虫 + 语义去重，定期同步最新版本
- 版本匹配机制：企业用 MySQL 8.0，就只入库 8.0 的文档
- 标注来源："根据《MySQL 8.0 官方文档》第 15.2.3 章节..."

---

#### **Tier 3：行业知识库（可靠性 ★★★☆☆）**
- **Stack Overflow**：高赞问答（vote > 50）
- **GitHub Issues**：已关闭的 bug + 解决方案
- **技术博客**：字节、阿里、美团的技术博客

**可靠性保障**：
- 只采纳"官方回复"或"维护者确认"的答案
- 引入"多源验证"：同一个问题在 3 个渠道得到一致答案才入库
- 定期人工抽查：每月抽查 10% 知识库内容

---

#### **Tier 4：合成知识（可靠性 ★★☆☆☆）**
- **AI 生成总结**：用 LLM 将多个碎片化知识合成为标准化 SOP
- **模拟场景推演**：用 AI 生成"如果 Redis 内存占用 90%，可能的 5 种原因"

**可靠性保障**：
- **必须标注"AI 生成"**，不能伪装成人工知识
- 由资深运维审核后才能正式入库
- 用户可以反馈"此方案无效"，触发重新生成

---


```java
public enum OperationRisk {
    LOW,     // 低风险：清理日志、重启从库 → 可自动执行
    MEDIUM,  // 中风险：重启服务、修改配置 → 需人工审批
    HIGH     // 高风险：删库、重启主库 → 强制人工审批 + 二次确认
}

@Service
public class AutoRemediationService {
    public void executeScript(String script, OperationRisk risk) {
        if (risk == OperationRisk.HIGH) {
            // 强制人工审批
            sendApprovalRequest(script);
        } else if (risk == OperationRisk.MEDIUM) {
            // 默认需审批，可配置为自动执行
            if (isAutoExecutionEnabled()) {
                executeDirectly(script);
            } else {
                sendApprovalRequest(script);
            }
        } else {
            // 低风险直接执行
            executeDirectly(script);
        }
    }
}
```

### **优化 2：增加工具调用的"审批流"机制**

**当前问题**：

```java
// 1. 定义高危工具白名单

}
```

### 第三步：OpsBrain AI 接收 Webhook

#### 3.1 创建 `PrometheusWebhookController`

**文件**：`src/main/java/com/devops/agent/controller/PrometheusWebhookController.java`

```java
package com.devops.agent.controller;

import com.devops.agent.application.DevOpsAgentService;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Map;

/**
 * Prometheus Alertmanager Webhook 接收器
 * <p>
 * 用途：接收 Prometheus 告警，触发 AI Agent 自动分析与处理
 * </p>
 *
 * @author OpsBrain AI
 * @since 2026-07-20
 */
@Slf4j
@RestController
@RequestMapping("/api/v1/webhook")
@RequiredArgsConstructor
public class PrometheusWebhookController {

    private final DevOpsAgentService agentService;
    private final ObjectMapper objectMapper;

    /**
     * 接收 Prometheus 告警
     * <p>
     * Alertmanager Webhook 格式：
     * {
     *   "alerts": [
     *     {
     *       "status": "firing",
     *       "labels": {
     *         "alertname": "HighLatency",
     *         "severity": "warning",
     *         "service": "law-firm-platform"
     *       },
     *       "annotations": {
     *         "summary": "接口响应时间过长",
     *         "description": "接口平均响应时间 3.2s，超过 2 秒阈值"
     *       }
     *     }
     *   ]
     * }
     * </p>
     */
    @PostMapping("/prometheus")
    public Map<String, Object> handlePrometheusAlert(@RequestBody Map<String, Object> payload) {
        log.info("📨 [Webhook] 收到 Prometheus 告警: {}", payload);

        try {
            // 1. 解析告警列表
            List<Map<String, Object>> alerts = (List<Map<String, Object>>) payload.get("alerts");

            if (alerts == null || alerts.isEmpty()) {
                log.warn("⚠️ [Webhook] 告警列表为空，跳过处理");
                return Map.of("status", "ok", "message", "no alerts");
            }

            // 2. 处理每个告警
            for (Map<String, Object> alert : alerts) {
                String status = (String) alert.get("status");  // firing / resolved
                Map<String, String> labels = (Map<String, String>) alert.get("labels");
                Map<String, String> annotations = (Map<String, String>) alert.get("annotations");

                String alertName = labels.get("alertname");
                String severity = labels.get("severity");
                String service = labels.get("service");
                String summary = annotations.get("summary");
                String description = annotations.get("description");

                log.info("🚨 [Webhook] 处理告警: {} | {} | {} | {}", alertName, severity, service, summary);

                // 3. 构造 AI 提问
                String query = buildAiQuery(alertName, severity, service, summary, description, status);

                // 4. 异步触发 AI Agent 分析（不阻塞 Webhook 响应）
                agentService.handleAlertAsync(query, alertName, severity);
            }

            return Map.of("status", "ok", "message", "alerts processed");

        } catch (Exception e) {
            log.error("❌ [Webhook] 处理告警失败", e);
            return Map.of("status", "error", "message", e.getMessage());
        }
    }

    /**
     * 构造给 AI 的提问
     */
    private String buildAiQuery(String alertName, String severity, String service,
                                 String summary, String description, String status) {
        if ("resolved".equals(status)) {
            return String.format("告警已恢复：%s 系统的 %s 告警已解除。", service, alertName);
        }

        return String.format("""
            【紧急告警】%s 系统触发 %s 级别告警

            告警名称：%s
            问题描述：%s
            详细信息：%s

            请立即分析原因并给出处理建议。如果是已知问题，自动创建工单。
            """, service, severity, alertName, summary, description);
    }
}
```

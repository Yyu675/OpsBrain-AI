## E4 · 大数据量分页（625 工单，批88-L 补测）

E1~E3 时 dev 库仅 25 张工单，「500+ 工单掉帧」曾是诚实声明的未覆盖边界。
本批插入 600 张压测工单（总量 625）实测后清理，边界已闭合。

| 场景 | 中位延迟（3 次取样） |
|---|---|
| page=1 size=20 | 14.7ms |
| page=1 size=100 | 28.7ms |
| page=15 size=20（中段） | 15.5ms |
| **page=31 size=20（深页）** | **14.8ms** |
| status=PROCESSING 过滤 | 16.1ms |
| keyword=stress 模糊搜索 | 17.6ms |
| sort=SLA_ASC | 14.1ms |

**关键结论**：深页（page=31，OFFSET 600）与首页延迟一致（14.8 vs 14.7ms），
无 OFFSET 扫描退化——服务端分页 + 复合索引（批87 落库）真实生效。
size=100 也仅 28.7ms。625 工单规模下全场景 < 30ms。

> 注：此为后端 API 层延迟。前端渲染层（TicketList 两级 computed，批85 已优化）
> 在 625 行规模下需浏览器实测（见任务 #16 Playwright），但单页只渲染 size 行
> （20/100），不随总量增长，前端不构成瓶颈。

语义缓存预热后 100 并发 SSE 仅 19/100（虚拟线程/SSE 发射器瓶颈需独立排查）。

> SSE 连接池，把 100 并发 SSE 约束留给预发布环境专项压测。

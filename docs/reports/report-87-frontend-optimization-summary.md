## 二、已完成优化项

### 2.1 富文本编辑器优化（P2-高频）

**问题**：
- Element Plus 自带的 Tinymce 语言包体积 800+ KB（gzip 后 274 KB）
- 默认配置加载 22 种语言包，但中文用户只需要 `zh-CN`

**优化方案**：
1. ✅ 富文文本编辑器默认改为 **Markdown 模式**（保留富文本切换选项）
2. ✅ Tinymce 语言包精简到核心 12 种：
   ```typescript
   // 从 22 种 → 12 种（核心语言）
   const CORE_LANGUAGES = [
     'zh-CN', 'en', 'ja', 'ko',      // 东亚核心
     'es', 'fr', 'de', 'ru',         // 欧洲主要
     'ar', 'pt', 'it', 'nl'          // 运维常见
   ]
   ```

**收益**：
- **构建速度提升 77%**：17.91s → 4.10s
- **运行时优化**：默认 Markdown 模式，首次加载不下载 Tinymce（节省 274 KB）
- **体积不变**：因为已使用 `defineAsyncComponent` 懒加载，打包体积不变（800.88 KB）

**落地文件**：
- `devops-platform-frontend/src/components/knowledge/ArticleFormDialog.vue`（默认 Markdown）
- `devops-platform-frontend/src/components/knowledge/RichTextEditor.vue`（语言包精简）

### 2.2 TanStack Query 缓存优化（P2-高频）

**问题**：
- 所有 Query 默认 `staleTime: 0`，每次切换都重新请求
- 频繁的网络请求影响用户体验（闪烁、加载）

**优化方案**：
为不同业务场景配置合理的缓存策略：

| Query | staleTime | gcTime | 说明 |
|-------|-----------|--------|------|
| Dashboard 统计 | 60s | 10min | 统计数据变化缓慢 |
| 工单列表 | 10s | 5min | 变化较频繁，短暂缓存 |
| 工单热门标签 | 60s | 10min | 标签分布变化缓慢 |
| 告警列表 | 15s | 3min | 需要较及时数据，短暂缓存 |
| 告警详情 | 30s | 5min | 变化不频繁 |
| 审批列表 | 20s | 5min | 变化较频繁，短暂缓存 |
| 审批待审数 | 30s | 10min | 角标数字变化不频繁 |

**收益**：
- 减少重复请求（预计减少 40-60%）
- 页面切换更流畅（无闪烁）
- 降低服务器负载

**落地文件**：
- `src/api/queries/dashboard.query.ts`
- `src/api/queries/tickets.query.ts`
- `src/api/queries/alerts.query.ts`
- `src/api/queries/approval.query.ts`

## 三、待实施优化项（下一步）

### 3.1 P2-低频优化（可选，性价比低）

#### A. 知识库迁移到 TanStack Query（时间成本：2-3 小时）

**现状**：
- 知识库仍使用传统 store 模式（手动 loading/error/data）
- 没有自动缓存和失效机制

**收益**：
- 与其他模块统一技术栈
- 自动缓存和失效（无需手动 `fetchList`）

**建议**：**暂缓**，知识库访问频率低，优化收益有限

#### B. 路由懒加载优化（时间成本：1 小时）

**现状**：
- 所有路由已使用 `component: () => import()`

**可优化点**：
- 检查是否有组件被多个路由同时引用导致重复打包

**建议**：**暂缓**，当前路由拆分已合理

#### C. 图片优化（时间成本：30 分钟）

**现状**：
- 404 页面使用 SVG 插图（体积小）
- Home 页面 Hero 图未优化

**可优化点**：
- 使用 WebP 格式（体积减少 30-50%）
- 图片懒加载

**建议**：**暂缓**，当前项目图片很少（仅 Home 页一张）

### 3.2 体验优化（P2-待实施）

#### D. 骨架屏加载（时间成本：2 小时）

**现状**：
- 列表页使用 `v-loading` 全屏遮罩
- 用户体验不够友好（突兀、感觉慢）

**优化方案**：
- 替换为骨架屏（Skeleton）加载
- 保持页面结构稳定，减少闪烁

**收益**：
- 感知加载速度提升 30-50%
- 用户体验更现代化

**建议**：**推荐实施**（性价比高）

#### E. 虚拟列表（时间成本：3 小时）

**现状**：
- 工单列表/告警列表使用 `el-table` 全量渲染
- 当前分页大小 20 条，性能无问题

**触发条件**：
- 分页大小上调到 50/100 条时才需要

**建议**：**暂缓**，当前数据量下无性能瓶颈

## 六、风险与注意事项

### 6.1 缓存策略风险

**风险**：
- 缓存时间过长可能导致数据不一致
- 缓存时间过短失去优化意义

**缓解措施**：
- 写操作后统一 `invalidateQueries`（已有机制）
- 重要数据（工单详情、告警详情）缓存时间设置较短（15-30s）
- 统计类数据（Dashboard、标签）缓存时间较长（60s）

### 6.2 语言包精简风险

**风险**：
- 如果用户需要非核心语言（如泰语、越南语），会回退到英文

**缓解措施**：
- 保留核心 12 种语言（覆盖 90% 用户）
- 用户反馈需要时可随时添加

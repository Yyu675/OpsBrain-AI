# OpsBrain 部署运维手册（S5-2：5-2.1~5-2.4 / 批 37）

> 单一事实源：从零起栈到备份恢复演练。值班现场另查 `docs/09-operations/值班SOP.md`。

## 1. 从零起栈（5-2.4）

```bash
cp .env.example .env            # 必填 ALIBABA_API_KEY / ALERT_WEBHOOK_SECRET 见 .env.example 注释
docker compose up -d --build    # 首启:Flyway 自建 schema(S0-1),勿手灌 init.sql
curl http://localhost:8088/ai/api/v1/health/ping   # 存活探针:只证进程活
```

起栈后三查：① `docker compose ps` 全 healthy;② `GET /ai/actuator/health`
（含 postgres/redis/向量库可达，DeepSeek 仅 REPORT 不拖 DOWN——口径见 application.yml
management 注释）;③ Prometheus targets 页 `opsbrain` job UP(5-2.5 自监控）。

## 2. 生产运行件预算（5-2.1，批 37 立）

| 件 | 预算 | 语义 |
| --- | --- | --- |
| app 内存 | **2g limit / 768m reservation** | JVM MaxRAMPercentage=75 → ~1.5g 堆；超限语义是 OOMKill+编排重启，不是降速。ExitOnOutOfMemoryError 已配，OOM 即干净退出 |
| app CPU | 1.5 | SSE 流式与评测并发按此预；持续触顶先看 LLM 限流配速（60/s,S0-3 校订案） |
| 全容器日志 | json-file 50m × 5（锚点统一） | 有界是告警前提：磁盘满事故的最常见源头就是没人限日志 |

改预算先看基线，别拍脑袋——预算与告警规则互为表里。

## 3. 密钥管理（5-2.2：当前口径与迁移路径）

当前：`.env` 环境变量注入，`.gitignore` 已挡入库；容器内 `docker inspect` 可见——**这是已知风险，不是事故**。
迁移路径（按安全等级排序，选型一次性定，勿混用）:

| 级 | 方案 | 适用 |
| --- | --- | --- |
| L0 | 现状 .env + 文件属主 600 | 单机内网试点（当前） |
| L1 | Docker Compose `secrets:`(file 挂入）+ 应用读 `/run/secrets/*` | 单机上生产第一刀，改造量小 |
| L2 | Vault/KMS + 启动期拉取 | 多实例/合规要求 |

**铁律**：任何一级都禁止密钥进镜像层、进日志（脱敏纪律见报告 97 族）、进 git。
从 env 迁 secrets 时同步改 `docker-compose.yml` 注释与 .env.example。

## 4. 备份与恢复（5-2.3)

```bash
scripts/backup.sh                 # 产出 backups/<ts>/{postgres.dump,minio.tar.gz,manifest.json}
scripts/restore.sh --from backups/<ts> --confirm   # 破坏性操作,两次确认才动手
```

- **备份物三件互相锁死**:manifest 记录双料 SHA256,restore 第一步就拒收串件/残件；
- **保留默认 14 天**(`RETENTION_DAYS` 覆写）——备份不修剪就是慢性磁盘炸弹；
- **恢复顺序不可换**:stop app → 还库 → 还桶 → 起栈 → 三查（工单数/文档数/最近告警）;
- **演练纪律**：每季度在其运行环境（非生产）演一次，记进 `docs/09-operations/恢复演练记录.md`
  （首栏模板在下表）——**备份脚本存在过 ≠ 能恢复，演练记录才是 13.1 验收点**。

| 日期 | 备份批次 | 环境 | pg_restore 结果 | MinIO 回灌 | 三查对账 | 参与者 | 备注 |

## 5. 自身监控（5-2.5，批 37 落地件）

- `monitoring/prometheus.yml`:`opsbrain` job 抓 `/ai/actuator/prometheus`;
- `monitoring/alert.rules.yml`:`opsbrain-app-alerts` 组——OpsBrainDown(P0,2m)/

## 6. API 入口限流（批 45 落件）

- 机制：`RateLimitFilter` 按（规则， 客户端IP)分桶发 resilience4j 闸，超员即 429（不排队）；配置在 `application.yml` 的 `devops.security.rate-limit`;
- 出厂两闸：**登录 10/60s**(IP)、**AI 对话 20/60s**(IP);`RATE_LIMIT_ENABLED=false` 仅压测排障用，常态不该下闸；
- 限流键 = `ClientIpResolver` 口径：前置代理部署必须配 `TRUSTED_PROXIES`（否则所有访客共用代理 IP 一只桶）；
- 已知边界（类注四条全在案）:IP 桶非用户桶 / 桶表 2 万硬顶粗回收 / 单机口径（多副本全局配额≈配额×副本数）。

## 7. 日志格式（批 48 落件）

- **prod 全量 ECS JSON**(Boot 3.5.6 原生结构化日志，console+file 双道）;dev 保持人类可读 pattern；
- 排障姿势：`docker compose logs app | jq -c 'select(.traceId=="<截图上的 traceId>")'` 一拉收拢单请求全链；
- 回滚走改档（git 审计），没有运行时开关——与本文件密钥 auth 同款「口子最小化」。

## 8. 业务指标与业务告警（批 49/50 落件）

- `BusinessMetrics` 四枚水位计：`opsbrain_tickets_total` / `opsbrain_tickets_urgent_pending` / `opsbrain_alerts_active` / `opsbrain_approvals_pending`（经 prometheus job 进库）;
- 业务告警组起步阈值：UrgentPendingHigh(>10/15m)、ApprovalBacklog(>5/1h)——**真窗首周按 P95 水位校准**；供体崩→NaN 比较恒 false 不误报（依赖/Down 闸另责）。
- 健康观测的「三面」从此齐了：进程（actuator 原生）、资源池（Hikari 三兄弟）、业务（此四枚）——看板别只盯进程活没活。

## 9. OTLP 指标导出（批 52 落件）

- 默认**关**:`OTLP_EXPORT_ENABLED=true` 且 `OTLP_METRICS_URL=http(s)://collector:4318` 后起效，步进 60s;
- 与 prom 拉模型**共存互不干扰**——告警面继续由 prom 抓（§5),otlp 供长期画像/趋势（接 Tempo/Mimir/云监控）；接 collector 前先接好告警面的账（别把画像当告警）。

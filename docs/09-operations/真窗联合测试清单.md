## T6. 告警风暴 100 RPS(S5-4.1 放行尺）

【前置】`.env` 的 webhook token 与 app 一致；压 100 RPS 需提闸门：
compose env 覆盖 `DEVOPS_ALERT_WEBHOOK_RATELIMIT=7000` 后重启 app
（不提闸也可——直接看 T7 的 429 语义）。

【步骤】
```bash
BASE=http://localhost:8080/ai TOKEN=<token> RPS=100 DURATION=120 \
  bash scripts/lab/alert_loadgen.sh
docker compose exec postgres psql -U opsbrain -d opsbrain -c \
 "SELECT count(*) AS 风暴工单数 FROM sys_devops_ticket WHERE title LIKE '%LabHighCpuLoad%';
  SELECT service, occurrence_count FROM sys_alert WHERE alert_name='LabHighCpuLoad' ORDER BY id;"
```

【判定】2xx ≥ 99%;同一指纹风暴只聚合为一张工单（occurrence_count 万级递增，不新建单）;
脚本混入的 1/10 新源各自独立建单；app CPU/内存无异常爬坡。
【回帖产物】`loadgen-*.csv` 汇总行 + PSQL 输出；S5-4.1 格消号。

## T7. Webhook 拒闸语义（401/429，报告 128 真窗核验）

【步骤】
```bash
TOKEN=x BASE=http://localhost:8080/ai RPS=300 DURATION=20 MODE=reject \
  bash scripts/lab/alert_loadgen.sh     # 无 token 腔:expect 401 一族
curl -i -X POST http://localhost:8080/ai/api/v1/alerts/webhook \
  -H "Content-Type: application/json" -H "X-Webhook-Token: WRONG" -d '{}'  # expect 401
# 超额放火（250+/60s 未提闸时）→ expect 429 携 Retry-After 头
```
【判定】401 与 429 语义分明（不混 403),429 带 Retry-After。
【回帖产物】三次请求的状态码/响应头快照。

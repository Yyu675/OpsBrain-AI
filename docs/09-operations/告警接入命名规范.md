# 告警接入命名规范 — labels / annotations 契约

> 读者：写 Prometheus 规则的同事。读完这一页，你的告警在 OpsBrain 值班卡片上
> 就是「拿来即用」的：值班人不用点开平台就知道影响、数值和第一步做什么。
>
> 代码侧对偶：`AlertAnnotationKeys.java`（键字典）+ `AlertNotifyTemplate.java`
> （卡片渲染）。**新增键必须三处联动**（字典 + 模板渲染位 + 本文档），
> 只加字典不加渲染位，平台会安静收下但永远不显示——比不显示更糟。

## 一、labels 与 annotations 的分工铁律

| | labels | annotations |
|---|---|---|
| 给谁看 | **机器**：路由、去重、聚合 | **人**：值班卡片正文 |
| 变化频率 | 稳定、低基数（进 dedupKey） | 每条可变（数值、描述） |
| 放什么 | severity/service/module/alertname/instance | summary/impact/current_value/…（见下） |
| 禁忌 | 把易变值（时间戳、traceId）放进去——去重失效=风暴 | 把路由依据放这里——平台不看它做决策 |

一句话：**会变的信息进 annotations，用来分拣的信息进 labels。**
OpsBrain 的去重键由 labels 派生；annotations 原样落 `sys_alert.annotations_json`
并渲染进卡片，不参与任何路由判断。

## 二、annotation 键字典（9 键）

| 键 | 档位 | 语义 | 卡片呈现 |
|---|---|---|---|
| `summary` | ⭐ 必填 | 一句话说清「什么东西怎么了」，人话，不是指标名 | 第一行「摘要」 |
| `description` | 建议 | 核心描述（Alertmanager 标准键沿用）；缺 `summary` 时兜底顶摘要位 | 「详情」 |
| `impact` | ⭐ 建议 | 影响面：谁受影响、影响多大。「部分用户下单失败」胜过「服务异常」 | 「影响」（排在指标前） |
| `current_value` | ⭐ 建议 | 当前值，**带单位**（`12.3%` / `1.7GB`），与 `threshold` 成对时渲染「12.3%（阈值 5%）」 | 「指标」/「当前值」 |
| `threshold` | 建议 | 触发阈值，同样带单位 | 同上 |
| `likely_cause` | 可选 | 最可能原因（一条即可，多因写首步动作里） | 「可能原因」 |
| `first_action` | ⭐ 建议 | 值班第一步做什么，编号式：`1) 看盘 2) 查发布` | 「首步动作」 |
| `runbook_url` | 建议 | 处置手册直链（别只给目录页） | 「Runbook」 |
| `dashboard_url` | 可选 | 该服务监控大盘直达 | 「监控大盘」 |

卡片渲染纪律（平台侧承诺，测试钉死）：

- **顺序固定**：摘要/影响 → 指标（当前值/阈值/持续）→ 详情/原因/动作 → 链接 → 工单。
  先说影响再说指标——值班第一屏回答「要不要现在爬起来」。
- **缺料整段省略**：没填的键整行不出现，绝不渲染 `null` 或空占位。
- 全键填齐时卡片仍受 1500 字符上限保护，超长砍尾留「全文见告警详情页」回链。

## 三、labels 约定

| 键 | 要求 | 用途 |
|---|---|---|
| `severity` | 必填，`critical`/`warning`/`info` | 映射 P0/P1/P2~P4（映射表单源在后端） |
| `service` | 必填，服务注册名小写连字符（`order-service`） | 卡片标题、按服务下钻 |
| `module` | 建议，模块中文名或英文代号 | 卡片归属展示 |
| `alertname` | 必填，PascalCase 稳定命名（`OrderServiceHttp5xxHigh`） | 去重键成分，改名=新告警流 |
| `instance` | 建议，实例标识 | 卡片标题「| instance」下钻位 |

## 四、完整规则示例（Prometheus rule yaml）

```yaml
groups:
  - name: order-service
    rules:
      - alert: OrderServiceHttp5xxHigh
        expr: |
          sum(rate(http_requests_total{job="order-service",code=~"5.."}[5m]))
            / sum(rate(http_requests_total{job="order-service"}[5m])) > 0.05
        for: 5m
        labels:
          severity: critical        # → P1，高危走强提醒
          service: order-service
          module: 交易链路
          instance: prod-order-cluster
        annotations:
          summary: "订单服务 5xx 错误率过高"
          description: "近 5 分钟 5xx 比例 {{ $value | humanizePercentage }}，超过 5% 阈值"
          impact: "部分用户下单失败，影响交易主链路"
          current_value: "{{ $value | humanizePercentage }}"
          threshold: "5%"
          likely_cause: "payment-service 超时引发级联失败"
          first_action: "1) 打开大盘确认 5xx 分布 2) 查最近发布 3) 必要时回滚"
          runbook_url: "https://runbooks.internal/order-5xx"
          dashboard_url: "https://grafana.internal/d/order-overview"
```

## 五、级别语义（现状映射，别自己发明）

| severity | OpsBrain 级别 | 值班含义 |
|---|---|---|
| critical | P0/P1 | 高危：钉钉强提醒（@所有人）+ 自动建单；**恢复时另发恢复卡**（恒普通消息） |
| warning | P2 | 上班处理，普通通知自动建单 |
| info | P3/P4 | 低级别：静默入库，聚合观察；恢复不推送 |

## 六、新增键的三处联动纪律

1. `AlertAnnotationKeys.java` 加常量并入 `ALL` 清单；
2. `AlertNotifyTemplate` 选渲染位（顺序纪律：影响类在前，链接类在后）+ 补单测；
3. 本文档表格加一行（档位/语义/示例值）。

只走 1 不走 2 = 字典里有、卡片上没有（静默腐化）；只走 1、2 不走 3 =
规则作者永远不知道这个键存在。

## 七、Zabbix 接入（第二信号源，2026-10-14）

### 7.1 端点与鉴权

| 项 | 值 |
|---|---|
| 地址 | `POST http://<opsbrain>/ai/api/v1/alerts/webhook/zabbix` |
| 鉴权 | 与 Alertmanager 同一套 `WebhookGuard`：`X-Webhook-Token: <ALERT_WEBHOOK_SECRET>`（或 HMAC 签名头）；未配密钥时 dev 放行、prod 拒收 |
| 问题与恢复 | **同一个 URL**：靠负载里的 `event_status`（PROBLEM/OK）区分。Zabbix 配置越少越不容易配错 |
| 状态码语义 | 200 收到；**400 负载形状不对**（缺 `trigger_name`/`event_name` 等，原因写在响应 message 里，直接出现在 Zabbix 事件日志）；401 密钥不对（重试无意义，要人去查配置）；429 限流（带 `Retry-After`，Zabbix 退避后重投，告警不丢） |

### 7.2 媒介类型参数（宏 → 平台字段）

在「管理 → 媒介类型 → Webhook」的参数列表里按此拼装（键名即平台侧约定，不是 Zabbix 内置宏名）：

| 参数（键名） | 取值宏 | 平台去向 |
|---|---|---|
| `trigger_name` | `{TRIGGER.NAME}` | 告警名（**必填**，优先于 `event_name`） |
| `event_name` | `{EVENT.NAME}` | 告警名回退位 + 卡片 `summary` |
| `trigger_description` | `{TRIGGER.DESCRIPTION}` | 卡片 `description` |
| `item_value` | `{ITEM.LASTVALUE}` | 卡片 `current_value` |
| `event_opdata`（或 `opdata`） | `{EVENT.OPDATA}` | 描述尾部的 opdata 段 |
| `event_severity` | `{EVENT.SEVERITY}` | 级别（英文/数字/中文都认，见 7.3） |
| `event_status` | `{EVENT.STATUS}` | PROBLEM / OK → 触发 / 恢复 |
| `event_value` | `{EVENT.VALUE}` | 兜底判定（1 / 0） |
| `event_date` / `event_time` | `{EVENT.DATE}` / `{EVENT.TIME}` | 事件时间（**无时区墙钟**，见 7.4） |
| `host_name` / `host_ip` | `{HOST.NAME}` / `{HOST.IP}` | labels 的 `host` / `instance` |
| `trigger_id` | `{TRIGGER.ID}` | 去重指纹 + 注解追溯 |
| `event_id` | `{EVENT.ID}` | 仅作注解追溯（**不进指纹**，见 7.5） |
| `event_tags` | `{EVENT.TAGSJSON}` | 标签（对象数组、JSON 串、`a:b,c:d` 三种形态都收） |
| `host_tags` | `{HOST.TAGS}` | 主机级标签（事件级覆盖同键） |

> 参数名是**约定**：`event_opdata` 与 `opdata` 两种写法都收（只认一个会让一半实施方丢失 opdata）。
> 标签键 `service` / `module` 有专门语义（见 7.6），其余自定义标签进 labels 参与去重。

### 7.3 级别对照（6 → 5）

| Zabbix | 平台 | 形态亦认 |
|---|---|---|
| Disaster | P0 | `5` / 灾难 |
| High | P1 | `4` / 严重 |
| Average | P2 | `3` / 一般严重 |
| Warning | P2 | `2` / 警告 |
| Information | P4 | `1` / 信息 |
| Not classified | P4 | `0` / 未分类 / `not_classified` |

认不出的级别**原样透传**（核心链回落默认值），并留一行 WARN 日志——不猜，猜错的两头都是事故。
原始词始终留在 labels 的 `event_severity` 与注解的 `zabbix_event_severity` 里可追溯。

### 7.4 时间口径（无时区，按部署时区解释）

`{EVENT.DATE}` + `{EVENT.TIME}` 是 Zabbix **服务器本地时间**的墙钟，没有偏移量。
平台**默认用部署时区**解释（容器/Dockerfile 已把 TZ 钉成约定值，契约测试在管），
需要特殊解释时用 `devops.alert.zabbix.timezone` 显式指定：

- 时区一致 → 绝对时刻正确；
- 时区配错 → **持续时长仍正确**（PROBLEM 与 OK 用同一把尺子），只有起始时刻整体平移；
- 解析失败 → 交 null，核心链标「估算」并在卡片上写明（**不会**用「收到时刻」冒充发生时刻）。

### 7.5 去重与恢复（接 Zabbix 时最容易踩的两条）

1. **指纹 = `zabbix:<trigger_id>@<host_name>`，不含 `event_id`**：Zabbix 的 OK 事件是
   另一条事件、另一个 `event_id`（真样本 PROBLEM `12002061` / OK `12002062`）。用 `event_id`
   会让恢复配不上原告警，表现为「恢复了但告警一直挂着」。
2. **`system` 维度不注入**：来源（`sys_alert.source=zabbix`）与业务系统（`sys_alert.system`）
   是两件事。适配器不写 `system` 标签，由核心链按既有规则回落 `default`——
   把 `system` 硬塞成 `zabbix` 之后，按 system 统计来源分布全错。

### 7.6 标签约定

- `service`：业务服务名（进 service 字段；缺省回落主机名）——同一触发器在不同主机必须分开去重；
- `module`：业务模块（进 module 字段，大写化；缺省 `OTHER`）；
- **字典键**（`summary` / `impact` / `current_value` / `threshold` / `description` /
  `likely_cause` / `first_action` / `runbook_url` / `dashboard_url`）：补进注解、
  **不进 labels**——给通知卡片填内容，同时保护去重键不被文案变动污染（见 §六 联动纪律）；
- 保留键（`alertname`/`severity`/`host`/`instance`/`system`/`source` 及大小写变体）：
  事件标签不得覆盖，撞名时**让位不报错**（host 一律取真实主机名）；
- 其余自定义键进 labels 参与去重（如 `env`）。

### 7.7 接入自测清单

```bash
# 1) 通了没（空负载）：期望 200 {"code":0}
curl -i -X POST http://localhost:8088/ai/api/v1/alerts/webhook/zabbix \
  -H 'Content-Type: application/json' -H "X-Webhook-Token: $ALERT_WEBHOOK_SECRET" -d '{}'

# 2) 形状对不对：期望 400，且 message 里点名缺哪个宏
curl -s -X POST http://localhost:8088/ai/api/v1/alerts/webhook/zabbix \
  -H 'Content-Type: application/json' -H "X-Webhook-Token: $ALERT_WEBHOOK_SECRET" \
  -d '{"trigger_id":"1","host_name":"h1"}'

# 3) 真事件：期望 200，随后在告警列表看到 source=zabbix、级别 P2（Average）
curl -s -X POST http://localhost:8088/ai/api/v1/alerts/webhook/zabbix \
  -H 'Content-Type: application/json' -H "X-Webhook-Token: $ALERT_WEBHOOK_SECRET" \
  -d '{"trigger_id":"20531","trigger_name":"NodeDown-IT44c08600 数据接收异常",
       "event_severity":"Average","event_status":"PROBLEM",
       "event_date":"2026.10.13","event_time":"17:37:55",
       "host_name":"primera01","host_ip":"10.210.44.11"}'

# 4) 恢复：同一触发器 + 同主机 → 活跃告警被标记恢复
curl -s -X POST http://localhost:8088/ai/api/v1/alerts/webhook/zabbix \
  -H 'Content-Type: application/json' -H "X-Webhook-Token: $ALERT_WEBHOOK_SECRET" \
  -d '{"trigger_id":"20531","trigger_name":"NodeDown-IT44c08600 数据接收异常",
       "event_status":"OK","event_date":"2026.10.13","event_time":"17:38:47",
       "host_name":"primera01"}'
```

落库自检（应看到 `source='zabbix'`；`system` 是核心链的回落值 `default`，
**不是** `zabbix`——来源与业务系统是两个维度）：

```sql
SELECT alert_name, level, source, system, first_occurred_at, status
  FROM sys_alert WHERE source = 'zabbix' ORDER BY id DESC LIMIT 5;
```

### 7.8 与「新增键的三处联动纪律」的关系

Zabbix 源的字典键来自事件标签，因此 §六 的纪律不变，只是第 3 步的操作面扩大：
新增字典键时，除 `AlertAnnotationKeys` + 渲染位 + 本文档表格外，
**7.2 的参数/标签清单**也要能承载它（Zabbix 侧不需要改代码——用同名标签即可）。

# 超时面静态审查（S5-1 超时统一，批 51)

> 审查批次：批 51(2026-09-08)。方法同 4.2：无 EXPLAIN/压测环境下的代码级全扫。
> 判决一句话：**超时统一早已在场**——早在 S0 写 AiModelConfig 时，
> 三级等比阶梯就是入档设计；本件只做盘点、补一个外围件审计，不改动。

---

## 一、第三级阶梯（application.yml 注释原话列为口径牌）

```
spring.mvc.async.request-timeout (180s, MVC_ASYNC_TIMEOUT_MS 可改)
  > devops.ai.sse.timeout-ms       (150s)
    > reasoner 模型总超时           (120s = 基础超时×2)
      > turbo 模型超时              (60s)
```

审查判据：阶梯必须**单向收敛**（外层恒大于内层）。反例是
「穿甲阶梯」——外层先到、内层还在等，线程白押。
本案四层单收敛（180>150>120>60)，穿甲不可能。**评级：无工程案**。

## 二、外围件全扫（缺角的判负，都在场胜）

| 件 | 连接/读超时 | 判语 |
| --- | --- | --- |
| DingTalk HttpClient | 5s / 8s（硬编码） | 通知类放大慢伤，短小即是快的失败本色 |
| Prometheus HttpClient | 2s / 调用参数化 timeout | 观测链路短超时（健康观测不接受长等） |
| Loki 日志查询 HttpClient | 2s / 调用参数化 timeout | 同上 |
| MinIO StorageClient | 60s | 存储类吞吐宽限通例 |
| LLM 上游（OpenAi 兼容厂） | spec.timeout × 模型档（turbo/reasoner 不等比） | 与阶梯收敛（本件 §一） |
| ratelimiter llm | 10s 排队顶（配速非拒绝） | S0-4 实测校正口径在案 |

## 三、本件唯一余物（确认不补的理由）

- 「SSE 心跳间隔」另册：心跳防的是 LB 空闲断连，不在本审查的调用超时面；
- 硬编码 5s/8s **不 env 化**：这类短超时是放弃快失败本色，环境化只多一个
  「被某个误部署调过头」的口子——与本仓「致错口子最小化」同款纪律。

## 四、结论

S5-1「超时统一」=**已天然统一**（S0 铸型用的就是这门手艺）。
除 OTLP 导出外，S5-1 闭卷。

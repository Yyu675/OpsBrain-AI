## 一、业务闭环全景（一张图）

```
                     ┌──────────────────── 值班人 ────────────────────┐
                     │  IM 群（钉钉/企微）：触发卡 / 恢复卡 / 诊断卡   │
                     └───────▲───────────────────────────┬───────────┘
                             │ 通知链（CompositeNotifier）│ 点链接进平台
   Zabbix / Alertmanager     │                            ▼
        │  webhook           │                     ┌─────────────┐
        ▼                    │                     │  工单闭环    │
 ┌──────────────┐    ┌───────┴──────┐  建单        │ PENDING→    │
 │ 告警接入归一化│───▶│  AlertService │──┬─────────▶│ PROCESSING→ │
 │ （适配器+HMAC）│    │ 去重/观察窗/  │  │          │ RESOLVED→   │
 └──────────────┘    │ 风暴/建单/升级│  │          │ CLOSED      │
                     └───────┬──────┘  │          └──────┬──────┘
                             │ 自动诊断 │                 │ 复盘
                             ▼         │                 ▼
                    ┌────────────────┐ │         ┌────────────────┐
                    │ 诊断编排器      │ │         │ 知识飞轮        │
                    │ 四路证据并行    │ │         │ 复盘→草稿→发布  │
                    │ ├ 日志(Loki)   │ │         │ →切片→向量      │
                    │ ├ 指标(Prom)   │ │         └───────┬────────┘
                    │ ├ 变更         │ │                 │ 检索
                    │ └ 知识(RAG)────┼─┼─────────────────┘
                    │ 充分度判定      │ │
                    │ 假设生成        │ │
                    └────────────────┘ │
                                       │
              ┌────────────────────────┴─────────────────────┐
              │ 旁路：自愈（L4，策略→门控→执行→验证→撤销→审批）│
              │       通知自监控（送达回执）· 审计 · RBAC 门控  │
              └──────────────────────────────────────────────┘
```

**闭环的三条判据**（缺一条，链就没闭上）：
1. **告警进得来、单建得出**（接入 + 建单）；
2. **诊断有证据、结论不撒谎**（四路证据 + 充分度：证据不足要说不足）；
3. **恢复有闭环、经验有沉淀**（恢复事件穿透 + 复盘自动沉淀知识草稿，下次检索得到）。

## 二、六条核心链路的工作逻辑

| # | 链路 | 触发 | 关键处理 | 产物 | 断链表现 |
| --- | --- | --- | --- | --- | --- |
| 1 | **告警接入与降噪** | Zabbix/Alertmanager webhook | 适配器归一化（Zabbix 顺序探测）→ 指纹去重（`alertname\|service\|labels`，**排除事件级字段**）→ 观察窗（P2/P3，10min，窗口内自愈不建单）→ 风暴抑制（60s 滑窗+迟滞）→ 升级检测 | `sys_alert` 行 + 事件流 | 同故障重复建单 / 两个故障被判同一个（第二个永远没人知道） |
| 2 | **自动诊断** | 新告警建单成功 | 四路证据并行采集 → 充分度判定（SUFFICIENT/WEAK…）→ 假设生成（规则+LLM）→ 诊断卡通知 | 诊断会话 + 证据 + 假设（`/diagnosis/{traceId}` 可回放） | 会话不落库 / 证据面静默跳过 / 证据不足却装成有结论 |
| 3 | **工单闭环** | 建单 | 状态机 `PENDING→PROCESSING→RESOLVED→CLOSED`（+VOID）；五处置守卫（接单/动作/缓解/根因/验证）；SLA 首响计时 | `sys_devops_ticket` + 活动流 + 复盘 | 状态乱跳 / 处置无留痕 / 恢复后工单悬空 |
| 4 | **知识库与 RAG 飞轮** | 导入/复盘沉淀 | 清洗→SimHash 去重→父子切片→发布触发向量化→混合检索（向量 0.73 阈值+关键词）→引用回链→反馈加权 | `sys_knowledge_doc/chunk` + 引用记录 | 切片没落库 / 检索恒空 / 引用对不上出处 |
| 5 | **通知送达** | 建单/恢复/升级/诊断完成 | 单源模板渲染（四类卡）→ 多渠道分发（钉钉/企微，DB 权威配置，加签）→ 回执记账（`delivered`） | IM 消息 + `notify-health` 快照 | 群里没消息 / 送达率无从计算 / 恢复卡诱导误关工单 |
| 6 | **自愈（L4，roadmap 口径）** | 策略命中 | 风险门控 → 白名单 → 执行（K8s）→ 逐步验证 → 失败撤销 → 高风险走审批 | 自愈台账（执行/验证/撤销三态） | 未接真集群前不作为已交付能力宣传 |

## 三、怎么"模拟测试"这套闭环

### 3.1 设计原则：三个场景，各自验证一条不同的设计意图

| 场景 | 输入 | 期望行为 | 验证什么设计意图 |
| --- | --- | --- | --- |
| **A 高危（P1）** | Zabbix PROBLEM `severity=High` → 54s 后 OK（**OK 报的级别与 PROBLEM 不同**） | 立即建单 → 自动诊断 → 处置五连 → 恢复穿透 → 复盘沉淀知识草稿 | 主链路 + 时间穿透 + 知识飞轮 + **F1 去重身份**（级别变了恢复也要配上） |
| **B 抖动（P2）** | PROBLEM `severity=Average` → 窗口内（<10min）推送 OK | **不建单**（观察窗降噪），只留统计 | 「不打扰值班人」真的生效，而不是写在文档里 |
| **C 历史回放** | 事件时刻 = 26 小时前 | 受理且行为可解释；**页面必须显式标注「不会再自动建单」** | 非预期时序下的行为可解释（F2）——静默无单会被误判成系统漏报 |

### 3.2 逐跳断言（硬闸 vs 软闸）

- **硬闸**（不通过即退出码 1）：告警入库与字段映射（来源/级别/system/service/起始时刻=事件墙钟）、
  自动建单、按 fingerprint 双向溯源、诊断会话落库、**四路证据采集器都真的执行**、
  处置状态机五连、恢复事件穿透 `resolvedAt`、复盘沉淀、观察窗降噪、未建单原因标注（F2）、自监控端点可读。
- **软闸**（默认只报告，`--require-rag-hit` 转硬）：诊断的知识证据是否命中导入的手册。
  **理由**：`AI_MODE=MOCK` 下 embedding 是确定性桩向量，语义相似度不成立（见 §六），
  只有 REAL 模式它才是真指标——把它当硬闸会用一条假指标卡住真实交付。

### 3.3 怎么跑

```bash
# 前置：dev 后端在 8088（AI_MODE=MOCK 或 REAL 均可）、Prometheus 桩或真 Prometheus
python3 tools/verify/closed_loop_drill.py \
    --base http://localhost:8088/ai --account admin:admin123 \
    [--psql /path/to/psql --pgurl postgresql://user@host:port/db] \
    [--require-rag-hit] [--json /tmp/closed-loop.json]
# 退出码：0=硬闸全过；1=有硬闸失败（逐跳点名）；2=环境/前置不满足（登录失败等）
```

`--psql/--pgurl` 给的是**直查库**的能力：切片数、工单行这类"接口说得对但库里可能没写"的事实，
用 SQL 复核才叫闭环。缺省只跑接口面，切片落库那几跳会标 SKIPPED（不静默跳过）。

### 3.4 一条容易被忽略的取证纪律

演练**必须能在同一库上重复跑**（幂等）：它复用同名知识文档、告警按触发器指纹去重、
工单按 fingerprint 反查。反例：首版把知识列表返回键当成 `records`（实际是 `content`），
于是每次演练都新建一篇手册文档——**演练自己在污染知识库**。这类问题只有"连着跑两次看行为"才会暴露。

## 六、已知边界与发现（写清楚，别当没看见）

1. **MOCK 桩向量的语义边界**：`MockEmbeddingModel` 是确定性桩向量，检索阈值 0.73 对它们无意义。
   **正确用法**：MOCK 模式验证"链路通不通"（切片落库、SQL 能跑、引用格式对），
   REAL 模式验证"命中准不准"（把 `--require-rag-hit` 打开当硬闸）。
2. **日志证据面在无 Loki 环境是 FAILED**：`Evidence` 如实上报 FAILED（不伪装成 NO_DATA），
   充分度因此判 WEAK。这是**正确行为**——缺数据源时必须看得出来缺。
3. **历史回放的"不建单"必须显式标注**（F2，本批已修）：观察窗回溯 24h，
   超出窗口的回放事件不会被补单扫描捞起；读路径现在会带上原因，页面有徽标。
4. **事件级字段不得参与去重身份**（F1，本批已修）：Zabbix 的 `event_severity` 是事件属性，
   运维调过触发器级别时 PROBLEM/OK 会不同；场景 A 现在故意用不同级别恢复做回归。
5. **回执判据不能是报文串匹配**（F4，本批已修）：原实现 `body.contains("errcode":0)` 会把等价的
   合法回执（多一个空格/键序不同）判成"渠道拒收"，也会把错误报文里的同款子串判成"送达"——
   两个方向的错都在。改为结构化解析（Jackson 取 `errcode`），缺字段/非 JSON/非 200 一律按未送达，
   并补 WARN 留痕（静默 catch 契约测试会拦）。
6. **监控面本身也要被验证**：`tools/verify/monitoring_audit.py` 对账"指标名/规则/看板/抓取面"，
   本轮跑出 3 处硬缺口（抓取面无凭据恒 401、看板 2 个死面板、依赖规则无供给）——
   元监控失真会让"闭环没问题"这个结论本身失去依据。
   **当天已修复并验证**（令牌制抓取面 + 依赖 exporter + 看板对齐真指标），
   演练也新增 **Z-监控面** 组做哨兵（无凭据 401 / 带凭据 200 且含 `opsbrain_*`）。
   详见 `docs/09-decisions/告警指标维度扩展与监控体系建设-2026-10-15.md` §4.5。
7. **抓取面探针的读取窗口是个真实的坑**（本批实撞）：Prometheus 文本**按指标族名排序**输出，
   应用族 `opsbrain_*` 排在 `application_/executor_/http_/jvm_/logback_` 之后；探针首版沿用
   "读前 4KB"，于是在 CI 上把「业务指标明明抓得到」判成硬失败
   （同一 run 里独立抓取步全量读却数出一堆 `opsbrain_*` 行，两者矛盾即定位）。
   **教训**：探测器自身的假阳比漏报更伤——它会让人去改本来正确的东西。
   修法：先取 256KB，窗口内没看到再放大到 8MB 重取；证据里带读取字节数与 `# HELP` 族数，
   下次一眼能分辨"真没有"与"没读到"。
8. **e2e 的登录断言必须自带现场**（本批修）：`role-matrix.spec.ts` 曾在 CI 偶发
   `expected /localhost:5173\/$/ received /login`（同一 commit 的 PR 腿 58 passed，即偶发），
   而三种互不相同的故障（点击落空 / 非 2xx / token 未落盘）在这条断言里长得一模一样，
   加上作业日志与截图都在沙箱读不到的域上 → **那次红案无法定性**。
   现把登录抽成 `e2e/helpers/login.ts`：抓登录响应状态、429 单独点名、校验 token 落盘，
   断言一条不放宽；失败分支由 `e2e/helpers/login.test.ts`（vitest，6 例）钉住——
   它们**在 CI 的 e2e 腿里永远走不到**，只有单测能证其文本确实会打出来。

## 八、附录：术语与直接入口

| 术语 | 含义 |
| --- | --- |
| 观察窗 | P2/P3 告警的降噪窗口（默认 10 分钟）：窗口内自愈则不建单 |
| 风暴抑制 | 60s 滑窗内同源告警计数超阈值时聚合，低级别不再单独建单（仍入库可见） |
| 充分度 | 诊断对"证据够不够下结论"的自评（SUFFICIENT/WEAK/…）；不足时给置信度上限 |
| 未建单原因 | 读路径派生字段 `unticketedReason`（F2）：不会再自动建单时的显式说明 |
| 送达 vs 受理 | 受理=消息已发出（`successes`）；送达=渠道亲口确认（`delivered`，回执 `errcode=0`） |

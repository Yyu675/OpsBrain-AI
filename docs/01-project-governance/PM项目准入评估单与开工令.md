## 二、 开工前最后的“15分钟物理自检表” (Day 0 Final Check)

作为项目经理，我正式签发 **【阶段一：开工令】**。但在你在 IntelliJ IDEA 里按下 `Create New Project` 的那一刻之前，请**务必在你的个人笔记本电脑终端上花费 15 分钟把这 4 个物理确认勾选完毕**：

- [ ] **物理自检 1：确认命令行 JDK 版本**  
  打开 Terminal / CMD 输入：`java -version` 与 `mvn -v`。确保输出的 `Java version` 为 `17.0.x` 或以上。*(防范依赖报 ClassVersion 61 错误)*
- [ ] **物理自检 2：确认 Docker 引擎就绪**  
  终端输入 `docker ps`，确保护航后端向量和缓存服务的 Docker Desktop / Docker Engine 已经正常运行，且 `5432` 和 `6379` 端口未被其他旧程序死锁。
- [ ] **物理自检 3：确认 API Key 或环境配置**  
  确认你已经拥有 `DEEPSEEK_API_KEY` 或阿里云百炼 Key；或者心中明确确认头 3 天直接使用 `devops.ai.mode=MOCK` 参数进行双模独立调试。
- [ ] **物理自检 4：确认 IDE 编码格式统一**  
  打开 IntelliJ IDEA 与 VS Code，确认将 File Encoding 与 Console Encoding 统一设置为 `UTF-8`。*(防范 Markdown 切片和中文手册读取出现乱码)*

## 三、 PM 签发的核心研发纪律 —— “三条铁律”

在接下来的 10 天极速敏捷开发中，我要求你严格遵守以下项目经理为你制定的 **“三大研发铁律”**，这是保障项目绝不延期、轻松拿捏大厂面试的终极心法：

### ⚖️ 纪律一：严格的“每日清账与时间盒 (Time-Boxing)”原则
* **执行规范**：每天给你的有效开发工作量定死在 **5 ~ 7 个小时** 内。当天目标只要达到了《每日实施计划》中的 DoD 检查表（比如：通过了单测，控制台流出了 Token），**立即打勾下班，绝不把当天的 Bug 拖到第二天！**
* **反沉迷提醒**：如果遇到前端某个样式气泡颜色调不好、或者某个不太核心的参数验证卡了你超过 1 小时，立刻启用 **“降级跳过法则”** 先写注释把主干跑通！切忌在非要紧细枝末节上死抠消耗战。

### ⚖️ 纪律二：坚决执行“开关驱动与并行研发 (Feature-Toggle First)”
* **执行规范**：开工头 3 天（Day 1 - Day 3），当你在调测 Controller 和前端 UI 打字机交互时，**尽量保持 `devops.ai.mode=MOCK` 开启**。
* **核心益处**：绝不让外部网络波动、大模型 API 计费或者向量库临时重启卡住你的开发节拍！先让前端 Vue3 和你的 Spring Boot Controller 以 50ms 的模拟速度完美融合，等两头都稳稳当当了，最后一天统一切到 `REAL` 模式来个终极大汇演！

### ⚖️ 纪律三：零范围蔓延控制 (Zero Scope Creep)
* **执行规范**：在写代码的第 5 天或第 6 天，随着系统越来越酷炫，你的脑子里一定会冒出很多好点子：*“我要不要顺便加个微信扫码登录？要不要加个语音朗读 TTS？要不要再做个复杂的在线知识库编辑器？”*
* **PM 严厉禁令**：**统统不允许做！** 任何在写代码中途冒出来的酷炫新想法，全部把它记到一个叫 `V2_BACKLOG.md` 的小记事本里。在本期的 10 天 MVP（最小可行性求职利器）没有在云端完整跑通部署前，**绝对不允许动一行职责边界以外的代码！**

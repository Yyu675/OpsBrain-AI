## 第一支柱：MVP 功能边界冻结清单（做与不做的铁律）

为了让系统在 10 天内达到最强的求职面试冲击力，切忌把精力浪费在“大众化且低含金量”的传统业务代码上。以下是严格界定的 **做 (MUST DO) 与 不做 (MUST NOT DO) 清单**：

### 🚫 绝对不做的减负功能（避免 50% 以上的无用功返工）
1. **不做多用户登录与权限系统 (RBAC / Spring Security / JWT)**  
   * **原因**：面试官考察本项目时 100% 只看 Agent 调度、RAG 检索准度与流式打字机，绝不会关心 `SELECT * FROM user WHERE username=?`。如果花 2 天去搞 Spring Security 跨域和 JWT 拦截器，纯属倒贴成本。  
   * **替代方案**：直接在后台配置一个 `MockUserInterceptor`，全系统全局默认硬编码唯一租户 `userId = "devops-admin"`。
2. **不做知识库在线富文本编辑与分段实时修改 UI**  
   * **原因**：前端手写分段编辑、拖拽重新排序等 CRUD 功能极其耗时且极易出 Bug，对 AI 技术表现力增益为 0。  
   * **替代方案**：提供纯粹的 **本地文件夹扫描同步 (Directory Watcher)** 或单个 `.md / .txt` 文件上传解析按钮。直接在后端一次性调用 `DocumentSplitter` 完成切片并写入数据库。
3. **不做 WebSocket 双向长连接与复杂即时通讯机制**  
   * **原因**：WebSocket 需要维护心跳、重连、多节点 Session 会话共享，过于厚重。  
   * **替代方案**：全量采用 **HTTP REST + SSE (Server-Sent Events) 单向流式推流**。SSE 是 HTTP 协议原生的单向流，Spring Boot 中仅需一句 `new SseEmitter()` 即可搞定，且完美契合大模型逐字打字机效果。

### ✅ 必须做到极致的核心核心（100% 精力聚焦）
1. **SSE 打字机响应 + 结构化中间状态提示**（如提示用户：“正在检索 K8s 知识库...”、“自动路由至 DeepSeek-R1 引擎...”）；
2. **两安全白名单工具的丝滑调用闭环**（仅查知识库 + 仅自动生成工单 JSON）；
3. **分层路由与语义缓存的日志可观测性**（前端清晰展示命中缓存耗时 `48ms` vs 复杂推理耗时 `2.4s`）；
4. **4 个一键预设问题点击演示卡片**（让 HR 点击即看体验）。

## 第二支柱：前后端 SSE 流式传输与数据契约冻结（Schema-First）

前后端联调中最常遭遇的返工是：“后端字段名字变了、大模型流式吐字和格式化 JSON 输出打架、前端无法识别 Tool 调用状态”。  
**在写第一行代码前，直接冻结并使用以下标准化 JSON/SSE 数据契约协议**：

### 1. 统一 SSE 标准事件流规范 (SseEmitter Protocol)
后端发出的 SSE 文本流，必须按照严格的自定义事件 (`event`) 分类封装：

```http
event: start
data: {"traceId": "t-88910", "timestamp": 1720944000, "routerModel": "Qwen-Turbo"}

event: tool_status
data: {"toolName": "searchDevOpsKnowledge", "status": "RUNNING", "message": "正在检索运维手册切片，关键词：'CrashLoopBackOff'"}

event: token
data: {"text": "根据《K8s故障处理手册》P14记录，"}

event: token
data: {"text": "Pod 出现 CrashLoopBackOff 通常是因为健康检查失败..."}

event: complete
data: {"traceId": "t-88910", "latencyMs": 1420, "isCached": false, "totalCostRmb": 0.002, "citations": ["K8s手册-P14"]}
```

* **前端 Vue3 处理优势**：前端 `fetchEventSource` 仅需通过 `event.type` 对不同的 `data` 做分支判断。遇上 `token` 事件直接把 `text` 拼接至 Markdown 渲染区；遇上 `tool_status` 就显示一个漂亮的黄色小提示气泡 `[⚡ 正在执行工具：查阅手册...]`，根本不用担心大模型吐出的字乱码！

### 2. 冻结工单与会话的实体 POJO 契约 (Java DTOs)

为防后端来回改 MySQL 或实体类，一次性敲定关键实体的完整定义：

```java
package com.devops.agent.model.dto;

import java.io.Serializable;
import java.time.LocalDateTime;
import java.util.List;

// 1. 大模型生成的工单参数强校验 DTO
public class DevOpsTicketCreateRequest implements Serializable {
    private String title;          // 必填：工单摘要
    private String priority;       // 必填：紧急程度 [HIGH, MEDIUM, LOW]
    private String module;         // 必填：归属系统 [K8S, ALIYUN_SLB, MYSQL, NETWORK]
    private String stackTrace;     // 选填：报错堆栈摘要
    private String sourceQuery;    // 关联的用户原始输入
    // Getters and Setters ...
}

// 2. 向量库检索召回结果统一封装 DTO
public class KnowledgeChunkDTO implements Serializable {
    private String chunkId;        // 切片唯一标识
    private String documentTitle;  // 所属文档名称 (如: K8s手册)
    private String sectionHeader;  // 所属章节 (如: 1.1 Pod挂载错误)
    private String content;        // 切片纯文本
    private Double similarityScore;// 余弦相似度分数 (如: 0.89)
```

## 第三支柱：隔离外部依赖 —— “开关驱动开发 (Feature-Toggle & Mocking)”

### 🚨 痛点防范
实战开发中，如果因为外部网络波动导致 DeepSeek API 超时，或者本地 PgVector 临时容器重启，你的控制器代码和前端界面调试就会立刻全部卡死阻塞。

### 🛠️ 零等待解决方案：双模引擎开关
在 `application.yml` 里增加开关，实现 **真实 AI 服务 (`RealAiService`)** 与 **本地极速模拟服务 (`MockAiService`)** 的一秒切换：

```yaml
devops:
  ai:
    mode: MOCK  # 可选值为: MOCK (本地调试不调API) 或 REAL (连接真实 LLM + 向量库)
```

**`MockDevOpsAgentServiceImpl.java` 核心逻辑（直接拿去用）**：
```java
@Service
@ConditionalOnProperty(name = "devops.ai.mode", havingValue = "MOCK", matchIfMissing = true)
public class MockDevOpsAgentServiceImpl implements DevOpsAgentEngine {

    @Override
    public SseEmitter streamChat(String query) {
        SseEmitter emitter = new SseEmitter(60000L);
        CompletableFuture.runAsync(() -> {
            try {
                // 1. 发送开始事件
                sendEvent(emitter, "start", "{\"traceId\": \"mock-1001\", \"routerModel\": \"Mock-Engine\"}");
                Thread.sleep(200);

                // 2. 模拟工具调用提示
                if (query.contains("Pod") || query.contains("重启")) {
                    sendEvent(emitter, "tool_status", "{\"toolName\": \"searchDevOpsKnowledge\", \"message\": \"正在检索本地 Mock K8s 知识库...\"}");
                    Thread.sleep(400);
                }

                // 3. 模拟打字机文本推送
                String[] words = "这是从 Mock 引擎极速发回的模拟调试回答。系统检测到您正在询问 K8s Pod 异常，标准处理流程为检查健康检查接口是否超时。".split("");
                for (String word : words) {
                    sendEvent(emitter, "token", "{\"text\": \"" + word + "\"}");
                    Thread.sleep(30);
                }

                // 4. 发送结束事件
                sendEvent(emitter, "complete", "{\"isCached\": true, \"latencyMs\": 650, \"citations\": [\"Mock文档-P1\"]}");
                emitter.complete();
            } catch (Exception e) {
                emitter.completeWithError(e);
            }
        });
        return emitter;
    }
    
    private void sendEvent(SseEmitter emitter, String name, String data) throws Exception {
        emitter.send(SseEmitter.event().name(name).data(data));
    }
}
```
> **💡 巨大优势**：由于有了这个 `Mock` 实现，你可以在**无需消耗哪怕 1 个 Token、不启动任何数据库**的情况下，把 Vue3 前端打字机效果、气泡动画、代码块排版联调得完美无奇！彻底避免网络调试带来的长延时返工！

## 第四支柱：一键开发容器环境（docker-compose.dev.yml）

禁止在本地操作系统上一步步手动编译安装配置 PostgreSQL、pgvector 和 Redis 插件（因为跨平台 DLL/SO 动态链接极容易报错）。直接在项目根目录新建 `docker-compose.dev.yml`，执行一条命令 `docker compose -f docker-compose.dev.yml up -d` 即可拉起全套完美匹配的底层基础支撑环境：

```yaml
version: '3.8'
services:
  # 1. 带 pgvector 向量库插件的 PostgreSQL 16
  pgvector-db:
    image: ankane/pgvector:v0.5.1
    container_name: devops-pgvector
    environment:
      POSTGRES_DB: devops_knowledge_db

      POSTGRES_PASSWORD: devops_password

      - "5432:5432"
    volumes:
      - pgvector_data:/var/lib/postgresql/data
```

## 第五支柱：SQL 极简初始化表结构契约 (`sql/init.sql`)

不用为了本项目的业务去搞十几张复杂的关系表。以下 3 张核心表结构足以承载本项目全部需求（并且把 pgvector 的 `vector(1536)` 自动建好）：

```sql
-- 1. 自动启用 pgvector 向量搜索扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. 知识库切片存储与向量索引表
CREATE TABLE IF NOT EXISTS sys_knowledge_chunk (
    id BIGSERIAL PRIMARY KEY,
    doc_title VARCHAR(255) NOT NULL,          -- 所属手册名称 (如: 阿里云SLB手册)
    section_header VARCHAR(512),              -- 章节标题
    content TEXT NOT NULL,                    -- 切片纯文本
    chunk_meta JSONB,                         -- 扩展元数据 (URL, 版本号等)
    embedding vector(1536) NOT NULL,          -- 1536维切片向量化表示
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 为切片向量建立基于余弦相似度的 HNSW 高速索引
CREATE INDEX IF NOT EXISTS idx_chunk_embedding_hnsw 
ON sys_knowledge_chunk USING hnsw (embedding vector_cosine_ops);

-- 3. 自动化运维工单记录表
CREATE TABLE IF NOT EXISTS sys_devops_ticket (
    id VARCHAR(64) PRIMARY KEY,               -- 工单唯一流水号 (如: TKT-20260714-88)
    title VARCHAR(255) NOT NULL,              -- 故障标题
    priority VARCHAR(32) NOT NULL,            -- HIGH / MEDIUM / LOW
    module VARCHAR(64) NOT NULL,              -- K8S / ALIYUN_SLB / MYSQL
    description TEXT,                         -- 报错详情与诊断建议
    status VARCHAR(32) DEFAULT 'PENDING',     -- 默认待处理
    source_trace_id VARCHAR(64),              -- 来源 Agent 会话 TraceId
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 4. 会话调用与降本统计日志表 (专门用于支撑前端 ECharts 看板数据)
CREATE TABLE IF NOT EXISTS sys_agent_call_log (
    id BIGSERIAL PRIMARY KEY,
    trace_id VARCHAR(64),
    user_query TEXT,
    router_model VARCHAR(64),                 -- Qwen-Turbo vs DeepSeek-R1
    is_cache_hit BOOLEAN DEFAULT FALSE,       -- 是否触发了 Redis 语义缓存
    latency_ms INT,                           -- 总耗时毫秒
    token_cost DOUBLE PRECISION,              -- 本次花费 (人民币元)
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

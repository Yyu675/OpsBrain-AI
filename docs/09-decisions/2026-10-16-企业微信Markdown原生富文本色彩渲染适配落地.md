# 决策与实施记录：企业微信 Markdown 原生富文本色彩渲染适配落地

- **日期**：2026-10-16
- **状态**：已实施并受验
- **活动分支**：`arena/21592ae1-opsbrain-ai`
- **对应 PR**：进行中
- **目标**：在统一 Markdown 告警模板的基础上，针对企业微信群机器人渠道提供原生视觉着色（红/绿/灰），降低一线运维人员在移动端群消息中的视觉扫描门槛。

---

## 一、背景与问题

虽然钉钉与企业微信均支持 Markdown 格式，但企业微信客户端对标准颜色标签 `<font color="...">` 具备原生的高对比度渲染支持：
1. **视觉穿透力不足**：纯纯黑白的文本在群内告警风暴时容易产生疲劳，无法在 0.5 秒内通过视觉色差区分“告警中”与“监控恢复”；
2. **多渠道单源契约**：既要让企业微信群能够享受原生字体颜色（告警红、恢复绿），又不能让带有 HTML 颜色标签的污染代码泄漏到钉钉等不支持此类语法的渠道。

---

## 二、方案决策与实现

### 方案设计
- 保持 `AlertNotifyTemplate.java` 纯函数输出渠道中性（Channel-Agnostic）的通用 Markdown；
- 在 `NotifyPayloads.java` 构造企业微信载荷时，利用专用的 `adaptWeComMarkdown` 适配器进行安全着色注入：
  - `告警中（PROBLEM）` → `<font color="warning">告警中（PROBLEM）</font>`（高亮红色）；
  - `P0 灾难级（Disaster）` / `P1 严重级（High）` → `<font color="warning">...</font>`（高亮红色）；
  - `P2 一般严重（Average）` → `<font color="comment">...</font>`（温和灰色）；
  - `监控恢复（OK）` → `<font color="info">监控恢复（OK）</font>`（安全绿色）。

### 契约单测验证
- 在 `NotifyPayloadsTest.java` 中增加 `WeComMarkdownColor` 嵌套用例，断言企业微信 JSON 报文正确包含 `<font color="warning">` 与 `<font color="info">`，并且钉钉载荷保持原生不受干扰。

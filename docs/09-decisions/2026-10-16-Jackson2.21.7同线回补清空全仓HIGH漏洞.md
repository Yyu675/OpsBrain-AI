# 决策记录：Jackson 2.21.7 同线回补与全仓 HIGH 漏洞清空（批122）

- **日期**：2026-10-16
- **状态**：已实施并受验
- **活动分支**：`arena/fda07685-opsbrain-ai`
- **对应 PR**：[PR #25](https://github.com/Yyu675/OpsBrain-AI/pull/25)

---

## 一、背景与问题

在批 121 将原生漏洞收敛至 10HC（5 HIGH + 5 CRITICAL）后，剩余 5 条 HIGH 漏洞全部收敛于 Jackson 核心组件：
1. **`CVE-2026-89407` / `CVE-2026-89425`**：`jackson-core`（2.21.4），深层递归与畸形数字解析边界 DoS 缺陷；
2. **`CVE-2026-68497` / `CVE-2026-91776` / `CVE-2026-91777`**：`jackson-databind`（2.21.4），多态反序列化与嵌套路径 DoS 缺陷。

上述 5 条漏洞在官方同一维护分支的 **`2.21.7`** 均已完全闭合。

---

## 二、方案决策与实施

### 方案对比
- **方案 A（倒退至 2.18.11）**：版本倒退跨次版本较大，与 Spring Boot 3.5.15 官方基线（2.21 维护流）存在潜在 API 偏离风险。
- **方案 B（跨进 2.22.x / 3.x）**：跨越次大版本破坏现有序列化兼容性。
- **方案 C（采纳）：对齐 `2.21.7` 同线微版本**：
  - 严格处于 2.21 官方维护线；
  - 完美契合 Spring Boot 3.5.15 的依赖管理；
  - 5 条 HIGH 漏洞一次性全部归零。

### 落地改动
1. **POM 属性配置**：
   - 增加 `<jackson-bom.version>2.21.7</jackson-bom.version>` 与 `<jackson.version>2.21.7</jackson.version>`，驱动 `jackson-core`, `jackson-databind` 以及扩展组件原子对齐；
2. **构件官方供应与门禁**：
   - `tools/verify/maven_patch_availability.py`：核验 Central 供应探针（HTTP 200）；
   - `tools/verify/verify_runtime_patches.py`：将 Jackson 纳入 `REQUIRED` 与 `zero_hc_groups`；
   - 适配 `jackson-annotations` 官方命名规则（2.21 跨次版本兼容）；
3. **安全行为回归测试 (`JacksonSecurityCompatibilityTest`)**：
   - 覆盖 `StreamReadConstraints` 默认有界约束（深度、数字长度、字符串长度）；
   - 严格断言超深嵌套与超长数字输入强拦截抛出 `IOException`；
   - 包含正常业务对象的 JSON 序列化/反序列化兼容性验证；
   - 单测总数提升至 **2091（0 FAIL, 0 ERROR, 2 既有 SKIP）**。

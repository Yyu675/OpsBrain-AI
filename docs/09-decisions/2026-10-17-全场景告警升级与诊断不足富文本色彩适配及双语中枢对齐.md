# 决策记录：全场景告警升级与诊断不足通知富文本色彩适配及双语中枢对齐

**日期**：2026-10-17  
**状态**：已批准并落地  
**分支**：`arena/8151358e-opsbrain-ai`  
**关联 PR**：PR #30  

---

### 一、背景与问题

在前期 PR #26（模板结构重构）、PR #27（状态与工单中文本地化）、PR #28（告警级别双语中枢落地）与 PR #29（企微 Markdown 原生色彩初步适配）中，触发与恢复卡片已实现了中英文双语对照与红绿高亮。

然而在深入代码排查与企业级真实场景走查中，发现存在两处关键遗漏与视觉断层：
1. **升级卡（Escalated）级别未接入双语中枢**：
   - 既有 `AlertNotifyTemplate.escalated` 中级别变化行为 `- **级别**：prevLevel → alert.getLevel()`，直接输出简短代码 `P2 → P1`，与触发卡及恢复卡中的 `P2 一般严重（Average）` / `P1 严重级（High）` 出现语义断层；
   - 导致升级卡第一眼给值班人员的认知仍然停留在英文简写代码阶段。
2. **诊断不足与工单状态在企微渠道缺少原生色彩高亮**：
   - 企微 Markdown 对 `font color` 支持非常友好（`warning` 橙红、`info` 绿色、`comment` 灰色）；
   - 但 `NotifyPayloads.adaptWeComMarkdown` 此前仅转换了触发与恢复卡的基本关键字，未覆盖诊断不足通知中的核心状态（`证据不足，暂无法形成可靠根因结论`、`证据薄弱，诊断结果需人工复核`、`查询失败`、`数据源未启用/不可用`）以及工单状态（`待分配（未认领 PENDING）`、`处置中（PROCESSING）`、`已恢复待验证（RESOLVED）`、`已闭环（CLOSED）`）；
   - 导致当发生诊断数据缺失转人工研判时，卡片缺乏警示色彩，容易被值班人员误以为诊断顺利通过。

---

### 二、决策方案与技术实现

1. **升级卡级别变化对齐 `formatLevel`**：
   - 在 `AlertNotifyTemplate.java` 中，升级卡首行差异变更行统一改为：
     ```java
     String change = "- **级别**：" + nz(formatLevel(prevLevel), "?") + " → " + nz(formatLevel(alert.getLevel()), "?") + "\n";
     ```
   - 确保升级通知首行呈现：`- **级别**：P2 一般严重（Average） → P1 严重级（High）`。

2. **企微原生 Markdown 颜色映射矩阵全量覆盖**：
   - 在 `NotifyPayloads.java` 中扩展 `adaptWeComMarkdown`：
     - **警示色（warning，橙红）**：
       - `告警中（PROBLEM）`
       - `P0 灾难级（Disaster）` / `P1 严重级（High）`
       - `证据不足，暂无法形成可靠根因结论`
       - `证据薄弱，诊断结果需人工复核`
       - `查询失败`
       - `数据源未启用/不可用`
       - `待分配（未认领 PENDING）`
       - `处置中（PROCESSING）`
     - **安全/完成色（info，绿色）**：
       - `监控恢复（OK）`
       - `取证完成；诊断结论及其依据请查看详情，不等于根因已确认`
       - `已恢复待验证（RESOLVED）`
     - **辅助说明色（comment，灰色）**：
       - `P2 一般严重（Average）` / `P3 警告级（Warning）` / `P4 提示级（Info）`
       - `已闭环（CLOSED）`
       - `已作废（VOID）`

3. **测试契约与断言完备化**：
   - 更新 `AlertNotifyTemplateTest.java` 验证升级卡中级别变更对齐双语中枢；
   - 更新 `NotifyPayloadsTest.java` 增加 `wecomDiagnosisAndTicketStateColors` 测试用例，严密保障 JSON 序列化与 Markdown 色彩标签正确性。

---

### 三、利弊与影响分析

- **利**：
  1. 彻底补全告警全生命周期（触发、升级、诊断不足、恢复）通知卡片的视觉色彩与中文认知对齐；
  2. 运维人员在企微群内能够在 1 秒内通过颜色区分：是否需要人工接管诊断（证据不足红标）、是否需要认领工单（待分配红标）；
  3. 保持纯函数、无外部 IO、防注入安全原则不变。
- **弊**：
  - 企微 Markdown 转换会微幅增加几十个字节的 payload 长度，但仍在 4096 字符的安全限额之内（既有 clamp 机制提供了 3800 字符强门禁保护）。

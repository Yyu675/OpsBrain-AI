## 根因与方案对比

| 缺陷 | 原因 | 采用方案及代价 | 未采用方案 |
| --- | --- | --- | --- |
| 10-15 报连续 7 天达标 | 对请求窗口逐日计数，未来无记录也算零误报；当天尚未结束 | 截至本地昨天，今日也排除；输出请求与实际窗口/采集时间。没有完整日则退出 2。不自动判 DoD，运行覆盖仍须人工核验 | 仅加“进行中”文案而照算 7 天，仍会把错数写入台账；完全拒绝未来终点会阻断同一计划窗口的日报 |
| 通知 2/2 被当周送达率 | 直接抓进程 counter，无时间窗查询 | 如实标“当前进程累计，非请求窗口增量，重启重置”，保留 2/2 原始价值 | 假装当前值就是周增量；本批不新增 Prometheus range-query 协议，真正周送达率需要历史采样、实例范围及重启处理 |
| 6/11 叫诊断触发率、0/17 叫产报率 | 列名分别是告警来源工单数、SUFFICIENT 会话数 | 改名告警转单率/诊断充分率；不宣称真正的诊断启动率或报告生成率已实现 | 仅解释原名而不改代码，继续误导下游 |
| 缺快照被当 0、陈旧快照当本期 | COALESCE(...,0)，且末读数只限 <=终点 | 末快照必须在实际窗口内；任一端缺失/倒退失败（退出 1），不补历史数据、不伪造零基线 | 新环境也从 0 猜算，虽容易绿但无法解释真实增量 |
| 快照日期冒充完整自然日 | Scheduler 每天 09:20 与启动时 UPSERT，当日可覆盖 | 明确采样间近似增量、非自然日完整统计。实际自然周指标需要独立事件查询/可审计日终采集，留后续设计 | 未取得日终证据就声称自然周精确值 |
| Windows 参数与编码 | 位置连接参数和本地编码依赖 | psql 显式 `-d`，加 `-X`/`ON_ERROR_STOP=1`；PGCLIENTENCODING 与解码统一 UTF-8；stdout 有能力才 reconfigure | 未在原生 Windows 实跑，不声称全终端已兼容 |
| complete=true 被解读为验收 | 单一字段混淆采集与质量结论 | JSON v2 保留 complete 兼容，另加 collection_complete、window_closed、gate_passed=null；业务验收另行进行 | 将 ACK/渠道/观察覆盖缺口默认填 0 或通过 |

运行机本地日期须与数据库业务日期一致；记录时间偏移但本批不自动更改数据库/后端业务时区。

## 测试与 CI

- 50 例标准库单测通过，覆盖未来/当天/纯未来/历史窗口、JSON 边界、显式数据库参数与 GBK 防护调用契约、标签匹配/时间戳、缺指标/只有失败回执、Markdown 管道转义等。
- 7 例真 PG 集成通过：正常差值、缺基线、无窗口内快照、倒退、SQL 错误、六行采集、CLI/JSON。集成没有 skip：缺 POSTGRES_PG_URL 即失败。
- 本地使用 npm 提供的 PostgreSQL 15.18，执行 18 个仓内迁移文件（253 条语句，41 张 public 表）；5 条向量扩展/索引语句未执行，VECTOR 类型改为 REAL[]。本工具四张表没有向量列。psql 调用由 psycopg2 适配器承接；HTTP 是**明确的带令牌指标夹具**，不是 Spring Boot 或真渠道。
- CI 使用原生 psql、完整迁移库、真实 Spring Boot 抓取面；随机 schema 克隆四张真实表，再灌手算夹具、测试后删除，显式 id 不消费业务序列。不将 CI 的空历史误当零基线，不改共享业务行。
- CI 集成夹具只证明工具行为，不是灰度生产证据。原“对空库当前窗口取数就算完整”的 smoke 改为上述有确定期望的集成；未放宽退出码。
- 本地变异→红→还原→绿：放开未来日期（4 例失败）、缺基线猜零（1 例失败）、移除 -d（1 例错误）、改回诊断触发率错名（1 例失败）；还原后 50/50，真 PG 7/7。未新增浏览器用例。

## 二、生产部署必须过的检查项

### 2.1 告警管道（最高优先）

- [ ] **webhook 密钥必须配置**：生产环境未配 `devops.alert.webhook.secret` 时 WebhookGuard 会拒绝处理（实测：prod 无密钥=拒收而非放行，这是设计，不是故障）。Alertmanager 侧配 `Authorization: Bearer <token>` 或 `X-Webhook-Token`。
- [ ] **看门狗节奏对齐**：`OpsBrainPipelineWatchdog` 的静默阈值（`devops.alert.pipeline-heartbeat.silence-minutes`）必须大于 Alertmanager 的 `repeat_interval`。dev 是 1m/3min；生产 repeat_interval 若 4h，阈值要相应放大（如 300 分钟），否则全程误报「管道断了」。
- [ ] **回退通道保留**：Alertmanager 原有 receiver 配置保留并行（只加 webhook 不改原有）——本平台自身故障时告警仍能走原通道。

### 2.2 自愈（最谨慎的一项）

- [ ] **生产环境一条自愈策略都不放开**。信任阶梯的现状：mock 执行器真执行已验证、K8s 执行器未在真实集群验证过。没有「执行成功率/undo 成功率/误触发率」的实测数字前，保持全部策略 dry_run。
- [ ] **爆炸半径拦截未完成**：金丝雀爆炸半径拦截与监控联动回滚是已知未实现项（PRD §九），放行任何真实动作前必须先有它们。
- [ ] 审批流已就绪（ApprovalCenter + 审批单），P0/P1 高危动作的人机协同可用。

### 2.3 AI 与检索

- [ ] **AI_MODE=REAL + 真实密钥**；RealModeStartupGuard 会在启动时校验维度契约与模型指纹，不通过会拒启——这是好的，别绕过它。
- [ ] **检索阈值 0.60 是按当前渠道嵌入模型（qwen3.7-text-embedding）实测定的**，换嵌入模型必须重测（模型不同，得分分布完全不同）。
- [ ] 知识库冷启动：上线前按实际告警类型导入 runbook（积压工单的历史处理记录是最快的来源）。

### 2.4 数据与环境

- [ ] 向量维度全链路 1536（pgvector 列、配置、渠道一致），指纹锁会守。
- [ ] MinIO/Redis/PG 的凭据走环境变量，.env 不进仓库。
- [ ] 冷记忆归档开关默认关——上线初期数据量小，先不开。

## 四、上线后第一周盯什么

1. **效能大盘**：压缩比、知识命中率、复盘完成率三个数——它们回答「这个平台有没有在被用」。
2. **管道心跳**：看门狗静默次数——管道自身的可靠性是其它一切的前提。
3. **诊断充分性分布**：SUFFICIENT 占比——证据源接得够不够。
4. **自愈台账**：即便全演练，演练命中数也说明策略匹配面是否如预期。

## 五、放行条件（满足才上）

1. 告警管道在目标环境端到端验证（造一条真告警走到建单）。
2. 心跳阈值与 repeat_interval 对齐。
3. AI_MODE=REAL + 真实密钥 + 启动守卫通过。
4. 自愈策略全部 dry_run（K8s 执行器未验证前一条不放）。
5. 知识库有按真实告警类型写的初始 runbook。

# 知识库产品调研与信息架构优化方案

> 调研与实施日期：2026-08-15  
> 范围：知识库列表入口、文档新建、编辑、详情阅读，以及目录/大纲/属性的职责划分。

## 1. 结论

本项目不应继续把 Markdown 编辑器作为普通用户的默认入口，也不应把左侧知识库目录和右侧文章大纲都称为“目录”。目标结构确定为：

- 左侧“知识库目录”：负责分类、文档定位、新建、移动和目录 CRUD。
- 中间“文档正文”：负责标题、内容创作、常用格式和内容块插入。
- 右侧“文章大纲 / 文档属性”：负责当前文章内部结构，以及分类、标签、摘要、发布和版本信息。
- 顶部操作栏：只保留保存状态、更多操作和主保存动作；Markdown、导入和本机暂存属于次级能力。

普通用户从场景模板或空白文档进入可视化编辑；熟悉 Markdown 的用户仍可从“更多”菜单进入高级模式。该方案吸收语雀的三栏知识库工作区、Notion 的块插入和模板化起步、Confluence 的结构化插入菜单，同时保留本项目已有的文档生命周期和运维分类能力。

## 2. 调研来源与可复用模式

| 产品/资料 | 公开来源 | 观察到的模式 | 本项目取舍 |
| --- | --- | --- | --- |
| 语雀式参考稿 | 项目内 `.design-reference/知识库编辑 - 语雀版.html`、`.design-reference/知识库详情 - 语雀版.html` | 顶部文档操作、左知识树、中间正文、右侧文章目录/设置；写作主区域持续可见 | 采用三栏职责；不实现无后端支撑的“协作”占位按钮 |
| Notion | [Intro to writing & editing](https://www.notion.com/help/writing-and-editing-basics) | 内容块、悬停块操作、`+`/`/` 插入菜单、最近使用内容块靠前 | 本轮先实现模板和“插入”菜单；完整斜杠菜单与块拖拽列为后续编辑器内核升级项 |
| Confluence Cloud | [Create and edit content](https://support.atlassian.com/confluence-cloud/docs/create-and-edit-content/)、[Insert elements into a page](https://support.atlassian.com/confluence-cloud/docs/insert-elements-into-a-page/) | 模板起步、结构化内容插入、编辑与发布动作分层 | 采用运维场景模板和结构化插入；保留草稿/发布生命周期 |
| Outline | [Outline official repository](https://github.com/outline/outline)、[Outline guide](https://docs.getoutline.com/) | collection/document 层级、轻量编辑、文档优先的阅读界面 | 采用目录与文档分层、弱化编辑器装饰；协同能力必须等待服务端协议 |

调研只用于提取交互模式，不以像素级复制某一产品为目标。当前项目是运维知识库，模板、分类、状态、版本和可检索性比自由画布、数据库视图或社交化协作更重要。

## 3. 原页面问题

### 3.1 编辑入口门槛过高

- 新建后直接面对空白编辑器，用户需要自己决定文档结构。
- Markdown 与可视化模式同级展示，普通用户在写作前先被迫理解格式概念。
- 工具栏同时展示字体、字号、行距、对齐、颜色等大量低频控件，首屏认知成本高。

### 3.2 信息架构职责重叠

- 左侧分类树与右侧标题列表都叫“目录”，用户无法立即判断两者差异。
- 保存状态在顶部和正文元信息重复出现。
- Markdown、导入、本机暂存、保存全部平铺在顶部，主次不明确。
- 设置和文章结构混在同一个右栏，但标签只写“设置/目录”，语义过于笼统。

### 3.3 写作效率不足

- 标题、提示、代码和表格需要在大工具栏中寻找。
- 新建运维文档没有故障排查、操作手册、故障复盘等固定骨架。
- 编辑页和详情页只提取 H2，三级章节在阅读页会失去结构。

## 4. 目标信息架构

```text
全局导航
└─ 文档操作栏：返回 / 当前文档 / 保存状态 / 更多 / 保存或发布
   └─ 知识库工作区
      ├─ 左：知识库目录
      │  ├─ 搜索目录和文档
      │  ├─ 分类树与文档
      │  └─ 新建、移动、分类 CRUD、回收站
      ├─ 中：文档正文
      │  ├─ 标题与所属分类
      │  ├─ 新建模板或高频格式工具栏
      │  ├─ 可视化正文
      │  └─ 插入标题、提示、代码、表格、分隔线
      └─ 右：当前文档上下文
         ├─ 文章大纲：H2/H3、定位、重命名、删除
         └─ 文档属性：分类、标签、摘要、发布、版本说明
```

边界规则：左栏操作知识库层级，中间操作正文，右栏操作当前文档上下文，顶部只承载跨区域的文档级命令。

## 5. 本轮已实施

1. 新建文档默认显示“空白文档、故障排查、操作手册、故障复盘”四种模板；选择后生成真实可编辑 HTML 正文。
2. 默认编辑方式为 WangEditor 可视化编辑，Markdown 移入顶部“更多编辑操作”。
3. 顶部“更多”统一承载 Markdown 高级模式、Markdown 导入和本机暂存，主保存按钮保持独立。
4. 富文本工具栏压缩为标题、引用、粗体、下划线、斜体、删除线、列表、待办、链接、图片、表格、代码、分隔线、撤销/重做。
5. 正文增加“插入”菜单，可在当前光标处真实插入 H2、H3、提示块、代码块、表格和分隔线。
6. 左栏继续使用“知识库目录”，右栏统一改为“大纲 / 属性”，面板标题为“文章大纲 / 文档属性”。
7. 编辑页和详情页均支持 H2/H3 大纲，三级标题缩进展示；新增、重命名、删除会回写正文。
8. 右栏使用独立浅灰背景与边界线，中间正文保持白色写作面，三栏职责在视觉上可区分。
9. 新建模板从垂直居中调整到标题下方，消除大块无意义空白；500px 窄屏使用单列模板列表。

## 6. 后续建设顺序

| 优先级 | 能力 | 实施前提与边界 |
| --- | --- | --- |
| P1 | 斜杠菜单 | 评估 WangEditor 自定义菜单或迁移到 Tiptap；必须支持键盘筛选、最近使用和光标定位，不能只弹静态菜单 |
| P1 | 模板管理 | 增加模板表、模板分类、创建/编辑/删除/权限 API；当前内置模板只负责最低门槛起步 |
| P1 | 附件与图片 | 接入对象存储和附件引用表，替换生产环境 base64 图片；支持上传进度、失败重试、引用检查 |
| P1 | 分类强外键 | 文档增加 `category_id`，通过双写和回填迁移替代字符串分类 |
| P2 | 块拖拽与大纲排序 | 需要编辑器支持稳定块 ID；大纲拖拽必须真实调整正文顺序 |
| P2 | 全局标签管理 | 增加标签字典、合并/重命名/删除 API，并展示受影响文档数量 |
| P3 | 评论与协作编辑 | 先落地用户、团队、ACL；实时协作需要 WebSocket + OT/CRDT，未具备服务端能力前不展示假按钮 |

## 7. 验收与效果指标

### 7.1 已完成技术验收

- 新建页初始显示模板选择，不加载复杂工具栏。
- 点击“故障排查”生成 4 个 H2 章节，右侧文章大纲同步生成 4 项。
- 切换 Markdown 后得到对应的 4 个 `##` 标题；返回可视化后内容不丢失。
- “插入三级标题”在正文生成 H3，并在大纲生成缩进项。
- 桌面 1440×1000 与窄屏 500×844 无横向溢出或组件覆盖。
- Vue 类型检查、Vite 生产构建和依赖安全审计通过。

### 7.2 建议增加的产品指标

- 新建到首次输入或选择模板的耗时。
- 新建页面退出率、模板选择率和各模板使用占比。
- 草稿保存成功率、发布成功率、版本冲突率。
- Markdown 高级模式使用率，用于判断其入口是否还需要继续弱化。
- 用户完成首篇文档所需的平均操作数。

这些指标需要前端埋点和后端事件模型支持，本轮不添加虚假统计。

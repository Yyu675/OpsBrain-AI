## 三、六层干净架构职责边界（SRP 铁律）

| 层 | 包路径 | ✅ 只做 | 🚫 严禁 |
| :--- | :--- | :--- | :--- |
| L1 Controller | `controller` | HTTP/SSE 接入、参数判空、traceId、`new SseEmitter`、连接异常回调 | 拼 Prompt、直接调 model、写 SQL、直接用 redisTemplate |
| L2 Application | `application` | 缓存拦截→路由→调引擎→异步记账的编排 | 自己写切片算法、自己写工单入库 SQL |
| L3 RAG | `domain.rag` | 切片、向量化、混合检索、`Score<0.73` 过滤、返回带出处父段落 | 干涉大模型如何措辞回答 |
| L4 Tools | `domain.tools` | `@Tool` 原子能力、参数强校验、抛异常供模型反思 | 在工具内再起一轮 Agent 循环（防死循环） |
| L5 Biz | `domain.biz` | 工单 CRUD、调用日志统计入库 | 只接收 100% 校验后的结构化数据 |
| L6 Infra | `infrastructure` | 模型 Bean、向量库/Redis 连接、API Key/超时/温度 | 换模型时不允许改上层任何业务代码 |

**核心承诺**：换底层模型（DeepSeek → 私有 Ollama）只改 `infrastructure.llm.AiModelConfig` 一处，上层零改动。

## 四、一次流式请求的调用时序

```
前端 fetchEventSource GET /api/v1/chat/stream?query=...
   │
   ▼
DevOpsChatController ── 校验+traceId+SseEmitter ──► 发 event:start
   │
   ▼
DevOpsAgentServiceImpl (大总管)
   ├─► SemanticCacheService.tryHitCache()
   │      └─ 相似度 >0.95 命中 → 模拟打字机推流 → event:complete(isCached=true) 【48ms 结束】
   │
   ├─► [未命中] SecurityInputGuard 注入检测 → 命中危险词则拦截
   │
   ├─► DevOpsIntentRouter.routeEngine(query) → 选 turbo 或 reasoning 引擎
   │
   ├─► engine.streamChat(query) 启动 ReAct (maxIterations=3)
   │      ├─ 模型决定调工具 → 发 event:tool_status
   │      │     └─► DevOpsTools.searchDevOpsKnowledge() → HybridRetriever → 过滤<0.73
   │      └─ 模型流式吐字 → 逐 token 发 event:token
   │
   ├─► onComplete: cacheService.putCache() + 发 event:complete(isCached=false)
   │
   └─► 异步线程池 AgentCallLogService.recordLog() 写 sys_agent_call_log
```

## 五、⚠️ 关键契约锁定：Embedding 维度（必读）

**这是全项目最易翻车的点**。原始文档中 Day2 同时出现了 `.dimension(1536)` 与 `BgeLargeZhEmbeddingModel`（实际 1024 维），二者冲突会导致入库首行即抛 `PSQLException: expected 1024 dimensions, not 1536`。

**MVP 定型决策：统一采用方案 A（云 API Embedding，1536 维）。** 理由：本地 ONNX 模型吃内存（8G/16G 笔记本易 OOM），云 Embedding 零本地压力、维度稳定。

| 项 | 锁定值 |
| :--- | :--- |
| Embedding 模型 | 阿里云百炼 `text-embedding-v2` 或 OpenAI `text-embedding-3-small` |
| 输出维度 | **1536** |
| `VectorStoreConfig` | `.dimension(1536)` |
| `init.sql` 建表 | `embedding vector(1536)` |
| Redis 语义缓存向量 | 同源 1536 维 |

> 🔒 **铁律**：全链路（切片入库、检索、语义缓存）必须使用**同一个** EmbeddingModel Bean，绝不允许入库用 A、检索用 B。

> 若坚持本地免费 ONNX（`bge-large-zh-v1.5`），则全链路改为 **1024** 维，且注意正确的类名（见 [功能模块设计 §RAG 层](02-功能模块设计.md)），不能使用含连字符的非法包名。

  ai:
    mode: MOCK   # MOCK=本地模拟不调API不连库；REAL=接真实LLM+向量库

- 二者实现同一 `DevOpsAgentService` 接口，Controller 与前端零感知切换。

## 八、非功能性指标预算（Latency Budget）

| 环节 | 时间预算 |
| :--- | :--- |
| Redis 语义缓存检索 | < 20ms（命中即结束，总 ~48ms） |
| PgVector 混合检索 + 过滤 | < 120ms |
| LLM 首字响应 TTFT | < 700ms |
| **前端首屏可见（SSE 首字）** | **< 850ms** |
| 简单问答总耗时（Turbo 路） | < 1s |
| 复杂推理总耗时（R1 路） | 2 ~ 3s |

成本目标：单次均价 < 0.005 元，人均日成本 < 0.05 元（对比传统降本 > 70%）。

## 九、容错与安全（MVP 最小闭环）

- **降级兜底**：推理路（R1）超时/429/503 → `try-catch` 平滑降级回主路 Turbo，前端无报错弹窗。
- **SSE 防缓冲**：响应头 `Cache-Control: no-cache, no-transform`、`X-Accel-Buffering: no`，防 Tomcat/Nginx 缓冲吞流。
- **SSE 防泄漏**：`new SseEmitter(60_000L)` + `onTimeout`/`onError` 回调释放。
- **前端防重连风暴**：`onerror` 内 `throw err` 截断 fetch-event-source 无限重连。
- **注入防护**：`SecurityInputGuard` 正则拦截"忽略提示词/Ignore previous instructions/系统密码"等。
- **越权隔离**：绝不注册任何 `ProcessBuilder`/`Runtime.exec` 类工具，模型物理上无法操作宿主机。

> ⚠️ **安全提示**：MVP 明确不做鉴权（全局硬编码 `userId=devops-admin`）。SSE 接口 `@CrossOrigin(origins="*")` 仅限本地/演示环境；公网部署前需收敛 CORS 白名单并在 Nginx 层加访问控制，否则接口对外裸奔。

## 十、部署架构（生产一键编排）

`docker-compose.prod.yml` 编排 4 容器：

```
prod-frontend (Nginx:80) ──► prod-backend (SpringBoot:8080) ──┬─► prod-pgvector (5432)
                                                              └─► prod-redis (6379)
```

- 前端多阶段构建（node 编译 → nginx 托管）；2核4G 云服务器建议本地 `npm run build` 后再打包，规避 `npm run build` OOM。
- 后端 `eclipse-temurin:17-jre-alpine`。
- 敏感配置（DB/Redis 密码、`DEEPSEEK_API_KEY`）通过环境变量注入，禁止硬编码入 Git。

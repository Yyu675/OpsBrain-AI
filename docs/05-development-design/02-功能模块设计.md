# 🧩 OpsBrain AI 智能运维助手 —— 功能模块设计说明书

> **文档定位**：本文档是「做什么、每个模块的职责与输入输出、模块之间如何协作」的功能级契约。它把 6 层干净架构（见《01-技术架构设计.md》）中的每一层落到**可编码的具体模块**，明确每个模块的类名、方法签名、依赖关系与验收点。
> **配套阅读**：数据结构见《03-数据库设计.md》，对外接口见《04-API接口设计.md》，落地节奏见 `04-daily-implementation-plan/`。
> **MVP 边界**：严格遵守《前置契约白皮书》的 MUST DO / MUST NOT。不做登录鉴权、不做在线富文本编辑、不做 WebSocket。

## 一、 功能模块全景图

系统按职责划分为 **8 个一级功能模块**，分属 6 层架构。下表是模块索引，后续章节逐一展开。

| 编号 | 一级模块 | 所属架构层 | 核心职责一句话 | 落地天数 |
| :--: | :--- | :--- | :--- | :--: |
| **M1** | 对话接入与流式推送 | Controller | 接收提问，用 SSE 四事件把结果一个字一个字推给前端 | Day6 |
| **M2** | Agent 编排调度 | Application | 系统大脑：缓存拦截 → 路由分流 → 调起引擎 → 异步记账 | Day5/6 |
| **M3** | 智能意图路由 | Application | 判断问题复杂度，分发到 Turbo 小模型或 R1 推理模型 | Day5 |
| **M4** | 语义缓存 | Infrastructure | 向量相似度 > 0.95 直接复用历史答案，0 花费 | Day6 |
| **M5** | RAG 知识检索 | Domain / RAG | 文档父子切片、向量化入库、混合检索 + 阈值熔断 | Day2/4 |
| **M6** | 白名单工具 | Domain / Tools | 只暴露"查手册"和"提工单"两个 @Tool，物理防越权 | Day3/4 |
| **M7** | 运维业务 | Domain / Biz | 工单落库、调用日志记账 | Day3/5 |
| **M8** | 看板统计 | Controller / Biz | 聚合调用日志，输出 ECharts 看板所需指标 | Day8 |

外加两个横切模块：**输入安全门卫（SecurityInputGuard）** 与 **全局异常兜底（GlobalExceptionHandler）**。

## 二、 模块调用主链路（一次问答的完整流转）

```
前端提问
  │  GET /api/v1/chat/stream?query=...
  ▼
[M1 DevOpsChatController]  创建 SseEmitter(60s)，设置防缓冲响应头，异步执行
  │
  ▼
[横切: SecurityInputGuard]  Prompt 注入 / 敏感词拦截 → 命中则直接 error 事件返回
  │
  ▼
[M2 DevOpsAgentServiceImpl]  编排大总管
  │
  ├─(1)─▶ [M4 SemanticCacheService.tryHitCache]  相似度 > 0.95？
  │         └─命中─▶ 模拟打字机推送历史答案 → complete(isCached=true, cost=0) → 结束
  │
  ├─(2)─▶ [M3 DevOpsIntentRouter.routeEngine]  未命中，判断复杂度
  │         ├─ 短问 / 无堆栈特征 ─▶ turboEngine (deepseek-chat)
  │         └─ 长文本 / 含堆栈特征 ─▶ reasoningEngine (deepseek-reasoner)
  │
  ├─(3)─▶ [选中的 DevOpsAgentEngine.chatStream]  启动 ReAct，maxIterations(3)
  │         │
  │         ├─ 模型决定查手册 ─▶ [M6 DevOpsTools.searchDevOpsKnowledge]
  │         │                        └─▶ [M5 检索: 向量+关键词 → 过滤<0.73 → 返回父段落]
  │         │
  │         ├─ 模型决定提工单 ─▶ [M6 DevOpsTools.createDevOpsTicket]
  │         │                        └─▶ [横切 ToolParameterValidator 校验]
  │         │                        └─▶ [M7 TicketService.save 落库]
  │         │
  │         └─ 流式吐 token ─▶ 经 M1 escapeJson 后发 token 事件
  │
  ├─(4)─▶ [M4 SemanticCacheService.putCache]  写入本轮问答供下次复用
  │
  └─(5)─▶ [M7 AgentCallLogService.recordAsync]  线程池异步落 sys_agent_call_log
            │
            ▼
        complete 事件 (traceId, latencyMs, isCached, costRmb, citations) → emitter.complete()
```

## 三、 各模块详细设计

### M1 — 对话接入与流式推送模块

| 项 | 内容 |
| :--- | :--- |
| **包路径** | `com.devops.agent.controller` |
| **核心类** | `DevOpsChatController` |
| **对外接口** | `GET /api/v1/chat/stream`（详见《04-API接口设计.md》） |
| **依赖** | M2 `DevOpsAgentService` |

**职责边界（SRP）**
- ✅ 只做：解析 query、生成 traceId、`new SseEmitter(60000L)`、设置防缓冲头（`Cache-Control: no-cache, no-transform`、`X-Accel-Buffering: no`）、注册 `onTimeout/onError` 清理、把 M2 产出的事件流写进 emitter。
- 🚫 严禁：拼 Prompt、直接调 `chatModel`、写 SQL、操作 `redisTemplate`。

**关键方法**
```java
@GetMapping(path = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter streamChat(@RequestParam("query") String query, HttpServletResponse response);

// 内部工具方法（私有）
private void sendEvent(SseEmitter emitter, String eventName, String jsonPayload) throws IOException;
private String escapeJson(String raw);   // 必须转义 \ " \n \r，否则前端 JSON.parse 崩
```

**SSE 事件契约（定型，前后端共用）**

| event | 触发时机 | data 字段 |
| :--- | :--- | :--- |
| `start` | 连接建立 | `traceId`, `routerModel` |
| `tool_status` | 工具开始执行 | `toolName`, `status`(RUNNING), `message` |
| `token` | 每个字符/词 | `text` |
| `complete` | 结束 | `traceId`, `latencyMs`, `isCached`, `costRmb`, `citations[]` |
| `error` | 安全拦截/异常 | `traceId`, `code`, `message` |

> ⚠️ **字段命名定型**：成本字段全链路统一为 **`costRmb`**（Double，人民币元）。废弃《白皮书》里出现过的 `totalCostRmb` 写法。前端 Day7 读的就是 `costRmb`，保持一致。

### M2 — Agent 编排调度模块

| 项 | 内容 |
| :--- | :--- |
| **包路径** | `com.devops.agent.application` |
| **核心类** | `DevOpsAgentService`（接口）、`DevOpsAgentServiceImpl` |
| **依赖** | M3 路由、M4 缓存、M6/M5 引擎、M7 记账、SecurityInputGuard |

**职责边界**
- ✅ 只做：编排顺序（安全门卫 → 缓存 → 路由 → 引擎 → 记账），把每一步产出转成 SSE 事件回调。
- 🚫 严禁：自己写切片算法、自己写工单入库 SQL、自己算相似度。全部委托下层。

**核心方法签名**
```java
public interface DevOpsAgentService {
    /** 编排一次完整问答，通过 emitter 以 SSE 事件流式输出 */
    void handleStreamChat(String query, String traceId, SseEmitter emitter);
}
```

**编排伪代码**
```
1. guard.check(query)                     // 命中 → 发 error 事件，return
2. cached = cache.tryHitCache(query)
   if cached != null → 模拟打字机推送 → complete(isCached=true, costRmb=0) → return
3. engine = router.routeEngine(query)     // 返回引擎 + 命中的 routerModel 名
4. 发 start 事件(routerModel)
5. engine.chatStream(query)               // 流式，工具回调经 M1 转 SSE
     .onNext → token 事件
     .onComplete → cache.putCache(); logService.recordAsync(); complete 事件
     .onError → error 事件
```

### M3 — 智能意图路由模块

| 项 | 内容 |
| :--- | :--- |
| **包路径** | `com.devops.agent.application.router` |
| **核心类** | `DevOpsIntentRouter` |
| **依赖** | 两个 `DevOpsAgentEngine` Bean（`turboAgentEngine` / `reasoningAgentEngine`） |

**分流规则（两级，纯本地，0 延时 0 花费）**

| 优先级 | 判定条件 | 分发目标 |
| :--: | :--- | :--- |
| 1 | 长度 < 60 且不含堆栈特征词 | `turboEngine`（deepseek-chat） |
| 2 | 长度 ≥ 150 或含堆栈特征词（exception/stacktrace/at com./caused by/panic 等） | `reasoningEngine`（deepseek-reasoner） |
| 3 | 灰度地带（60~150 之间且无特征） | 兜底 `turboEngine` |

**降级容错**：`reasoningEngine` 返回 429/503/超时，`try-catch` 平滑回退到 `turboEngine`，前端提示"正在启用深度排查专家引擎"。

**方法签名**
```java
public DevOpsAgentEngine routeEngine(String userQuery);
public String routedModelName(String userQuery);   // 供 start 事件展示 routerModel
```

### M4 — 语义缓存模块

| 项 | 内容 |
| :--- | :--- |
| **包路径** | `com.devops.agent.infrastructure.cache` |
| **核心类** | `SemanticCacheService` |
| **依赖** | `StringRedisTemplate`、`EmbeddingModel` |

**命中逻辑**：把 query 向量化 → 与近期热点问题向量算余弦相似度 → **≥ 0.95** 判为同义 → 取 Redis 中 `devops:cache:ans:{query}` 的历史答案。

**方法签名**
```java
public String tryHitCache(String userQuery);          // 命中返回答案，否则 null
public void putCache(String userQuery, String answer); // TTL = 24h
```

**失效策略**：Redis Key `TTL=24h`；知识库文档更新时，由 M5 触发批量 `DEL devops:cache:ans:*` 保证一致性。

> 📌 MVP 阶段热点向量用 `ConcurrentHashMap` 内存缓存即可；进阶可迁移到 Redis Hash 或 PgVector。

### M5 — RAG 知识检索模块

| 项 | 内容 |
| :--- | :--- |
| **包路径** | `com.devops.agent.domain.rag` |
| **核心类** | `ParentChildDocumentSplitter`、`KnowledgeIngestionService`、`HybridRetrieverService` |
| **依赖** | `EmbeddingStore<TextSegment>`、`EmbeddingModel` |

**子模块职责**

| 类 | 职责 | 关键方法 |
| :--- | :--- | :--- |
| `ParentChildDocumentSplitter` | 按 `## ` 标题切父段落(~800token)，父内切子段落(~200token)，子段落 metadata 绑 `parent_id` + `parent_text` | `List<TextSegment> splitWithParentChild(Document doc)` |
| `KnowledgeIngestionService` | 扫 `resources/knowledge/*.md` → 切片 → 向量化 → 批量入库 | `void ingestAllLocalDocuments()` |
| `HybridRetrieverService` | 向量检索 + PostgreSQL tsvector 关键词检索，加权 `0.65*向量 + 0.35*关键词`，阈值 < 0.73 过滤，返回去重父段落 | `List<KnowledgeChunkDTO> retrieve(String query, int topK)` |

**阈值熔断（第四层幻觉防护）**：`embeddingStore.search(EmbeddingSearchRequest.builder().queryEmbedding(embedding).maxResults(3).minScore(0.73).build())`，从返回的 `EmbeddingSearchResult<TextSegment>` 用 `.matches()` 取 `List<EmbeddingMatch<TextSegment>>`；空结果返回标准兜底话术，绝不把低分垃圾文本喂给模型。

> 📌 **MVP 简化**：混合检索的关键词部分若来不及做，可退化为纯向量检索 + 0.73 阈值，先保证主干跑通（遵守《PM 开工令》降级跳过法则）。父子切片和阈值熔断是必做项。

### M6 — 白名单工具模块

| 项 | 内容 |
| :--- | :--- |
| **包路径** | `com.devops.agent.domain.tools` |
| **核心类** | `DevOpsTools`（@Component，Spring 托管）、`ToolParameterValidator` |
| **依赖** | M5 检索、M7 TicketService |

**⚠️ 关键约束（SOP 拦截点 3）**：`DevOpsTools` 必须交给 Spring IOC 托管，构造引擎时通过 `.tools(devOpsToolsBean)` 注入，**严禁 `new DevOpsTools()`**，否则内部 `@Autowired` 字段为 null 抛 NPE。

**只暴露两个 @Tool（物理防越权，第二层幻觉防护）**

```java
@Tool("检索 K8s/阿里云 SLB 等运维手册文档切片")
public String searchDevOpsKnowledge(@P("精炼检索关键词") String keyword);

@Tool("用户需要开工单/上报二级运维时调用")
public String createDevOpsTicket(
    @P("工单标题") String title,
    @P("优先级 [HIGH/MEDIUM/LOW]") String priority,
    @P("故障描述与堆栈摘要") String description);
```

- 🚫 绝不注册任何 `Runtime.exec` / `ProcessBuilder` / Shell 类工具。
- `createDevOpsTicket` 第一行调 `ToolParameterValidator` 强校验，参数不合格抛 `IllegalArgumentException`，LangChain4j 会把异常带回给模型自愈重试（第三层幻觉防护）。

## 四、 四层幻觉防护 → 模块映射（面试高频，务必对齐）

## 五、 模块级验收清单（DoD）

- [ ] M1：`curl -N .../chat/stream?query=你好` 逐字冒 token，中断连接后台打印清理日志无泄漏
- [ ] M3：短问走 turbo（<1s），长堆栈走 reasoning（2-3s），日志可见分流决策
- [ ] M4：连续两次同义提问，第二次 `isCached=true` 且 <50ms
- [ ] M5：`ingestAllLocalDocuments()` 入库 50+ 切片；检索"Pod FailedMount"返回正确父段落
- [ ] M6：输入"重启全部服务器"被拒；输入"提工单"触发建单；`maxIterations(3)` 内闭环
- [ ] M6：超纲提问触发 0.73 熔断，输出兜底话术无捏造
- [ ] M8：看板 4 卡片 + 饼图 + 降本折线正常渲染，空数据有兜底

# 🗄️ OpsBrain AI 智能运维助手 —— 数据库设计说明书

> **文档定位**：定型数据持久层结构，含 PgVector（关系表 + 向量表）与 Redis（语义缓存 + 会话）两部分。所有表结构、字段类型、索引在此冻结，`sql/init.sql` 以本文档为准。
> **配套阅读**：字段与 DTO 映射见《03-API接口设计.md》；表的使用方（Repo 层）见《02-功能模块设计.md》。

---

## 一、 存储选型总览

| 存储 | 版本/镜像 | 用途 | 说明 |
| :--- | :--- | :--- | :--- |
| PostgreSQL + pgvector | `ankane/pgvector:v0.5.1` | 关系数据 + 向量检索 | 一库两用，避免 Java 调 FAISS 的 JNI 巨坑 |
| Redis | `redis:7.0-alpine` | 语义缓存 / 会话窗口 | 缓存答案 + 存热点向量 |

> **不引入 MySQL / ElasticSearch**。全文关键词检索用 PostgreSQL 内置 `tsvector + GIN`，向量检索用 pgvector `hnsw`，统一在一个 PostgreSQL 实例内完成混合检索（Hybrid Search）。

## 二、 ⚠️ 向量维度铁律（开工前必须二选一，全链路统一）

这是最高频、最致命的踩坑点（SOP 拦截点 2）。`init.sql` 建表维度、`VectorStoreConfig.dimension()`、`EmbeddingModel` 输出维度**三者必须完全一致**，绝不允许上下游混搭：

| 方案 | Embedding 来源 | 实际维度 | 建表字段 | `.dimension()` | 推荐场景 |
| :--- | :--- | :--: | :--- | :--- | :--- |
| **A（推荐）** | 阿里云百炼 `qwen-text-embedding-v2` / OpenAI `text-embedding-3-small` | **1536** | `vector(1536)` | `.dimension(1536)` | 本地内存小，走 API，0 本地压力 |
| **B** | 本地 ONNX `bge-large-zh-v1.5` | **1024** | `vector(1024)` | `.dimension(1024)` | 无 API Key，纯离线 |

> **本项目默认选方案 A（1536 维）**，与《白皮书》`init.sql` 一致。
> 若改用本地 bge（1024 维），必须同步改建表字段和 `.dimension()`，否则入库首行即抛 `PSQLException: expected 1024 dimensions, not 1536`。
>
> **注意 Day2 文档遗留问题**：Day2 计划里同时出现了 `.dimension(1536)` 和 `import ...BgeLargeZhEmbeddingModel`（1024 维），且该 import 包名含连字符是非法 Java 语法。编码时以本表方案 A 为准，不要照抄 Day2 的 bge import。

## 三、 PgVector 关系表 / 向量表结构（`sql/init.sql`）

### 0. 启用扩展
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 表 1：`sys_knowledge_chunk` —— 知识库切片与向量

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | BIGSERIAL | PK | 自增主键 |
| `doc_title` | VARCHAR(255) | NOT NULL | 所属手册名（如 K8s故障处理手册） |
| `section_header` | VARCHAR(512) | | 章节标题 |
| `content` | TEXT | NOT NULL | 子切片纯文本（供向量检索，~200 Token） |
| `parent_id` | VARCHAR(128) | | 父段落 ID，形如 `K8s手册-P-3` |
| `parent_text` | TEXT | | 完整父段落（~800 Token，检索命中后直接送 LLM） |
| `chunk_meta` | JSONB | | 扩展元数据（version/module/priority_weight 等） |
| `content_tsv` | TSVECTOR | | 全文检索分词列（混合检索用） |
| `embedding` | VECTOR(1536) | NOT NULL | 子切片向量（维度随方案，见第二节） |
| `create_time` | TIMESTAMP | DEFAULT now | 入库时间 |

```sql
CREATE TABLE IF NOT EXISTS sys_knowledge_chunk (
    id BIGSERIAL PRIMARY KEY,
    doc_title VARCHAR(255) NOT NULL,
    section_header VARCHAR(512),
    content TEXT NOT NULL,
    parent_id VARCHAR(128),
    parent_text TEXT,
    chunk_meta JSONB,
    content_tsv TSVECTOR,
    embedding VECTOR(1536) NOT NULL,
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 向量：余弦相似度 HNSW 高速索引
CREATE INDEX IF NOT EXISTS idx_chunk_embedding_hnsw
    ON sys_knowledge_chunk USING hnsw (embedding vector_cosine_ops);

-- 全文：GIN 索引（混合检索 Sparse 侧）
CREATE INDEX IF NOT EXISTS idx_chunk_tsv_gin
    ON sys_knowledge_chunk USING gin (content_tsv);

-- 父段落聚合查询辅助
CREATE INDEX IF NOT EXISTS idx_chunk_parent ON sys_knowledge_chunk (parent_id);
```

> **父子切片说明**：`content` 存短子切片（检索精度高），`parent_text` 存完整父段落（回答完整）。检索命中子切片后直接取其 `parent_text` 送 LLM，无需二次回查，见《02-功能模块设计.md》M4。
> **LangChain4j 兼容**：`PgVectorEmbeddingStore(createTable=true)` 会自建它自己的表结构。若用其托管建表，`parent_id/parent_text` 通过 `TextSegment.metadata` 落入其 metadata 列；若手动建表则用本 DDL。二者择一，不要混用。

### 表 2：`sys_devops_ticket` —— 自动化运维工单

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | VARCHAR(64) | PK | 工单号，如 `TKT-20260714-88` |
| `title` | VARCHAR(255) | NOT NULL | 故障标题 |
| `priority` | VARCHAR(32) | NOT NULL | HIGH / MEDIUM / LOW |
| `module` | VARCHAR(64) | NOT NULL | K8S / ALIYUN_SLB / MYSQL / NETWORK |
| `description` | TEXT | | 报错详情与诊断建议 |
| `status` | VARCHAR(32) | DEFAULT 'PENDING' | PENDING / PROCESSING / CLOSED |
| `source_trace_id` | VARCHAR(64) | | 来源会话 traceId |
| `create_time` | TIMESTAMP | DEFAULT now | 创建时间 |

```sql
CREATE TABLE IF NOT EXISTS sys_devops_ticket (
    id VARCHAR(64) PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    priority VARCHAR(32) NOT NULL,
    module VARCHAR(64) NOT NULL,
    description TEXT,
    status VARCHAR(32) DEFAULT 'PENDING',
    source_trace_id VARCHAR(64),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_ticket_priority ON sys_devops_ticket (priority);
CREATE INDEX IF NOT EXISTS idx_ticket_status   ON sys_devops_ticket (status);
```

### 表 3：`sys_agent_call_log` —— 调用与降本统计（看板数据源）

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | BIGSERIAL | PK | 自增 |
| `trace_id` | VARCHAR(64) | | 会话 ID |
| `user_query` | TEXT | | 用户提问 |
| `router_model` | VARCHAR(64) | | deepseek-chat / deepseek-reasoner / semantic-cache |
| `is_cache_hit` | BOOLEAN | DEFAULT false | 是否命中语义缓存 |
| `latency_ms` | INT | | 总耗时毫秒 |
| `token_cost` | DOUBLE PRECISION | | 本次花费（元） |
| `create_time` | TIMESTAMP | DEFAULT now | 记录时间 |

```sql
CREATE TABLE IF NOT EXISTS sys_agent_call_log (
    id BIGSERIAL PRIMARY KEY,
    trace_id VARCHAR(64),
    user_query TEXT,
    router_model VARCHAR(64),
    is_cache_hit BOOLEAN DEFAULT FALSE,
    latency_ms INT,
    token_cost DOUBLE PRECISION,
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_log_create_time ON sys_agent_call_log (create_time);
CREATE INDEX IF NOT EXISTS idx_log_router ON sys_agent_call_log (router_model);
```

> **字段名对齐提醒**：日志表存 `token_cost`（下划线），SSE `complete` 事件对外用 `costRmb`（驼峰），二者是同一含义，在 Service/DTO 转换层映射，编码时勿混淆。

## 四、 看板聚合 SQL（供接口 2 / M8）

```sql
-- 总问答数

  FROM sys_agent_call_log GROUP BY router_model;
```

## 五、 Redis 键设计

| Key 模式 | 类型 | TTL | 说明 |
| :--- | :--- | :--- | :--- |
| `devops:cache:ans:{query}` | String | 24h | 语义缓存的历史答案文本 |
| `devops:cache:vec:{query}` | String/Hash | 24h | 热点提问向量（可选，也可存 JVM `ConcurrentHashMap`） |
| `devops:session:{userId}` | List | 2h | 会话滑动窗口（MVP 可省略） |

**语义缓存命中逻辑**（M2）：
1. 新 query 向量化 → 与近期热点向量算余弦相似度
2. `similarity >= 0.95` 判为同义 → 取 `devops:cache:ans:{命中query}` 直接流式回放
3. 命中耗时 <50ms、0 Token
4. 知识库重新入库时，`DEL` 对应缓存快照保证一致性

> 连接配置：`host=localhost port=6379 password=devops_redis_pwd`（开发），生产走环境变量。

## 六、 ER 与数据流关系

```
                        ┌──────────────────────┐
   Markdown 手册 ──入库──▶│ sys_knowledge_chunk  │◀──向量+全文混合检索── M4 RAG
                        │ (embedding/tsv/父子)  │
                        └──────────────────────┘
   用户提问 ──▶ M2 语义缓存(Redis) ─未命中─▶ M3 路由 ─▶ Agent ─┬─▶ M4 检索(上表)
                                                            └─▶ M6 建单 ─▶ sys_devops_ticket
                                                                            │
   每次调用结束 ──异步写──▶ sys_agent_call_log ──聚合──▶ M8 看板(接口2)
```

三张表之间**无外键强关联**（MVP 简化，靠 `trace_id` / `parent_id` 逻辑关联），降低耦合、便于独立测试。

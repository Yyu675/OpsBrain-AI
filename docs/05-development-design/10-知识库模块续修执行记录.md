## 4. 尚未伪实现的能力

以下差异不能只靠前端补样式，否则会形成假数据或假 CRUD：

| 能力 | 当前阻塞 | 可行改造 |
| --- | --- | --- |
| 最多浏览 / 阅读量 | `sys_knowledge_doc` 无浏览量字段，也无详情访问计数接口 | 增加 `view_count` 或独立事件表；详情访问异步计数；列表开放 `VIEWS_DESC` 排序 |
| 权限 / 团队可见 | 文档 DTO、表结构和鉴权策略均无权限字段 | 增加 visibility、owner/team、ACL 表，并在查询层强制权限过滤 |
| 分类强外键 | 本轮为兼容历史接口，文档仍保存规范化分类名，分类重命名由事务同步 | 后续可增加 `category_id` 外键并双写迁移，最终移除字符串关联；当前 CRUD 与层级能力不受影响 |
| 协作编辑 | 无协作会话、在线成员、冲突合并协议 | 需要 WebSocket + OT/CRDT 服务；不能放一个无效果的“协作”按钮冒充完成 |

## 5. 后续产品设计建议

| 优先级 | 建议 | 可行方案 |
| --- | --- | --- |
| P1 | 降低长文档排版成本 | 在现有可视化编辑器上增加斜杠菜单和块级快捷插入，首批覆盖标题、提示块、代码块、表格、图片；Markdown 保持为高级模式，不再作为默认入口 |
| P1 | 统一标签管理 | 增加标签字典与标签管理抽屉，支持新建、重命名、合并、删除和使用量；删除前显示受影响文档并要求确认 |
| P1 | 完成分类强关联 | 文档表增加 `category_id` 外键，先双写、回填与校验，再移除字符串分类；避免同名分类和重命名批量更新成本 |
| P1 | 正式化图片与附件 | 将当前 2MB 以内图片粘贴能力替换为对象存储上传，保存资源 ID、URL、文件名、大小和引用关系；删除文档时做引用检查 |
| P2 | 提升目录编辑效率 | 右栏目录支持拖拽调整章节顺序、折叠层级，并将 H2/H3 层级同步到正文；操作必须写回正文而不是只改右栏状态 |
| P2 | 提升检索与浏览效率 | 列表增加已保存筛选、最近浏览、我的文档；依赖真实用户与访问事件数据后再开放“最多浏览”排序 |
| P3 | 团队权限与协同 | 先落地所有者、团队、可见范围和 ACL，再建设评论、提及与 WebSocket + CRDT 协作；未有服务端能力前不展示占位按钮 |

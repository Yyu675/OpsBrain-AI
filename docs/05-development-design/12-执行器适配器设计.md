# 12 · 执行器适配器设计（D1 拍板：适配器模式）

> **决策**：2026-08-26 用户拍板——真实执行器采用**适配器模式（Adapter Pattern）**实现。
> **目的**：V1.2 第一个只读执行器（`queryPodStatus`）的设计前置；让「目标系统选型」只影响一个实现类，选型错误可低成本替换。
> **配套**：59 号报告 §三（双轨验证）、63 号报告（V1.2 里程碑）、PRD §9（L4 受控自愈）。

---

## 一、为什么是适配器模式

| 对比项 | 直连实现 | 适配器模式 |
|--------|---------|-----------|
| 目标系统更换 | 改业务代码 | **只新增一个适配器** |
| 测试 | 依赖真实集群 | 适配器接口可 mock / Fake 实现 |
| 凭证管理 | 散落各处 | 每适配器自管（KubeConfig / AK-SK / 平台令牌） |
| 爆炸半径控制 | 与业务耦合 | 统一命令模型承载（namespace / maxInstances） |
| 治理链路接入 | 每系统一套 | **统一入口 `OpsExecutor`，治理只认接口** |

**架构形态**：

```
AI Agent (@Tool)
  └─ ToolRuntimeManager（白名单/风险分级/审批/记录/审计）
       └─ OpsExecutorAdapter（把执行器包装成 @Tool，统一治理）
            └─ OpsExecutor（统一执行接口）
                 ├─ K8sOpsExecutor      ← 第一个实现（fabric8，V1.2）
                 ├─ CloudOpsExecutor    ← 预留（云厂商 API）
                 └─ ScriptOpsExecutor   ← 预留（内部脚本平台）
```

## 二、接口设计（Java 骨架，已建代码文件）

### 2.1 统一命令模型 `OpsCommand`

```java
public record OpsCommand(
        String action,            // 动作标识：queryPodStatus / restartPod / logCleanup ...
        Map<String, String> params, // 参数（namespace / pod / path ...）
        String targetSystem        // 目标系统：k8s / aliyun / script ...
) {
    public String requireParam(String key) { /* 缺失抛 IllegalArgumentException */ }
}
```

### 2.2 统一执行接口 `OpsExecutor`

```java
public interface OpsExecutor {
    /** 目标系统标识（注册表键） */
    String targetSystem();

    /** 支持的动作白名单（只读动作 + 写动作，供校验与 UI 展示） */
    Set<String> supportedActions();

    /** 执行动作（只读动作无副作用；写动作由治理层审批后调用） */
    OpsExecutionResult execute(OpsCommand command);

    /** 是否有补偿动作（写操作需在 @ToolMeta.compensationAction 声明） */
    default boolean supportsCompensation(String action) { return false; }
}
```

### 2.3 统一结果 `OpsExecutionResult`

```java
public record OpsExecutionResult(
        boolean success,
        String summary,      // 人类可读摘要（审计/展示）
        Map<String, Object> data,  // 结构化结果（前端渲染）
        String errorMessage
) {
    public static OpsExecutionResult ok(String summary, Map<String, Object> data) { ... }
    public static OpsExecutionResult fail(String errorMessage) { ... }
}
```

### 2.4 执行器注册表 `OpsExecutorRegistry`

```java
@Component
public class OpsExecutorRegistry {
    private final Map<String, OpsExecutor> executors = new ConcurrentHashMap<>();

    public void register(OpsExecutor executor) { executors.put(executor.targetSystem(), executor); }

    public OpsExecutor resolve(String targetSystem) {
        OpsExecutor e = executors.get(targetSystem);
        if (e == null) throw new IllegalArgumentException("未注册的目标系统: " + targetSystem);
        return e;
    }

    public Set<String> registeredSystems() { return executors.keySet(); }
}
```

## 三、K8s 适配器实现要点（第一个，V1.2）

```java
@Component
public class K8sOpsExecutor implements OpsExecutor {

    // 懒加载：只有配置了 kubeconfig 才初始化（未配置时系统仍可运行，只读动作报「未配置集群」）
    private volatile KubernetesClient client;

    @Override public String targetSystem() { return "k8s"; }

    @Override public Set<String> supportedActions() {
        return Set.of("queryPodStatus");   // V1.2 只读切口；restartPod 等写动作 V1.3 再加
    }

    @Override public OpsExecutionResult execute(OpsCommand cmd) {
        return switch (cmd.action()) {
            case "queryPodStatus" -> queryPodStatus(cmd);   // fabric8 podOperations().inNamespace().withName().get()
            default -> OpsExecutionResult.fail("K8s 适配器不支持动作: " + cmd.action());
        };
    }
}
```

**关键设计**：
1. **依赖**：`io.fabric8:kubernetes-client`（V1.2 加入 pom，CI 用官方 `FakeK8sClient` 测试）；
2. **凭证**：KubeConfig（默认 `~/.kube/config`，可用 `KUBECONFIG` 覆盖）或 ServiceAccount——凭证不进仓库，符合 PRD §十一；
3. **爆炸半径**：命令统一走 `namespace` 限定，写动作强制单实例（V1.3 金丝雀 5% 在治理层校验）；
4. **只读优先**：`queryPodStatus` 无副作用，`READ_ONLY_DIAGNOSTIC` 免审批——先走通治理全链路，再上写动作。

## 四、与现有治理链路的集成（复用，不新建）

| 现有组件 | 适配器接入方式 |
|---------|--------------|
| `DevOpsTools`（2 个 @Tool） | 新增 `@Tool("查询 K8s Pod 状态")` 方法 → 内部走 `OpsExecutorRegistry.resolve("k8s").execute(...)` |
| `ToolRuntimeManager`（白名单/风险/审批） | 新 @Tool 加 `@ToolMeta(riskLevel=READ_ONLY, requiresApproval=false)`——自动进白名单校验与执行记录 |
| `ToolExecutionRecord` / `SagaCompensationManager` | 只读动作无补偿；V1.3 写动作加 `@ToolMeta(compensationAction)` 走既有补偿链 |
| `ActionAllowlist`（白名单表） | 新增 `queryPodStatus` 条目（`READ_ONLY_DIAGNOSTIC` 分类，`sys_action_allowlist` 已有表结构） |
| 审计 | 执行记录自动落 `sys_agent_tool_execution` + `sys_operation_audit`——演示剧本 v2 的「审计留痕」即此 |

## 五、双轨验证（59 号报告 §三.2 落地）

| 轨道 | 环境 | 方式 | 验证内容 |
|------|------|------|---------|
| A 开发/CI | 沙箱/CI | fabric8 `FakeK8sClient` 注入适配器 | 治理全链路（策略→白名单→风险→执行→记录→审计）单测+集成测试，**不依赖真实集群** |
| B 演示 | 本机 | kind 单节点 + 真实 kubeconfig | 演示剧本 v2：真实告警 → AI 诊断 → `queryPodStatus` → 审计留痕 |
| 兜底 | 任意 | 适配器接口 mock | 接口契约不变，选型错误只影响一个实现类 |

## 六、验收标准（V1.2 Exit Criteria）

1. `queryPodStatus` 经 `OpsExecutor` 接口执行成功，返回结构化 Pod 状态（phase/restartCount/age）；
2. 治理链路被第二个场景验证：白名单校验 → 执行记录 → 审计留痕全通；
3. `OpsExecutorRegistry` 可注册/解析多目标系统，未注册系统报明确错误；
4. CI 全绿（FakeK8sClient 路径）；本机 kind 演示视频可复现；
5. 未配置集群时系统不崩溃，动作返回「未配置目标系统」明确提示。

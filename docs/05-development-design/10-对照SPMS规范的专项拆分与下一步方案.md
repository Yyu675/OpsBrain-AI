## 一、规范对照：OpsBrain 现在处在哪一档

按《资深前端编码前必读开发规范》0.3 分级，当前前端是 **「普通业务系统」偏中后台**：列表/详情/写操作已落库，但权限、统一请求、部分页面状态仍未达到中后台最低线。

| 规范要求 | OpsBrain 现状 | 判断 |
| :--- | :--- | :--- |
| 请求统一封装 | 多数接口直接 `fetch`，错误码/超时/401 处理分散 | 未达标 |
| loading / empty / error | 知识库、工单详情已有三态；Dashboard/部分空态仍是内联文字 | 部分达标 |
| 表单校验 + 防重复提交 | 工单/知识编辑有 dirty guard、提交锁；校验规则未抽到单一来源 | 部分达标 |
| 危险操作二次确认 | 删除/废弃/关闭多数已确认 | 达标 |
| 401 / 403 / 404 | 有 403/404 页；无真实登录，守卫空转 | 未达标 |
| 写操作落库 + 乐观回滚 | 工单/知识库主路径已落库 | 达标 |
| 枚举与后端一致 | 工单 5 态已对齐；Dashboard KPI 与设计稿字段不一致 | 部分达标 |
| 权限默认收紧 | `isAuthenticated=true`、`permissions=['*']` | 未达标（已知 L1 债务） |
| 页面不堆业务细节 | TicketList / TicketDetail / KnowledgeEditor 仍偏巨型 | 未达标 |
| 不伪造数据 | 浏览量/权限/Dashboard 图表已拒绝伪造 | 达标 |

**结论**：核心业务链路（知识 CRUD、工单 CRUD/回复/标签/附件、AI 对话 SSE）已是交付物，不是演示壳。缺口集中在 **工程底座**（请求层、权限、页面拆分）和 **未接线能力**（通知、Dashboard 图表、健康检查消费）。

## 二、从 SPMS 规范抽出、必须遵守的 8 条

后续专项一律按这些条执行，不再另起风格。

1. **先问五问再改接口**：必填、类型、枚举、错误码、权限。冲突以后端 DTO/Controller 为准（《数据契约》§1–2）。
2. **前端校验通过的数据，后端必须也能过**。长度、trim、枚举共用同一份常量（《数据契约》§3）。
3. **页面至少四态**：loading / empty / error / 无权限。失败要给下一步（重试或返回），不能只写「暂无数据」（《兜底》§0.2、§1）。
4. **单个组件失败不能拖垮整页**。已有 `AppErrorBoundary`；详情内 AI 面板继续用 `PanelErrorBoundary`（《兜底》§1）。
5. **视图层不直接散写 URL、不弹业务错误以外的 axios 细节**。新接口进 `api/`，错误码在 service 映射（《架构》§1）。
6. **抽公共抽在「变化会同步」处**。状态徽标、分页、筛选栏、空态再抽；不要为抽而抽（《架构》§0、§9）。
7. **一次专项只做一件事**，改完汇报。禁止顺手重构无关页（《AI 协作》§1 阶段④）。
8. **高风险操作（删除、发布、作废、上传）必须确认 + 防重复 + 失败可恢复**。已有路径保持，新路径照抄。

## 三、专项任务拆分（按风险与收益排序）

每项都可独立开一轮，做完停下来验收，不和下一项绑死。

### S0 — 工程底座（先做，后面都依赖它）

| ID | 专项 | 要改什么 | 不做 | 验收 |
| :--- | :--- | :--- | :--- | :--- |
| S0-1 | 统一 HTTP 客户端 | 新建 `utils/http.ts`：超时、JSON、业务码 `code!==0` 抛错、40009/40004/40021 映射；工单/知识/看板逐步迁过去 | 不一次改完所有 `fetch`；不引入 axios | 至少知识文档 + 工单列表走新客户端；失败有统一文案 |
| S0-2 | 页面状态组件收敛 | TicketList 空/错态改用 `EmptyState`；Dashboard 空数据同此 | 不改业务数据逻辑 | 列表失败可重试，空态文案区分「无数据 / 筛选无命中」 |
| S0-3 | 枚举与标签单一来源 | 工单状态/优先级/void 样式抽到 `constants/ticket.ts`；列表与详情共用 | 不改后端枚举 | 再补状态不会漏样式 |

### S1 — 工单闭环（业务价值最高）

| ID | 专项 | 要改什么 | 不做 | 验收 |

## 四、建议执行顺序（2–3 周量级）

```
本周    S0-1 统一 HTTP（先迁工单列表 + 知识列表）
        S1-1 回归附件 / 沉淀 / void（手工点一遍）
        S2-1 全库总数
下周    S3-1 Dashboard 真 KPI + 预览图标注
        S1-4 CSV 导出（若后端暂无导出端点：前端按筛选拉全量，上限 2000 并提示）
        S4-1 会话过期页
再下周  S3-3 通知接告警 WS
        S0-2 / S2-2 / S2-3 体验小项
        S5 仅在页面继续膨胀时启动
```

**明确后置、本阶段不做：**

- 完整登录鉴权（要后端 session/JWT，属于 L2/P2）
- Dashboard 工单趋势/分类/AI 效率真实时序接口（后端没有就保持「预览数据」）
- 语雀式独立布局、md-editor 行内 + 号
- 浏览量 / 权限字段伪造

## 五、每一轮开工前的固定问法（摘自规范）

编码前先写清这 6 句，再改文件：

1. 这个专项解决什么业务问题？
2. 哪些字段不能错？
3. 页面四态怎么表现？
4. 哪些操作要确认 / 防重 / 回滚？
5. 接口失败、刷新、重复点击怎么办？
6. 本轮属于哪一档规范（可简化什么、必须守什么）？

做完用这一条验收：**正常路径能跑不算完成；空、错、刷新、重复提交都要可恢复。**

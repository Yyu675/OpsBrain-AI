## 二、P0 残留问题（必须修复）

### P0-1：tickets 版本冲突恢复清空详情页回复/活动流

**位置**：`stores/tickets.ts` L488-L511

**问题**：冲突后 `refreshTickets()` + `Object.assign(existing, refreshed)`，但 `convertBackendTicketToFrontend` 把 replies/activities/attachments 恒写 `[]`，详情页时间线被静默抹掉。

**方案**：合并时保留已加载的 replies/activities/attachments：

```typescript
if (existing) {
  const savedReplies = existing.replies
  const savedActivities = existing.activities
  const savedAttachments = existing.attachments
  Object.assign(existing, refreshed)
  existing.replies = savedReplies
  existing.activities = savedActivities
  existing.attachments = savedAttachments
}
```

### P0-2：knowledge updateDoc 成功后无条件 loadDetail 覆盖切走的文档

**位置**：`stores/knowledge.ts` L219-L227

**问题**：保存 A 时切到 B，A 保存成功后 `loadDetail(A)` 会覆盖 B 的详情。

**方案**：保存成功后原地 merge `saved`，不调 `loadDetail`：

```typescript
const updateDoc = async (id, req, version) => {
  const saved = await updateKnowledgeDoc(id, { ...req, version })
  // 只在当前详情就是这篇文档时原地合并
  if (detail.value?.id === id) {
    detail.value = { ...detail.value, ...saved }
  }
  await refreshList()
  return saved
}
```

### P0-3：dto-converter urgent 优先级往返丢失

**位置**：`dto-converter.ts` L45-L64

**问题**：`urgent → HIGH`，回来 `HIGH → high`，紧急工单保存后变高。

**方案**：后端无 URGENT 枚举，前端 `HIGH` 读回时无法区分原值。改为读回时保留后端原值不映射——让前端选择使用后端原始 `priority` 字段而非转换后的。或后端加 URGENT。

### P0-4：TicketDetail AIContextPanel 仍未接入

**位置**：`TicketDetail.vue` L218-219, L480-518

**问题**：`aiGenerateReply` 只 toast；右栏 AI 智能分析仍是静态预览卡。

**方案**：在右栏 `side-card-ai` 位置替换为 `<AIContextPanel>`，接 `draft-reply` 事件。

### P0-5：restoreTicket 丢 tags/status

**位置**：`stores/tickets.ts` L579-L590

**问题**：Undo 恢复的工单丢失标签和状态。

**方案**：恢复时回传 `tags` 和 `status`。

### P0-6：chat 跨标签页同步打断流式会话

**位置**：`stores/chat.ts` L130-L136

**问题**：另一标签写入后 `buckets.value = latest`，当前流式消息被换掉，token 丢失。

**方案**：流式期间忽略 `onPersistedChange`，或按 sessionId 合并跳过正在写的那条。

## 四、各页面核心优化方案

### 4.1 首页（Home.vue）

**当前状态**：营销落地页定位，统计条已接真实 API。

**核心建议**：从营销页转型为运维工作台入口。

**方案**：
1. 删除 Hero 卖点 / 营销文案 / 「免费试用」CTA
2. 统计栏改为工单 KPI（待处理/处理中/已解决/紧急）+ 平台统计（查询数/缓存命中/成本）
3. 功能卡片改为可点击的快捷操作入口（创建工单/浏览知识库/AI 助手）
4. 新增最近工单（5 条）+ 最近告警（3 条）列表
5. 加载改为 `http.ts` + AbortController

### 4.2 数据概览（Dashboard.vue）

**当前状态**：已删死代码、加刷新按钮、kpis 改 computed。

**核心建议**：补真实图表 + onActivated 刷新。

**方案**：
1. 引入 ECharts 折线图替代静态成本趋势列表
2. 引入 ECharts 饼图替代静态模型分布
3. 加 `onActivated`（keep-alive 回来时刷新）
4. 删除页脚重复 KPI
5. 统一 CSS 变量替代硬编码色值

### 4.3 知识库列表（KnowledgeBase.vue）

**当前状态**：已做 URL 同步、删冗余请求。

**核心建议**：补加载态 + 统一时间格式 + onActivated。

**方案**：

3. 加 `onActivated` 刷新 categories/hotTags
4. 「全部文档」只取消分类筛选，不清搜索词

### 4.4 知识库详情（KnowledgeDetail.vue）

**当前状态**：已接 safeMarkdown、展示 indexError。

**核心建议**：修全局选择器 + 统一时间格式。

**方案**：
1. `document.querySelector('.article-content')` 改用 `ref`
2. `fmtDateTime` 改用 `RelativeTime` 或基于 `Date` 的解析
3. `loadVersions`/`loadCompare` 加请求序号
4. 版本历史补全 CHANGE_TYPE 标签
5. 代码块加一键复制按钮

### 4.5 知识库编辑（KnowledgeEditor.vue）

**当前状态**：已加导入 sanitize + 文件大小限制 + 状态点修正。

**核心建议**：编辑器懒加载 + 离开保护统一。

**方案**：
1. `md-editor-v3` 改为 `defineAsyncComponent`
2. `publishOnChange` setter 移除 `isDirty = true`（切换开关不是内容修改）
3. 离开保护统一到 `useDirtyGuard`，`handleBack` 调用 `confirmLeave()`
4. 大纲解析防抖从 500ms 改 1000ms

### 4.6 工单列表（TicketList.vue）

**当前状态**：已补图标导入、加请求序号、三态完善。

**核心建议**：实现高级筛选面板 + 卡片视图 + URL 同步。

**方案**：
1. `advancedOpen` 为 true 时展开面板（服务/分类/负责人/标签/日期范围）
2. 实现卡片网格布局（工单号/标题/优先级/状态/SLA 进度条/标签/时间）
3. `router?.push` 去掉多余 `?.`
4. `selectedIds` 改用 `Set` 替代 `includes`
5. 删除冗余 `loadHotTags` 调用（模板不读取）
6. URL 同步（和知识库一样）

### 4.7 工单详情（TicketDetail.vue）

**当前状态**：已修 watch id/渲染描述/转派弹窗/终态回复守卫/删假 AI 事件。

**核心建议**：接入 AIContextPanel + 补标签/附件/状态操作。

**方案**：
1. 右栏 `side-card-ai` 替换为 `<AIContextPanel>`，接 `draft-reply` 事件填入回复框
2. 属性卡加标签 chips（展示 + 删除 + 添加 + 热门建议）
3. 左栏底部加附件区域（上传/列表/下载/删除）
4. 操作按钮补「标记处理中」(updateStatus processing)
5. 发送按钮加 `:disabled="submitting"` + loading 样式
6. 回复列表 `v-for` 用 `reply.time + reply.author` 组合 key 替代 index
7. 活动流加空态
8. 面包屑显示标题（截断 30 字符）
9. `goBack` 改为 `router.back()`（保留来源页状态）

### 4.8 AI 助手中心（AICopilotHub + 子组件）

**当前状态**：已挂载到 App.vue + FAB、v-show 保活、ChatMode 卸载 abort。

**核心建议**：修复 SuggestionMode 加载数据 + AlertStream upsert + safeMarkdown 缓存。

**方案**：
1. `SuggestionMode` 在 Hub 打开时调 `store.loadStats()`，不依赖缓存
2. `AlertStreamMode` 同 `alert.id` 按 upsert 合并（不 unshift 3 张卡）
3. `ChatMode` 调用 `safeMarkdown(text, msg.id + ':' + msg.content.length)` 传 cacheKey
4. `AIContextPanel` 替换内联 DOMPurify 为 `safeMarkdown`（消除重复实现）
5. Hub `before-close` 按 EP 契约改 `(done) => { ...; done() }`
6. ChatMode 加「用户上翻则停止自动滚」逻辑

### 4.9 基础设施

**核心建议**：修复 safeMarkdown 缓存 + 接上 http.ts + 清理死代码。

**方案**：
1. `safeMarkdown` 统一走 `marked.parse` 不区分 Markdown/HTML
2. `safeMarkdown` 加 try/catch 降级返回转义纯文本
3. `ChatMode` 传 `cacheKey` 给 `safeMarkdown`
4. `http.ts` 让业务 API 层真正使用它（或至少让新代码用它）
5. `app.signOut` 持久化 `isAuthenticated: false`
6. 删除 `nextTicketId` 死代码
7. `dto-converter` 补 `用户服务 ↔ OTHER` 往返修复

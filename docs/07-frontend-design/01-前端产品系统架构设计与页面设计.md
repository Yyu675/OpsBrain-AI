### 1.4 状态管理设计

| Store | 职责 | 持久化 | 核心状态 |
| :--- | :--- | :--- | :--- |
| `app` | 用户身份、设置、认证 | localStorage | `isAuthenticated`, `currentUser`, `settings` |
| `chat` | AI 对话会话（多会话桶） | localStorage | `buckets`（按 ticketId 隔离），`isStreaming`, `activeTicketKey` |
| `knowledge` | 知识文档列表/详情/版本 | 不持久化 | `list`, `detail`, `categories`, `hotTags`, `compareResult` |
| `tickets` | 工单列表/详情/统计/标签 | 不持久化 | `tickets`, `total`, `stats`, `hotTags`, `lastQuery` |
| `notifications` | 通知列表 | localStorage | `items`, `unreadCount` |

**设计原则**：
- 服务端分页数据不持久化（6.18 契约：缓存切片无意义且有害）
- 跨标签页不广播带上下文的数据（6.18 契约）
- 写操作必须落库，纯内存修改仅限 AI 建单回显（6.9 契约）
- 乐观更新必须可回滚（6.9 契约）

**路由守卫**：
- `requiresAuth`：检查 `app.isAuthenticated`
- `roles`：检查 `app.hasRole(meta.roles)`
- `permissions`：检查 `app.hasPermission(meta.permissions)`
- `stage`：标注自治等级，用于未来按阶段开放
- `hiddenFromNavigation`：不进入主导航但路由可访问

**懒加载策略**：
- 所有页面组件使用 `defineAsyncComponent` + 重试（2 次，300ms 退避）
- 加载中显示骨架屏（`AppSkeleton`，区分 list/detail/dashboard 三种变体）
- 加载失败显示 `NotFound` 组件
- 导航栏 hover 150ms 后预加载目标页面

### 1.7 全局交互模式设计

| 模式 | 实现 | 说明 |
| :--- | :--- | :--- |
| 骨架屏 | `AppSkeleton` 3 变体 | 路由懒加载 + 列表/详情/看板三种布局 |

| 快捷键 | `useHotkeys` + `HotkeysDialog` | 全局快捷键支持 |

### 4.3 三态加载规范

所有异步数据页面必须实现三态（6.18 契约）：

```vue
<!-- 加载中 -->
<div v-if="loading" class="loading-state">
  <el-icon class="is-loading"><Loading /></el-icon>
  <p>加载中...</p>
</div>

<!-- 加载失败 -->
<div v-else-if="loadError" class="error-state">
  <el-icon color="#f56c6c"><Warning /></el-icon>
  <p>加载失败</p>
  <el-button type="primary" @click="retry">重试</el-button>
</div>

<!-- 正常 -->
<template v-else-if="data">
  <!-- 内容 -->
</template>

<!-- 未找到（详情页） -->
<div v-else class="not-found-state">
  <p>未找到</p>
  <el-button @click="goBack">返回列表</el-button>
</div>
```

## 六、前端开发契约摘要

### 6.1 必须遵守的铁律

| # | 契约 | 来源 | 说明 |
| :---: | :--- | :--- | :--- |
| 1 | 前端不再使用 mock 数据 | 三章铁律 | 所有数据从后端 API 获取 |
| 2 | 写操作必须落库 | 6.9 | 纯内存修改仅限 AI 建单回显 |
| 3 | 乐观更新必须可回滚 | 6.9 | 失败时恢复快照 |
| 4 | 部分成功如实上报 | 6.9 | 批量操作返回成功数 |
| 5 | 列表筛选必须走后端 | 6.15 | 前端本地过滤只能作用于当前页 |
| 6 | total 必须与筛选条件一致 | 6.15 | findPage 与 countByQuery 共用 WHERE |
| 7 | 派生字段在后端算 | 6.15 | SLA 进度、文件大小等 |
| 8 | 服务端分页数据不得持久化 | 6.18 | 缓存切片有害 |
| 9 | 跨标签页不广播带上下文数据 | 6.18 | 各页筛选独立 |
| 10 | 异步加载空状态排除 loading | 6.18 | 避免首帧闪现「未找到」 |
| 11 | 不存在与加载失败分开展示 | 6.18 | 用户下一步动作不同 |
| 12 | 凡自增 version 的操作前端要同步 | 6.16 | 漏同步会导致误报冲突 |
| 13 | 写操作响应派生字段全部采用 | 6.16 | version/tags/slaProgress |
| 14 | 通用组件不得自行刷新调用方数据 | 6.17 | 只发事件，刷新由使用方决定 |
| 15 | 刷新必须沿用当前查询条件 | 6.17 | 无参刷新等于静默清空筛选 |
| 16 | 附属数据写入失败不回滚主体但必须记 ERROR | 6.19 | 静默丢失比失败更糟 |
| 17 | 前端须比对提交值与响应值 | 6.19 | 后端不抛异常时的发现途径 |
| 18 | 前端不得凭其他字段派生展示数据 | 6.13 | 派生属于编造 |
| 19 | 结构化输出优先于纯文本 | 6.32 | 原因/命令/置信度骨架 |
| 20 | 格式漂移必须降级而非报错 | 6.32 | 降级为全量 markdown |
| 21 | 安全异常消息分层 | 6.29 | getUserMessage() 面向前端 |
| 22 | 退出登录必须清登录态 | 6.26 | 调 app.signOut() |
| 23 | 配置项必须有代码读取 | 6.20 | 无读取的配置比没有更糟 |
| 24 | 同一事实只允许一处定义 | 6.20 | 维度/阈值等不可散落多处 |

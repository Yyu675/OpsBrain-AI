## 二、建议 3：鉴权配置开关（本轮重点）

### 为什么光"改回来"不够

上一轮修掉了一处真实事故：有人为 UI 预览把 `WebConfig` 里的
登录拦截器**整段注释掉**并提交。

但只把它恢复，等于假设"下次没人会再这么做"。
**而下次仍然需要免登录预览时，人会再做一次同样的事**——
因为当时没有别的路可走。

必须提供一条正确的路，否则这个修复只是一次性的。

### 改法

`devops.security.auth-enabled`，默认 `true`：

```bash
AUTH_ENABLED=false ./mvnw spring-boot:run   # 本地免登录预览
```

相比注释代码的四点改进：

| | 注释代码 | 配置开关 |
|---|---|---|
| 生产默认 | 取决于有没有人记得恢复 | **默认安全** |
| 可审计性 | 藏在注释里，review 不显眼 | 写在 yml 里 |
| 关闭时的信号 | 无 | 启动打醒目 ERROR |
| 集成测试 | 一并失效 | 仍走真实鉴权链 |

### 一个刻意的顺序安排

开关的 `return` 放在**审计拦截器注册之后**。

关掉鉴权时审计**仍然生效**——这恰恰是最该留痕的时候。
若把 return 提到方法最前面，免登录期间的所有写操作都不会有任何记录。

### 为什么要补 AuthSwitchDefaultIntegrationTest

上次那个事故其实被 `GovernanceRoleGuardIntegrationTest` 抓到了
（403 变 200），但那是**侧面撞上**的：那批用例本意是验角色边界。

**如果当时恰好没有治理端点的用例，改动会一路合进生产。**

本类把它变成正面断言，不依赖任何业务语义：

1. 默认配置下 `auth-enabled` 解析为 true（有人改 yml 默认值立刻红）
2. 未登录访问受保护读端点 → 401
3. 未登录访问受保护**写**端点 → 401（历史上出现过只给读路径配拦截）
4. **白名单端点仍免登录** —— 反向验证

第 4 条容易被忽略但很重要：不能为了"更安全"把探针也拦了。
`/api/v1/health/**` 被拦会让 K8s 判定 Pod 永远 NotReady，
**那是把安全做成了可用性故障**。

### 为什么不测"关闭开关后放行"

那需要起一个 `auth-enabled=false` 的独立上下文。
它验证的是"不安全配置确实不安全"——没有防护价值，
却会在测试套件里留下一个**鉴权全关**的 Spring 上下文
（按配置缓存复用），反而制造隐患。

**安全类测试只钉安全的那一侧。**

### 一处我自己的错

初版断言 `/api/v1/health/live`，实际 `HealthCheckController` 只有
`""` / `/ping` / `/db` 三个映射。提交前核对源码改为 `/ping`。

不核对就提交的话，这条会以「404 != 200」失败，
而原因与被测逻辑无关——又是一次"测试报错但错在测试"。

## 五、转而做了：执行器契约测试

两条建议受阻后，我没有硬做，而是找了**当前环境能做且有价值**的：

`OpsCommand` / `OpsExecutionResult` 是 D1 适配器模式的**公共词汇**，
K8s / 云厂商 API / 内部脚本平台三类目标系统都要通过它们与治理链路交互。

现在只有一个适配器，这些约定**只存在于一处实现的行为里，没被固定**。
第二个适配器接入时，写它的人会照自己的理解再实现一遍——
两边不一致，而治理层是按统一契约写的。

### 最值得说的一条

**失败结果的 `data` 必须非 null。**

调用方普遍写 `result.data().get("phase")`。若失败时 data 为 null，
每个消费点都要额外判空——漏一处就是 NPE，
而且**只在故障路径触发**：平时测不出来，真出问题时雪上加霜
（本来只是「K8s 查询失败」，变成整个 Agent 抛异常）。

### 其余动机

- **字段不串位**：record 声明顺序 `(action, params, targetSystem)`
  与工厂签名 `of(targetSystem, action, params)` **不同**，最容易写反
- **异常带动作名与目标系统**：这条异常会冒到 AI 的工具调用结果里。
  只说「缺少参数」，模型没法自我纠正，运维也定位不到是哪个适配器
- **空串按缺失处理**：放行的话 K8s 会拿 `""` 当命名空间去查，
  错误来自集群而非本地校验，排查链路拉长一层

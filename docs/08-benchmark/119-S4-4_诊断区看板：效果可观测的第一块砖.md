> 报告性质：路线图 §8.4（S4-4 效果看板）批次 16。

> 与 `sys_diagnosis_evidence` 两张 V3/V4 存量表从「落库即沉」变成「开窗可见」。

## 二、口径决策（每条都写进了代码注释，防回辩）

1. **`successRate = SUCCESS / total`，NO_DATA 计入分母不豁免。**
   「源健康但服务没事可报」和「取到了数据」本来就是两回事；把 NO_DATA
   从分母豁免会让一条从来没取到数的链路看起来 100% 健康。
2. **`attentionTypes` 只点名 FAILED / UNAVAILABLE > 0 的方向。**
   数据源失败率可见是验收点；NO_DATA 点名会制造假警——这是本最有价值、
   也最容易写反的一条。
3. **窗内无完成会话 → `avgDurationSeconds = null`，前端显示 `—`。**
   Dashboard 这一页的祖传纪律：null 与 0 必须区分（没有数据 ≠ 数据为零）。
4. **未知状态值计入方向 total 但不进四态桶。**
   将来新增 evidence 状态不会被合并面静默吞掉，同时不破坏既有四态口径。
5. **sufficiency 只来自 COMPLETED 会话（SQL 过滤）**，合并面原样透传，
   不发明第二层分类。

## 四、边界与欠账

- **集成测试不新加**：`/diagnosis-board` 走与 `/overview`、`/trends` 完全同构的
  `JdbcTemplate + @Transactional` 既有集成闸，单点夹紧与 AVG null 语义已由
  Composer 钉测覆盖；重复搭一条同构集成测试是负资产（见报告 117 §三「测试
  预算花在哪」的同一条纪律）。
- **LLM 层指标不进本板**：诊断区是「系统自己看病」的观测面；LLM 评测层的
  Recall/MRR/幻觉率归 S4-2 校准与 S4-3 基线对比的既有弹药面，两账分离。
- **趋势化欠账**：本质看板每值一窗口；多日趋势（诊断量按日分布）排入
  S4-4.3，需要 `sys_diagnosis_session.created_at` 日布聚合，SQL 侧零障碍，留
  下批。
- 看板数据面当前**无历史回填**：V3/V4 表上线不满一个窗口时数字天然稀疏，
  这是语义真相不是缺陷；空态文案已显式区分「窗口内暂无取证记录」。

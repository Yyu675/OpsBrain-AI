# 120 S4-4.3 诊断量逐日趋势：窗口的第二根轴

> 报告性质：路线图 §8.4（S4-4 效果看板）批次 17，接续批次 16（报告 119）。
> 批次 16 给诊断区开了窗（会话/方向看点），本批加第二根轴——**时间**：
> 逐日诊断量趋势（发起柱 + 完成折线），共享同一 `days` 窗口参数，不加查询面。

---

## 一、切片与落法

| # | 层 | 落法 |
|---|---|---|
| SQL | `DashboardServiceImpl#getDiagnosisBoard` 内增一条 | `GROUP BY DATE(created_at)` + `COUNT(*) FILTER (WHERE status='COMPLETED')`，窗口参数与 `getCallTrends` 同款 `CURRENT_DATE - CAST(? AS INTEGER)`（days-1）。SQL 只取有数的行 |
| 合并面 | `DiagnosisBoardComposer.buildTrend` | 补零与越窗丢弃属日历语义，全部下沉纯函数；`today` 由参数注入（本类不读时钟，断言永不漂移），序列长度恒等于窗口 |
| 载荷 | `sessionTrend: { days[], created[], completed[] }` | 三个等长对齐数组，与 `getTrends` 载荷同构（前端一把梭接图） |
| 前端 | B6 诊断区内嵌 `TrendChart` | 柱=当日发起（`#409eff`），折=当日完成（`#67c23a`），MM-dd 标签与 B2 趋势同款；`days` 空（老后端降级）整块收起 |

## 二、口径决策（与既有纪律对齐，不发明第二套）

1. **固定周期趋势必须补零——与 `getCallTrends` javadoc 同一条纪律的第二次执行。**
   没有诊断发起的日子画 0 点而不让折线跨坑跳接：跳接的线会把
   「系统闲」误读成「中间数据丢了」。趋势图的错误从不是报错，是误读。
2. **越窗行直接丢弃。** 序列长度恒等于窗口天数，秩序由左右端点定，
   不认行自带的日期范围——上一窗口的数据哪怕行递进来也不能污染本窗。
3. **Composer 不读时钟。** `today` 注入的唯一理由是让日历语义可钉测；
   与批次 15「计算面常驻 CI、语义可钉」的分层同宗。
4. **完成线 ≠ 发起线。** 同日发起与完成分离画（柱/折），REJECTED/ERROR
   计入发起不计入完成——两条线的剪刀差就是「积压率」的自解释形状，
   不必再发明第三个指标。

## 四、边界与欠账

- **SQL 层行不对齐天不补**（有数才出组），补零纯在合并面——`sys_diagnosis_session`
  无日期序列小抄表，Join `generate_series` 属于把日历搬进 SQL，拒绝。
- **方向级趋势（某方向逐日成功率）欠账**：会话级·方向级分层清晰，但方向
  趋势读的是 `sys_diagnosis_evidence.collected_at` 的逐日 GROUP BY，等报表
  放量（欠账池既有借条：等放量）再上，防止给两周试用期的数据量配望远镜。
- 阶段 4 剩余：S4-2 校准（EVAL_LLM 窗口）→ S4-3 CI 触点挂线（workflows 权限）。
  诊断区至此看点/看链/看时三轴齐，S4-4 大图只剩「给更久的时间」。

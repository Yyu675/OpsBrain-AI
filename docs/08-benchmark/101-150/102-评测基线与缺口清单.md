## 三、关键教训：本论差点记下一个假基线（过程全录）

1. **捕获轮一**（34115435905，临时去门控+阈值 100%）：注解约 250 字节截断，完整报告穿不出来——教训：注解通道必须把**关键数字放消息第一行**。
2. **捕获轮二**（34115837596，数字置顶+三桶统计）：测得命中率 56%（28/50），未命中 18 条——但是 `ragCoverageEvaluation` 本体 **ERROR 了**（运行时异常「向量化失败」）。追查：「向量化失败」是文档生命周期 `INDEX_FAILED` 的标签——**S0-3 的 llm 限流（30/s · 零等待）把顺序批量摄取的突发拒绝了**。那 18 条「未命中」不是知识库缺口，而是嵌入调用被限流拒绝、被检索层按既有契约吞为 null 信号后的**假缺口**。
3. **校正**（S0-3 决策修订）：llm 限流改为**配速模式**（60/s + 10s 等待上限消化突发、超限仍拒绝）。批量负载要配速不要拒绝；交互单发嵌入的典型等待感知 <1s；10s 是失控任务的最后防线。
4. **捕获轮三**（34116296014）：连通性 100%（50/50）、未命中 0——验证了修复，也钉死了 MOCK 口径的真实语义：在 minScore=0 下命中率恒为 100%，它的正确用途是**管道连通性回电线**（有数据却返回空 → 红），语义覆盖率在 MOCK 下无从谈起。
5. **最终定版**：`ragCoverageEvaluation` 恢复 `EVAL_RAG` 门控，断言语义改为连通性 100% 红线（它本轮已经证明会抓真缺陷——限流缺陷就是它抓的），文档注释写明口径。

> 评测设计的元教训：**判据与度量模型必须同口径**。0.73 相似度门槛是为真实嵌入设计的，拿 MOCK 向量去比是无效测量；本次把三层评测各自的「可度量性边界」显式写进了代码与报告，后续误读率应为零。

## 五、收尾挂账（恢复条件：GitHub App 获 workflows 权限 / 用户手工应用）

`.github/workflows/ci.yml` 追加（与 S0-1 挂账的 flyway validate 步骤同批处理最佳）：

```yaml
  eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
      - name: RAG 覆盖评测（Testcontainers pgvector，无需外部服务）
        env:
          EVAL_RAG: 'true'
        run: ./mvnw -B -ntp test -Dtest=AgentEvaluationTest
      - name: 上传评测报告
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: eval-report
          path: target/eval-report.md

  eval-llm:
    runs-on: ubuntu-latest
    if: github.event_name == 'workflow_dispatch'
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
      - name: LLM 端到端评测（真实 Key，仅手动触发）
        env:
          EVAL_LLM: 'true'
          ALIBABA_API_KEY: ${{ secrets.ALIBABA_API_KEY }}
          SPRING_PROFILES_ACTIVE: dev
        run: ./mvnw -B -ntp test -Dtest=AgentEvaluationTest#llmEndToEndEvaluation
```

> 注：eval job 无需 postgres/redis service——全部依赖由 Testcontainers 提供（0-4.2 的设计收益）。
> 另一个前置：`secrets.ALIBABA_API_KEY` 需用户在仓库设置中配置（否则手动 job 也是 MOCK 空转）。

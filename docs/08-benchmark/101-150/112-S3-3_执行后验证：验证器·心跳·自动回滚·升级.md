## 二、一条关键的三态差分（UNKNOWN 的存在理由）

```
HEALTHY   → markVerified(PASS)          → 全剧终
UNKNOWN   → markVerified(UNKNOWN)       → 只留痕（验证不了≠失败，集群不可达不该升级）
UNHEALTHY → markVerified(FAIL)
            → 有 undo_token ? 自动 undo（转 UNDONE）→ P1 工单（人已回滚无需救火）
                            : 跳过              → P0 工单（系统还在病态，立刻接管）
```

「验证不了」谎报成 UNHEALTHY 会让值班员半夜被 P0 砸醒去救一个
其实没病的系统——狼来了三次之后真狼没人信。三态差分是报警质量的根基。

## 三、SKIPPED 的强制留痕

无匹配验证器的 SUCCEEDED 行必须写下 `verify_status=SKIPPED`：
否则一条未被验证的成功执行会在页面上与已验证的成功长得一模一样。
验证覆盖面的缺口本身也是审计事实。

## 四、双轨验证器

| 验证器 | 覆盖 | 行为 |
|---|---|---|
| MockActionVerifier | `mock.*` | 合成错误率改善曲线；探针 `simulateVerifyFail=true` 制造 UNHEALTHY——无真集群下演练「回滚+升级」全链的唯一通道 |
| K8sReadinessVerifier | `k8s.pod.restart` / `k8s.deploy.scale` | scale：readyReplicas 达 desired 即健康；restart：同应用标签下观测到 uid ≠ 快照的 Running 新 Pod；懒加载 client + resolveClient 测试接缝（与执行器基座同轨） |

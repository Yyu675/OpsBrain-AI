## 二、设计六决策（写死在类 javadoc，防回辩）

1. **只做构造与递交**：引擎不复刻治理门任一判定；重复门禁必然漂移成「策略说能做、门说不能做」的双真相源。
2. **requestedBy=auto**：复用 agent 审计旁写的既有谓词（`!"auto".equals(requestedBy)` 即写），策略来源走 params 溯源键而非 schema 新列。
3. **REJECTED 不计冷却/日上限**：演练与拒批不是「动过手」。
4. **stopOnMatch=acted 才停**：见 §一#6。
5. **异步池选型**：初稿裸 `Executors.newSingleThreadExecutor` 被 `ExecutorLifecycleContractTest` 架构门禁拦下——无界队列在告警风暴下等于无声 OOM。改 `ManagedExecutors.forBestEffort("healing-policy-engine", 1, 200)`：有界、满载丢弃+告警，与「告警链不可阻」铁律咬合（ DingTalkNotifier 同款先例）。
6. **模板只认三变量**：`${service}/${alertName}/${alertId}`。标签驱动的复杂模板先不做——超出动作面的取值能力是下一批的账。

## 三、测试矩阵（7 例，CI 已绿）

| 用例 | 断言核心 |
|---|---|
| 无策略 | orchestrator 与仓储双双零调用（引擎在场如不在场） |
| 不命中 | 四条件 AND 任一不符即跳过 |
| 演练留痕 | insert 行 `POLICY_DRYRUN/REJECTED`、alertId/target 正确、stepsJSON 含双节点；handle 零调用 |
| 真递交 | 模板就地展开（`hit order-service #42`）、数值型参数保型、`__policyId` 溯源、requestedBy=auto |
| 冷却跳过 | 宽策略冷却中 → 窄策略接手递交（stopOnMatch 不生效） |
| 日上限 | `countSince` 达上限 → 不递交 |
| stopOnMatch | 拿到单后后续策略连冷却查询都不发生（times(1)） |

> 修测试时自咬过一次：stopOnMatch 用例首策略 cooldownMinutes=0
> 根本不触发 lastExecutionAt，`times(1)` 必挂——给首策略补 1 分钟冷却才成立。
> 「断言的存在性也要被证明」在此应验。

## 五、工具账（本批新增，未来批次直接引用）

1. **本地 JDK 不可用**：沙箱对外 TLS 全封（Adoptium/Oracle/Corretto/清华/阿里/华为镜像同死）、无 root。
   编译验证只能走 CI annotations 通道——批次 6 的 `argThat` 与本批两轮修红证明该通道
   给符号级定位（行号+符号名），但**代价是每轮 10 分钟**。
   对策已内化：推前强制静态复核签名/导入/参数数（本批轮 1 就是复核漏网的代价）。
2. **git HEAD 重置事故**（本批开场发现）：本地 HEAD 被重置回 session 基线 `674429c`，
   工作树文件全部保留——`git status` 把全部已提交成果显示成「未跟踪/已修改」，
   极易误判成「大批旧账未交」。处置：`git fetch` → `git reset --mixed FETCH_HEAD`
   （工作树零触碰），重建后 status 归零。**判据入库：凡 status 显示海量未跟踪目录
   （如整个 domain/healing/）而你确定提交过，先 `git rev-parse HEAD` 对账远端再动手。**

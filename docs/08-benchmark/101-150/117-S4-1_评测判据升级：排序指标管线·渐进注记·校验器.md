## 二、为什么指标与数据源分层（记账防重演）

MOCK 嵌入向量跨文本近似正交，排名本身无语义（报告 102 §三定论）——
但「公式算得对不对」与「向量真不真」毫无关系。因此：
- **计算面**做成纯函数 + 8 例确定性钉测（常驻 CI，不依赖 pgvector/LLM）；
- **RAG 环境消费面**只负责把 docTitle 序列喂进去、按参与样本数出报告；
- 报告里 MOCK 排序小节自带 ⚠ 声明：数值只证「注记→检索→指标」管线接通，
  语义数值归 EVAL_LLM。**没有注记样本时整节留空**（拒伪造口径，S0-4 元教训延用）。

历史对应病案：「0.73 语义门槛测 MOCK 正交向量」与「56% 未命中假基线」——
都是把不可度量环境当成可度量环境。本批的分层就是这两张学费单的制度化。

## 三、两个决策（写死防回辩）

1. **docTitle 为判据键**：检索接口从 SQL 查的就是 doc_title/section_header
   （`RetrievedChunk`），docId 未暴露到消费面；为指标再开一出与 SQL 一致的
   id 口是扩接口面，而标题注记（=文件名）让注记者不用连库。
2. **渐进注记制**：expectedDocs 出现即必须完整（校验器把半成品
   视为错误），但不强制每条必带——全量注记是内容工作，
   在 MOCK 环境下盲注 65 条等于给「做对了」造数字，与假基线同源。

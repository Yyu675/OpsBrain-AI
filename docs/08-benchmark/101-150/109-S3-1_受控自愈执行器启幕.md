## 二、链路全景

```
触发（手工 POST /healing/executions 或 alertId 联动）
   │
   ├─ HealingGate 门裁决（唯一准入点）
   │     ① 执行器存在?  ② 白名单+风险策略（复用 AutomationGovernanceService.evaluate）
   │     ③ 破坏性权限硬提 DUAL  ④ 终审
   │     → AUTO_EXECUTE / REQUIRES_APPROVAL / DENIED / NO_EXECUTOR
   │
   ├─ dryRun 演算（不动真，输出即审批单的「将要发生什么」）
   │
   ├─ 三分支：
   │     AUTO_EXECUTE      → executor.execute → 一行终态（快照+undoToken 当场落行）
   │     REQUIRES_APPROVAL → ApprovalService.submit(HEALING) → PENDING_APPROVAL
   │                          → 审批中心批准 → ApprovalOrchestrator 分发 HEALING
   │                          → executeApproved：台账参数回放 → 重走 dryRun+execute
   │     DENIED/NO_EXECUTOR → 一行 REJECTED（拒绝也是审计事实）
   │
   └─ 撤销：undo(id) — SUCCEEDED + undo_token 双校验 → 快照回放
            → UNDONE / UNDO_FAILED（撤而不成绝不记成 UNDONE）
```

## 三、六条不容商量的设计立场

1. **执行器只答「能不能、怎么做」，「该不该做」永远归治理门**——执行器实现里不做第二次策略判断，权责单一。
2. **查无执行器 = 拒绝**，与白名单「未登记 = 拒绝」同一默认安全语义。
3. **破坏性执行器强制双人审批**，任何白名单配置都放松不了（测试：`gateDestructiveOverride`）。
4. **拒绝也落台账**——REJECTED 行的存在让审计能回答「当时为什么没动」。
5. **快照在执行当下采集，事后无从补拍**——V7 `pre_snapshot_json` / `undo_token` 从第一天就落库。
6. **撤销状态诚实**：UNDONE 与 UNDO_FAILED 是两回事，绝不用一个「已处理」糊弄。

## 四、双轨与 PRD D1 选型对齐

- Mock 执行器（`mock.*` 动作族）是离线基调的又一实例：治理链路全程可联调、CI 有稳定契约、演示不依赖真集群。
- 真实执行器按 PRD D1 落地顺序：**K8s fabric8 只读（V1.2，P4 只读演示）→ 安全自愈 →（远期）云 API / 脚本平台**，注册进 `ExecutorRegistry` 即生效，编排层零感知。
- 已注册执行器对管理面可见：`GET /api/v1/healing/executors`。

## 五、测试矩阵（11 例纯 JUnit，不依赖 Spring 容器）

| 层 | 用例 |
|---|---|
| 注册表路由 | mock.* 命中 / 未知动作 empty |
| Mock 执行器契约 | dryRun 标记、快照回声、undoToken 必须给出 |
| 治理门四裁决 | AUTO / 审批模式透传 / DENIED 原因可读 / NO_EXECUTOR 短路（不依赖白名单查询） |
| 门安全收紧 | DESTRUCTIVE 即使免审配置也硬提 DUAL |
| 编排 AUTO | 终态 SUCCEEDED + 快照当场落行 + 无审批单 |
| 编排审批路径 | 建单 + PENDING_APPROVAL，execute 永不被调用 |
| 编排拒绝路径 | REJECTED 留痕，执行器与审批流双双不触 |
| 批准续走 | 台账回放 → markFinished 全回填 + 审批单 recordExecution 回写 |
| 防重放 | 非 PENDING_APPROVAL 行 executeApproved 抛 IllegalState |
| 撤销三态 | UNDONE 成功 / 非成功态拒撤 / 无凭据拒撤 |
| 审批桥 | 按 approvalId 找到台账续走 |

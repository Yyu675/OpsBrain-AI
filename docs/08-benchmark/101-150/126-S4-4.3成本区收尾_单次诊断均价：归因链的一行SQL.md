## 一、归因链与口径（每条写进了代码注释防回辩）

| 决策 | 口径 | 理由 |
|---|---|---|
| 分子 | `SUM(sys_agent_call_log.cost_rmb)` JOIN `sys_diagnosis_session` ON `trace_id`（仅 COMPLETED 会话，窗口内） | trace_id 一对多天然聚合；COALESCE 防 NULL；审计表是唯一成本 SSoT |
| 分母 | **全部完成会话**（含零成本会话） | 与 avgDurationSeconds 同分母连贯；「有成本的会话均价」会把缓存命中这类高价值零成本事件挤出口径 |
| 空分母 | 无完成会话 → `null`（不编造 0） | Dashboard 页祖传纪律：null ≠ 0；「有成本、零完成」时成本仍在账上，只是均价无从谈起 |
| 精度 | 四位小数 | 与前端 KPI「平均成本(付费) ¥0.0123」同一显示口径，前后端同一份四舍五入 |

## 二、动静面

| 层 | 件 |
|---|---|
| SQL | Impl 增一条聚合查询（COALESCE SUM + JOIN ON trace_id + COMPLETED + 窗口） |
| 合并面 | Composer 第 11 参数 `diagnosisCostTotal`；分母从 statusRows 取 COMPLETED（未知状态进 total 不进本口径分母——「不静默消失也不污染既有口径」与四态桶同纪律） |
| 载荷 | `sessions.avgCostRmb: number \| null` |
| 前端 | B6 第五张 KPI 卡「单次均价 ¥x.xxxx」（null→—）；mapper 兜底 null |
| 后端测试 | 10 例签名随参升级 + 2 新例（0.3333 四位收口；有成本零完成→null 不硬挂零分母）合 12 例 |
| 前端测试 | smoke 断言并轨（`¥0.0123`)——不增量，进批 16 既有第一例（同一 KPI 卡行） |

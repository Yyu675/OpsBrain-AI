## 二、置信度公式（路线图 §6.2 原文逐项落地）

```
base = 0.5
+ 0.15 × (证据方向数 / 总方向数)
+ 0.15 × (高相关性证据占比)
- 0.10 × 冲突证据数
- 0.20 × (证据不足 = WEAK)
clamp 到 [0.1, 0.95]
```

附加钳制：WEAK 态任何计算结果硬帽 0.6（2-2.5「证据不足时置信度 ≤0.6」）。
INSUFFICIENT 态根本不产生假设——编排器在聚合阶段即终止推理。

满信号上限 0.80（公式基线固有上界），不是 0.95——这是设计而非缺陷：
规则公式本来就不该让机器自信到近满分，留给人工复核的缝隙是刻意的。

## 三、双轨生成器设计（为什么不用纯 LLM）

1. **规则基线永远可用**：LLM 停机/超时/越权时，诊断产出不退化为空。
   这是与本仓「Trust but Verify + 离线 MOCKER 兜底」基调同族的工程承诺。
2. **LLM 版后补可插拔**：实现同一 `HypothesisGenerator` 接口，失败回落规则版，
   编排器零感知——这正是「接口稳定线内硬化模型面」的路线图原则。
3. 规则基线的因果排序：强变更(rel≥0.6) → 指标异常面板 → 错误日志模式；
   NO_DATA/FAILED 不出假设（「没有」不是线索）；Top-3 硬上限；建议动作非空。

## 四、置信度与充分性的一张对应图

| 充分性 | 生成假设？ | 置信度上界 | 去向 |
|---|---|---|---|
| SUFFICIENT | 是（Top-3） | 0.95（公式实达 0.80） | 摘要 + 工单回填 |
| WEAK | 是（Top-3） | **0.6 硬帽** | 摘要标注「建议人工复核」 |
| INSUFFICIENT | **否** | —（终止） | 摘要「终止推理，转人工」+ 已取证附卷 |

## 七、本次发现的小知识

设计与落地的两个观察点：
① 生成器接口在规则/LLM 双轨间零摩擦切换——接口先于实现定型的好处在此兑现；
② `RankedEvidence`（落库 id ↔ Evidence）是领域对象与持久化键之间的最小桥，
把它作为生成器入参而不是内部查询，避免了「生成器偷偷再去查库」的隐性耦合。

## 五、是否需要继续深挖？分层回答

### 🔴 不建议现在做的：继续大规模找前端 bug

理由是**边际收益已明显下降**：

| 轮次 | 发现缺陷数 | 严重度 |
|---|---|---|
| 前 3 轮 | 6、4、5 | 多个 P0/P1 |
| 后 3 轮 | 3、3、3 | 以 P1/P2 为主 |
| 最近 1 轮 | 3（其中 2 个是自己上轮引入的） | P1 |

更关键的信号：**最近两轮发现的缺陷里，有一半是我自己前几轮新写代码引入的**。
这说明前端存量代码的"低垂果实"已基本摘完，继续同样的方式投入产出比在降低。

### 🔴 必须先做的：让后端跑通一次

**68 个后端文件从未编译过**，这是当前唯一的硬阻塞：

```
沙箱内: java: command not found
Maven:  全部镜像不可达（已试 8 个源）
CI:     .github/workflows 不存在，GitHub App 无 workflows 权限
```

这些改动包含权限过滤、事务边界、全局 Filter、`@Valid` 注解、
反射导出、`ClientIpResolver` 依赖注入——**全都是编译期能发现的问题类型**。

一次 `mvn verify` 的信息量，大于我再读 10 遍代码。

**你需要执行（30 秒）**：
```bash
git pull && mkdir -p .github/workflows
git mv ci/github-actions-ci.yml .github/workflows/ci.yml
git commit -m "ci: 启用工作流" && git push
```

### 🟠 CI 通过后，深挖的正确顺序

**1. 后端 Controller 契约测试（3-5 天，收益最高）**

16/17 Controller 零测试，而 Controller 是**前后端契约的落点**。
前端已有 790 个测试保护，后端接口一改就可能悄悄破坏它们。

优先级：`AuditLogController`（新写的）→ `KnowledgeDocController`
（权限域最复杂）→ `ApprovalController`（触发真实执行）→ `AuthController`。

用 `@WebMvcTest` + MockMvc，参照已有的 `TicketControllerWebTest`。

**2. 后端 Service 层测试（3-5 天）**

3/21 覆盖。重点是有事务边界的：`TicketService`（14 个事务）、
`KnowledgeDocService`（8 个）。**事务回滚路径是最难靠人工发现的缺陷类**——
异常时到底回滚了没有，不跑一遍根本不知道。

**3. 前端组件测试补齐（2-3 天）**

`TicketDetail.vue` 2655 行仍零测试。它是本会话发现缺陷最多的文件
（状态机漂移、时间戳错误、防重入缺失都在这里），却没有任何回归防线。

**4. 一次真实的端到端联调（1-2 天）**

本会话所有验证都是单元级 + dev server 路由探活。
**从未有过：真实后端 + 真实数据库 + 真实登录态的完整流程验证**。

使用日志页的两个新端点尤其需要——前端写完了，但没跑过一条真实数据。

## 七、诚实的风险提示

**1. 后端的"完成度"是纸面上的。**
30,056 行代码里有 68 个文件从未经过编译器检查。我做过的所有后端校验
（括号配平、Python 复刻逻辑、YAML 解析）都只能发现低级错误，
**发现不了类型不匹配、依赖注入失败、注解冲突这类问题**。

**2. 前端覆盖率数字偏乐观。**
66.7% 不含 `.vue` 文件，而视图层占了 38,586 行的大头。

**3. 本会话的修复本身也需要验证。**
22 个 fix 里有相当一部分改的是后端，同样未经编译。
我已在每个相关提交里标注了这一点，但需要你知道：
**这些修复目前是"有理由相信正确"，而非"已验证正确"**。

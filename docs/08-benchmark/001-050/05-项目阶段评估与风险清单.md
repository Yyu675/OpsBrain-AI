## 二、当前最大的风险（按严重度）

### 🔴 R1：2543 行后端代码从未编译过

这是**压倒性的头号风险**，其他都排在它后面。

**为什么严重**：这批代码不是边角料，包含
- 知识库权限过滤（写错 = 越权或全站检索挂掉）
- 事务边界（写错 = 数据不一致）
- 审计拦截器（写错 = 每个请求都受影响）
- traceId Filter（最高优先级过滤器，写错 = 全站 500）

**已做的替代验证**（这些都做了，但都不能替代编译）：
1. 结构校验：括号平衡、包名、类名、导入解析、无死引用
2. 依赖签名**对照上游真实源码**：LangChain4j `ChatMemoryStore` 三方法、Spring `SseEventBuilder.comment()`、`ResponseBodyEmitter` 的 ReentrantLock
3. 关键算法**移植为可运行程序**逐条验证：驱逐策略、traceId 规范化、配额语义、滑动窗口、权限矩阵、缓存分区、状态机自洽性
4. SQL 占位符与绑定参数逐一计数（发现过一次假阳性，是校验脚本把三元运算符的 `?` 算进去了）
5. Bean 装配与生命周期核查：确认 `TtlChatMemoryStore` 由 `@Bean` 返回，Spring 仍会处理其 `@PostConstruct`（否则清扫线程不启动，泄漏修复静默失效）

**我这一轮又试了 10+ 个源**（阿里/腾讯/华为镜像、Eclipse、JAIST、npm 的 `node-jre`）全部不可达。`node-jre` 是个 4.8KB 的下载器且只有 JRE 无 javac。**沙箱内编译已确定不可能。**

> **处置**：`git mv ci/github-actions-ci.yml .github/workflows/ci.yml` —— 30 秒，这是唯一出路。

---

### 🟠 R2：99 个端点、0 个 Controller 测试

API 契约完全没有回归保护。本会话改动触及多个 Controller（限流、审计、webhook 加固），任何一处签名或状态码变化都无从察觉。

**建议**：先覆盖 8 个核心端点（`chat/stream`、工单 CRUD、知识检索、登录、webhook），用 `@WebMvcTest` 断言状态码与响应结构。约 1 天。

---

### 🟠 R3：迁移漏执行会静默损坏功能（本轮已加防护）

**发现的隐患**：迁移靠人工按序执行、无 Flyway 版本表。若部署新 JAR 却漏跑 v24，检索 SQL 会引用不存在的 `visibility` 列 → 整个检索链路报错 → 而 `DevOpsTools` 把它呈现为「知识库暂不可用」，**排查者会去查向量库和模型，很难想到是少跑了一个 ALTER TABLE**。

**已修**：新增 `SchemaGuard`，`ApplicationReadyEvent` 时校验关键列/表：
- 默认只告警（开发环境常只跑部分迁移，拒绝启动会没法调试）
- 生产建议 `SCHEMA_FAIL_FAST=true`，让问题在部署时暴露而非用户点击时
- CI 已开启严格模式

**根治建议**：引入 Flyway（约 1 小时：加依赖 + 改文件名为 `V24__xxx.sql`），彻底消除这类问题。

---

### 🟡 R4：AI 对话链路的知识检索恒为「仅 PUBLIC」

这是 C1 权限改造的**已知局限**，不是 bug 但要知晓。

工具运行在模型 HTTP 回调线程，取不到 ThreadLocal 中的 scope。我选择**退化为最小权限而非放行**——两种失败代价不对称：放行则权限在最关键链路静默失效；收紧则最坏是 AI 答不出受限内容，用户会反馈。

**代价**：ADMIN 在对话里也查不到 RESTRICTED 文档。
**根治**：改为每请求构建 AiService 实例，或用 LangChain4j 工具上下文透传。约 2 天。

## 四、给一个诚实的整体判断

**这个项目的"深度"明显超出典型应届作品**：四层幻觉防护、Saga 补偿、语义缓存、父子切片、虚拟线程下的 ThreadLocal 处理、SSE 取消传播——这些细节很多三五年经验的工程师都不会主动做。代码注释里大量「P2-23 教训」「6.22 联调发现」这类记录，说明是真踩过坑。

**短板从来不是能力，是工程闭环**：
- 会话前：没有 CI、没有 Dockerfile、连 `mvnw` 都没提交（clone 下来跑不起来）
- 现在：这些都补上了，**但 CI 还没按下启动键**

所以当前状态可以概括为：**一台调校精密的发动机，仪表盘刚装好、油箱补好了、刹车也装了——但还没打过火。**

`git mv` 那一步，是这个项目从"看起来很完整"变成"确实能跑"的分界线。

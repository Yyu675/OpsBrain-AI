## 一、P1 级修复（7 项）

### P1-1. 回复提交进行中标记缺失

**现象**：
- `useTicketActions.submitReply()` 无进行中标记，双击会发两次请求
- 网络慢时用户以为没反应继续点，活动流多条重复记录

**修复**：
```typescript
// useTicketActions.ts
const submittingReply = ref(false)

const submitReply = async () => {
  if (!replyDraft.value.trim() || submittingReply.value) return
  submittingReply.value = true
  try {
    await store.appendReply(...)
    replyDraft.value = ''
  } finally {
    submittingReply.value = false
  }
}
```

**UI 同步**：
```vue
<!-- TicketDetail.vue -->
<el-button :disabled="!replyDraft.trim() || submittingReply" :loading="submittingReply">
  {{ submittingReply ? '发送中…' : '发送' }}
</el-button>
```

### P1-2. 状态变更进行中标记缺失

- `updateStatus()` 无守卫，双击触发两次状态机迁移
- `OPEN → IN_PROGRESS` 双发变成 `OPEN → IN_PROGRESS → RESOLVED`（误操作链）

**修复**：
```typescript
const updatingStatus = ref(false)

const updateStatus = async (newStatus: TicketStatus) => {

  updatingStatus.value = true
  try {
    await store.updateStatus(ticket.value.id, newStatus)
  } finally {
    updatingStatus.value = false
  }
}
```

**UI 同步**：下拉菜单项 `disabled` 属性统一绑定 `updatingStatus`。

### P1-4. 复盘生成进行中标记缺失

**现象**：
- `useTicketActions.generateRetrospective()` 无守卫，双击触发两次生成
- 第二次覆盖第一次，活动流多两条「AI 生成复盘」

**修复**：
```typescript
const generatingRetrospective = ref(false)

const generateRetrospective = async () => {
  if (!ticket.value || generatingRetrospective.value) return
  generatingRetrospective.value = true
  try {
    await ticketService.generateRetrospective(ticket.value.id)
    await store.fetchById(ticket.value.id) // 刷新拿最新复盘
    notify.success('复盘沉淀已生成')
  } catch (e: any) {
    notify.error(e.response?.data?.message || '生成复盘失败')
  } finally {
    generatingRetrospective.value = false
  }
}
```

**UI 同步**：`RetrospectiveDrawer.vue` 生成按钮 `:disabled="generatingRetrospective" :loading="generatingRetrospective"`。

### P1-6. 转派进行中标记缺失

**现象**：
- `doTransfer()` 无守卫，双击会发两次转派请求
- **读-改-写竞态**：第二次读到的还是旧负责人，把刚改好的又改回去
- 活动流多两条记录：「转派给李四」→「转派给张三」（实际是竞态导致的回滚）

**修复**：
```typescript
const transferring = ref(false)

const doTransfer = async () => {
  if (!ticket.value || !transferTarget.value || transferring.value) return
  
  const t = store.getById(ticket.value.id)
  if (!t || t.assignee === transferTarget.value) {
    transferDialogVisible.value = false
    return
  }

  transferring.value = true
  try {
    await store.transferTicket(ticket.value.id, transferTarget.value)
    notify.success(`已转派给 ${transferTarget.value}`)
    transferDialogVisible.value = false
  } catch {
    // 失败时保持弹窗打开
  } finally {
    transferring.value = false
  }
}
```

**UI 同步**：确认按钮 `:disabled="!transferTarget || transferring"` + 动态文本「转派中…」。

### P1-7. 错误提示不统一

**现状**：
- 有的地方 `ElMessage.error(e.message)`
- 有的地方 `ElMessage.error(e.response?.data?.message || '操作失败')`
- 有的地方直接 `throw e`（无任何提示）

**修复方案**：统一错误处理辅助函数

```typescript
// src/utils/error.ts (新建)
import { ElMessage } from 'element-plus'

export function handleApiError(e: any, fallbackMsg = '操作失败') {
  const msg = e.response?.data?.message || e.message || fallbackMsg
  ElMessage.error(msg)
}
```

**迁移示例**：
```typescript
// 旧代码
try {
  await store.updateStatus(...)
} catch (e: any) {
  ElMessage.error(e.response?.data?.message || '状态更新失败')
}

// 新代码
try {
  await store.updateStatus(...)
} catch (e) {
  handleApiError(e, '状态更新失败')
}
```

**说明**：本批次暂不大规模重写（风险控制），仅新增辅助函数 + 在 P1-4/P1-5 两处示范使用，后续批次渐进迁移。

## 一、P2 索引删减（4 条失实索引清理）

### 背景

批 82 索引收敛计划 P2 列出 4 条「表名或列名失实」的索引定义，需逐条校验真实表结构后决策保留/删除/改正。

### 执行

| # | 原索引定义 | 失实点 | 校验结果 | 决策 | 依据 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| **P2-1** | `idx_ticket_alert_group` ON devops_ticket(alert_id) | 表名 devops_ticket | 真表名 **sys_devops_ticket**；alert_id 列存在 | **删除** | 表名失实，现有 `idx_ticket_alert` 已覆盖单列 alert_id 索引 |
| **P2-2** | `idx_ticket_assignee_status` ON devops_ticket(assignee, status) | 表名 devops_ticket | 真表名 **sys_devops_ticket**；assignee 列存在 | **删除** | 表名失实，现有 `idx_ticket_assignee` 已覆盖 WHERE assignee 谓词（status 二次过滤当前无性能问题） |
| **P2-3** | `idx_diagnosis_alert` ON diagnosis_session(alert_id, status) | 表名 diagnosis_session | 真表名 **sys_diagnosis_session**；alert_id 列存在 | **删除** | 表名失实，现有 `idx_dsession_alert_running` 部分唯一索引已覆盖 alert_id 占位语义（WHERE status IN('RUNNING','QUEUED')）；Repository 无 findByAlertId 方法，查询路径不存在 |
| **P2-4** | `idx_ticket_assignee_time` ON devops_ticket(assigned_to, created_at DESC) | 表名+列名双重失实 | 真表名 **sys_devops_ticket**；真列名 **assignee**（非 assigned_to）+ **create_time**（非 created_at） | **删除** | 表名+列名双重失实，现有 `idx_ticket_assignee` 已覆盖 WHERE 谓词（ORDER BY create_time 若有性能问题再复合） |

### 实施

V1__baseline.sql 中四处索引定义改为注释说明删除原因：

```sql
-- P2-1: 告警关联工单索引（已有 idx_ticket_alert 覆盖，本索引删除）
--   原计划: WHERE alert_id=? GROUP BY alert_id
--   现状: 真表名 sys_devops_ticket（非 devops_ticket）；alert_id 列存在
--   既有覆盖: idx_ticket_alert (alert_id) 单列索引已覆盖 WHERE 谓词
--   决策: 删除本索引（表名失实 + 与既有索引完全冗余）

-- P2-2: 待办工单按负责人索引（已有 idx_ticket_assignee 覆盖，本索引删除）
--   原计划: WHERE assignee=? AND status IN(...)
--   现状: 真表名 sys_devops_ticket（非 devops_ticket）；真列名 assignee（正确）
--   既有覆盖: idx_ticket_assignee (assignee) 已覆盖 assignee 谓词
--   决策: 删除本索引（表名失实 + 与既有索引冗余；若需优化 status 二次过滤可复合但当前无性能问题）

-- P2-3: 诊断会话按告警索引（查询路径不存在，本索引删除）
--   原计划: WHERE alert_id=? AND status IN(...)
--   现状: 真表名 sys_diagnosis_session（非 diagnosis_session）；alert_id 列存在
--   既有覆盖: idx_dsession_alert_running 部分唯一索引已覆盖 alert_id 占位语义（WHERE status IN('RUNNING','QUEUED')）
--   查询方法: DiagnosisSessionRepository **无 findByAlertId 方法**——查询路径不存在
--   决策: 删除本索引（表名失实 + 实际无消费代码）

-- P2-4: 我的工单列表索引（已有 idx_ticket_assignee 覆盖，本索引删除）
--   原计划: WHERE assigned_to=? ORDER BY created_at DESC
--   现状: 真表名 sys_devops_ticket；真列名 assignee（非 assigned_to）；真列名 create_time（非 created_at）
--   既有覆盖: idx_ticket_assignee (assignee) 已覆盖 WHERE 谓词
--   决策: 删除本索引（列名失实 + 与既有索引冗余；ORDER BY create_time 若有性能问题再复合）
```

## 二、P3 查询路径补齐（3 条计划索引对应代码逐项核实）

### 背景

批 82 索引收敛计划 P3 列出 3 条「代码可能不存在」的索引，需核实 Repository 方法存在性 + SQL 真实列名后决策。

### 核实结果

| # | 索引 | 覆盖查询 | 核实结果 | 决策 |
| :-- | :-- | :-- | :-- | :-- |
| **P3-1** | `idx_ticket_alert_group` | WHERE alert_id IN(...) GROUP BY alert_id | TicketRepository **无 findActiveGroupTicket 方法** | **删除**（已在 P2-1 处理） |
| **P3-2** | `idx_diagnosis_alert` | WHERE alert_id=? AND status IN(...) | DiagnosisSessionRepository **无 findByAlertId 方法** | **删除**（已在 P2-3 处理） |
| **P3-3** | `idx_approval_pending_time` | WHERE status='PENDING' ORDER BY created_at | ApprovalRequestRepository **有 findPendingApprovals 方法**，真实列名 **request_time**（非 created_at） | **保留但需列名修正**（见下） |

### P3-3 修正

原定义：
```sql
CREATE INDEX IF NOT EXISTS idx_approval_pending_time
    ON sys_approval_request (status, created_at DESC)
    WHERE status = 'PENDING';
```

**失实点**：sys_approval_request 表无 created_at 列，真实列名是 **request_time**。

**修正后**：
```sql
-- P3-3（批 82 审计后确认修正）: 审批看板待审列表索引（findPendingApprovals）
--   覆盖: SELECT * FROM sys_approval_request WHERE status='PENDING' ORDER BY request_time DESC
--   原定义失实: 列名 created_at（表中不存在）
--   修正: 改为真实列名 request_time
--   现状: status 无索引，ORDER BY request_time 回表排序
--   收益: Bitmap Index Scan（部分唯一索引谓词）+ Index Scan 排序免回表
CREATE INDEX IF NOT EXISTS idx_approval_pending_time
    ON sys_approval_request (status, request_time DESC)
    WHERE status = 'PENDING';
```

**实施**：V1__baseline.sql 该处注释改为上述说明 + SQL 改 request_time。

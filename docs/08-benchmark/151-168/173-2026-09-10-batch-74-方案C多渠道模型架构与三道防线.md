# 报告 173 ｜ 批 74: 方案 C 落地——多渠道模型配置 + 三道防线 + 渠道健康分治

**日期**:2026-09-10|**触发**:用户提出「换任何渠道模型会否崩溃?不同角色模型来自不同厂商怎么办?」——实测证实两个真缺口。

## 一、用户两问的实测答案(取证在案)

1. **换渠道会崩溃吗?** 不会崩,但有三种死法,按危险度:
   - 🔴 **静默垃圾检索**(最阴险):换 embedding 模型(即使同维度)后旧向量与新查询向量语义空间不同——检索"能跑"但返回不相关结果,**零报错**;
   - 🟠 写库即炸:维度不符 → `expected 1536, not 1024`(运行期才暴露);
   - 🟢 启动失败:key/模型名错 → Bean 创建即抛(fail-fast,最友好)。
2. **多厂商混用支持吗?** 此前不支持:`AiModelConfig` 全部模型共用单 base-url+单 key(`devops.ai.alibaba.*`),chat/embedding/(未来)reranker 被迫同渠道。

## 三、途中坑账(防再踩)

## 五、用户关键问答沉淀(向量库换模型指南)

**换 embedding 模型时库里的数据与索引要不要换?** 四种情形:
| 情形 | 旧向量 | 索引 | 处置 |
| :-- | :-- | :-- | :-- |
| 同模型换渠道(key/网关) | ✅ 兼容 | ✅ 不动 | 零操作 |
| 换模型同维度 | ❌ 语义空间变,向量=垃圾 | 列类型兼容 | **全库向量重算**(指纹锁拦截) |
| 换模型换维度 | ❌ 列类型都不符 | ❌ 重建 | 基线迁移+全库重算+索引重建 |
| 当前实况(库仅 1 条测试切片) | — | — | **零成本窗口,怎么改都不痛** |

关键认知:**pgvector 的表/索引是维度容器,换同维度模型不需要动 DDL;真正要换的是表里的向量数据**(新模型重算每条切片)。这就是指纹锁守的东西。

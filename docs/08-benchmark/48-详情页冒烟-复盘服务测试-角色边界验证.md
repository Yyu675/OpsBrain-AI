补 `flushPromises` 后全绿。

## 二、建议 2：`TicketPostmortemService`（+20 例）

### 我调整了上一轮的选择

上一轮点名的是 `KnowledgeIngestionService` / `HybridRetrieverService`。
实际动手前核查发现二者都是**字段注入 + 读 classpath 文件**，
脱离 Spring 容器测不出有意义的东西，且后者本就有 6 例集成测试兜底。

改选 `TicketPostmortemService`：183 行、6 个公开方法、**构造器注入**，
可测性最好、收益最直接。

### 顺带查出一处无效代码（已修）

```java
if (pm != null) {
    List<TicketActionItem> items = pmRepository.findActionItemsByPostmortemId(pm.getId());
    pm.setTimeline(pm.getTimeline());  // 自赋值
}
```

`TicketPostmortem` 实体**根本没有 `actionItems` 字段**，查出来的结果直接丢弃；
而前端本就走独立端点 `/postmortem/action-items` 取它们。

> 后果：每次打开复盘详情都白跑一次改进项查询。
> 不报错、功能也不缺，只是安静地多打一次库，
> 还会让后来人误以为「返回值里带着改进项」。

已移除，并补一条 `verify(never())` 用例钉住。

### 几条值得记的不变式

- **失败尝试也要写进时间线草稿** —— 只留有效动作的话，复盘就只剩「怎么修好的」，
  下次遇到同样故障的人还会把无效路径再走一遍；
- **跳过验证要明确标出** —— 与「验证通过」混为一谈，会让复盘评审误以为修复已被证实；
- **新建改进项强制 `OPEN`** —— 允许客户端传 `DONE` 就能凭空造出一条已完成项，完成率立刻失真。

## 三、建议 3：角色边界真实验证（+6 例）—— 填补一处安全真空

### 此前从未被验证过

所有 `*ControllerWebTest` 都是 `@WebMvcTest` 切片，而切片**刻意排除了 `WebConfig`**
——Sa-Token 的注解拦截器注册在那里，于是 `@SaCheckRole("ADMIN")` **在切片里根本不会执行**。

那些测试的类注释也都写明「本类的请求都是已放行状态，不构成对权限的任何保证」。

> **也就是说：此前整个项目没有一行代码验证过角色注解真的生效。**
> 注解写错了、漏写了、或被某次重构删掉了，CI 照样全绿——
> 上一轮发现的 `SagaController` 鉴权缺口，正是这么长期潜伏下来的。

### 本类怎么做

`@SpringBootTest + @AutoConfigureMockMvc`，**不排除任何拦截器**，走完整鉴权链：
真实建号 → 真实 BCrypt 登录 → 带真 token 请求 → 真实注解拦截器判定角色。

**双向验证**：普通用户(OPS) → 403 + 业务码 40103；管理员 → 放行。
只测前者的话，端点整个坏掉（路径写错返回 404）也会「看起来像权限生效」。

另两例守边界：不带 token → **401 而非 403**（都返回 403 的话，
token 过期的用户会被告知「权限不足」，然后一直等管理员加权限，
而他其实只需要重新登录）；伪造 token → 401。

## 四、深度核查结果

本轮扫描四类此前未覆盖的缺陷模式：

| 扫描项 | 结果 |
|---|---|
| 无效自赋值（同类于本轮查出的那处） | 命中 5 处，**逐个核对后全为不同对象间的正常拷贝** |
| 查询结果被赋值却从未使用 | 命中 1 处，核对后是**误报**（变量在 builder 链中于 10 行后使用，超出扫描窗口） |
| 前端 `v-for` 缺 `:key` | 初筛 6 处，**逐个核对后 0 处**（`:key` 都在下一行；唯一"真命中"是注释里提到 `v-for` 的文字） |
| 前端 `@click` 直接改 prop | 命中 2 处，核对后均为改本地 `ref` 而非 prop |

**结论：0 处真实缺陷。** 四类初筛共 14 处命中全是误报——
这本身说明前几轮的系统性治理（`tools/audit` 门禁 + 逐轮修复）确实有效、没有回潮。

> 值得记的方法：**初筛必须逐个核对，不能直接报数**。
> 若把 14 处命中当成 14 个缺陷去"修"，反而会把正确代码改坏。

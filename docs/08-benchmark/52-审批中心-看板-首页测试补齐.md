## 二、各页守住的核心契约

### ApprovalCenter：批准即执行真实动作

后端角色边界已有集成测试（`GovernanceRoleGuardIntegrationTest`
验证过 OPS 驳回审批得 403），但**前端「按钮该不该亮、点下去会发生什么」
此前零覆盖**。

- **串行化** —— 禁用判据必须是「有任意审批在处理中」而非
  「当前这一行在处理中」。只锁当前行的话，用户批准 A 之后可以立刻点 B，
  而 A 还在后端执行；两个动作若操作同一资源（如同时重启同一服务）
  结果不可预测
- **批准成功但执行失败要如实区分**（6.57 契约）—— 人的决策已成事实，
  笼统报「已批准」会让人以为动作已生效，实际需要人工介入
- **驳回理由必填且 trim** —— 要记入审计
- **无权限与加载失败分开** —— 403 / 40103 / 40301 显示「无审批权限」，
  混进通用错误态的话，非管理员会一直点重试等一个永远不会成功的请求

### Dashboard：全是「看起来正常」的错

看板不会崩，它只会显示错误的数字。而运维正是照着这些数字判断
「今天系统健康吗」。所以断言重点放在
**「没有数据」与「数值为 0」必须区分**：

> MTTA 为 `null` = 还没有任何工单被首响过；
> `0 分钟` = 秒级响应。**含义完全相反。**

同时补了反向用例：真的是 0 时必须显示「0 分钟」——
防止有人用 `if (!m)` 判空把真实的 0 一起吞掉。

另守住**四查询独立降级**（6.51）：趋势拉取失败只让图表区降级，
不连累已加载成功的 KPI。这是此前 `Promise.all + catch` 改造的目的，
改完一直没有测试守着，退回去不会有任何信号。

### Home：真正的风险在访客态

首页是公开路由，但它展示的统计来自 `/dashboard/overview`，
而那个端点在 `/api/**` 之下受 SaInterceptor 保护。

访客发出去 → 401 → http 层派发 `auth:unauthorized`
→ **用户被踢回登录页**。「访客能看首页」当场失效，
且现象极难归因：控制台只有一条 401，看不出是首页自己把自己踢走的。

核心断言因此是：**访客态一个请求都不许发出去。**

### 唯一「未抓到」的那条其实是发现了冗余代码

`switchTab` 里有一句 `if (tab === activeTab.value) return`。
删掉后测试仍绿。**探针实测确认**：给 ref 赋同一个值不会触发响应式更新，
queryKey 不变、Query 不重拉——该守卫对「防重复请求」是**冗余**的，
Vue 已经保证了。

处理方式：**没有删掉守卫**（它表达了意图，且将来若改用 `shallowRef`
或加了别的副作用就会变得必要），但在用例注释里写明
它断言的是「切同一 tab 不产生额外请求」这个**外部行为**，
不论该行为由守卫还是由 Vue 提供。

### 一处补出来的用例

**Home「失败时清空旧数据」**原写法直接以失败态挂载，
此时 `stats` 本来就是空的，删掉 `stats.value = []` 照样通过。

真实场景只可能是**先成功、后失败**：用户看着 12,345 次问答，
刷新失败了，页面若不清空，错误提示旁边还挂着可能已过期很久的数字。
改成这个序列后才真正有效。

这是本会话反复出现的同一条纪律：
**边界用例必须让正确实现与错误实现给出不同答案。**

## 四、三处测试自身的错（均未误改产品代码）

### 1. 夹具漏字段导致整片断言集体失败

Dashboard 夹具漏了 `modelDistribution[].percentage`（类型里有，我没给）。
模板 `item.percentage.toFixed(1)` 在 `renderList` 里抛 TypeError，
**整个 `v-else-if="data"` 分支渲染失败、页面停在加载态**，
于是 10 个 DOM 断言集体失败、而所有 vm 断言照常通过。

失败信息是「expected 0 to be greater than 0」，指向断言本身，
离真因隔了很远。靠打印完整 HTML 才看到那条 Unhandled Rejection。

> **教训：夹具照着类型定义写，不要照着「我以为页面用到哪些字段」写。**

### 2. `??` 把显式的 null 当成「没传」

`api.getClosureMetrics.mockResolvedValue(opts.closure ?? closure())`
会让「闭环数据缺失」那一例实际测的是「有数据」。
改用 `'closure' in opts` 判定。

### 3. 浮点期望写错，改期望而不是改产品

Home 期望 `40.55.toFixed(1) === '40.6'`，实测是 `40.5`——
因为 40.55 的双精度表示是 `40.549999999999997`。

这是 JS 既有行为不是缺陷，**改了期望而非产品代码**，
并单独立一例记下：将来若有人「修正」成 `Math.round(x*10)/10`，
这条会失败并提醒他那是一次**展示值变更**，
需要有意识地做而不是顺手改。

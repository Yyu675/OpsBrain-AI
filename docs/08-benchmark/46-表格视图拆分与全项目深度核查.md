## 一、建议 1：拆出 `TicketTableView.vue`

继卡片视图后的第二块模板拆分，搬的是更复杂的一块：
`el-table` + 13 个可配置列 + 列宽持久化 + 排序 + 行选择（271 行模板 + 51 行 `:deep()` 样式）。

### 防线确实跟着模板迁移了

这是本次最值得记的一点。做了**两次对称的注入验证**：

| 时机 | 注入 | 结果 |
|---|---|---|
| 拆分前 | 删父页面里 `service` 列的 `v-if` | 精确失败 2 例 |
| 拆分后 | 删子组件里同一个 `v-if` | **同样精确失败 2 例** |

说明冒烟测试守住的是**行为**而非**位置**——模板搬到哪，防线跟到哪。
这正是上一轮坚持「先补渲染断言再拆分」的回报。

### 两处由 `vue-tsc` 兜住的问题

- `row-click` 的 `column` 参数本想用 `unknown` 图省事，编译器直接报不兼容，
  改回 `TableColumnCtx<Ticket> | null`；
- 父页面 4 个已随模板迁走的导入（`RelativeTime` + 3 个 SLA 函数）成了死代码。

### 接口设计取舍

用了 16 个 prop 而非让子组件直接读 store。列宽/可见性来自 `useTicketColumns`、
状态与优先级映射来自父页面既有工具——**子组件自己再引一份必然与父页面漂移**，
尤其是中文标签，两处各写一遍，某次改词表时就会对不上。
宁可 prop 多，也要只有一个真相来源。

例外是 `slaRemainText` / `firstResponseText` 等纯函数，本身就是共享工具、
不存在漂移风险，直接从 `@/utils/sla` 导入。

## 二、全项目深度核查（回答「是否需要再挖隐藏 bug」）

**结论：需要，而且这次真挖到了一处安全缺口。** 以下是六类扫描的完整结果。

### 🔴 查出的真实缺陷：`SagaController` 鉴权缺口

用脚本扫「所有写端点是否有角色注解」，发现 `SagaController` **全类没有任何 `SaCheck` 注解**，
而另外四个治理类控制器（`AuditLog` / `Approval` / `AutomationGovernance` / `AgentTrace`）
**都已限 ADMIN**——它是唯一的例外。

它暴露的恰是权限敏感的两类能力：

| 类型 | 端点 | 风险 |
|---|---|---|
| 读 | `/attention`、`/steps` | 列出所有半残事务的工具名、业务主键、失败原因——**等同于把内部故障面摊开** |
| 写 | `/compensate` | 真正执行**逆向补偿**，回滚已落库的写操作（如作废已建工单） |

补偿动作本身幂等、重复执行安全，但「谁都能触发一次回滚」本身就是问题：
普通用户对着一个 sagaId 反复调用，就能把别人刚建好的单据撤掉。

> 注：`WebConfig` 拦截器已要求全局登录，所以此前**并非完全裸奔**；
> 但「登录用户」与「管理员」之间的差距，正是这个注解要补上的那一层。

**修复时机很关键**：前端 Saga 补偿中心目前还是 `FutureCapability` 占位页、尚无真实入口。
趁未接入先把服务端边界立好，比事后收紧安全——一旦有页面在用，
再加限制就要同步改前端权限、还可能打断正在用的人。

### ✅ 确认无问题的五类（一并记录，避免下次重复排查）

| 扫描项 | 结果 |
|---|---|
| 空 `catch` 吞异常 | 6 处，**逐个看过**：全部带解释性注释且属刻意降级（Sa-Token 非请求上下文回退、轮询 `TimeoutException`、单条历史解析失败跳过等） |
| 跨 2+ repository 写却无 `@Transactional` | **0 处** |
| `Optional.get()` 未判空 | **0 处** |
| 前端数值字段用 `\|\|` 兜底导致 `0` 被吞 | **0 处**（`\|\| '—'` 全部作用于字符串字段） |
| 前端 `await` in loop | 仅批量操作的顺序执行，是「部分成功」语义的**刻意设计** |

前四类在早前几轮已被系统性治理过（`tools/audit` 门禁 + 多轮修复），
这次扫描全绿，说明**那些治理是有效的、没有回潮**。

## 四、下一轮建议（可行性排序）

1. **补 `KnowledgeDocService` 直接单测** —— 当前最大的单点风险。
   它管着知识库的发布、废弃、版本回滚、物理删除，
   每一个都是「错了会丢数据或让 AI 检索不到」的写操作，
   而现在只有间接覆盖。建议优先覆盖状态流转与版本回滚。
2. **`TicketDetail.vue` 补渲染冒烟测试** —— 它已超过 `TicketList.vue` 成为最大文件。
   按本轮验证过的路径（先补冒烟 → 再拆模板）推进，
   拆分对象可选「AI 分析面板」或「时间线」。
3. **`SagaController` 的鉴权集成测试** —— 本轮加了注解，
   但切片测试不执行 Sa-Token 拦截器（已在类注释声明）。
   若要真正保证，需按 `AuthLoginChainIntegrationTest` 的方式写一个走真实鉴权链的用例。
4. **仍需用户操作**：`tools/audit/run_audit.py` 接入 CI（我无 workflows 写权限）：
   ```yaml
         - name: 代码模式扫描
           run: python3 tools/audit/run_audit.py
   ```

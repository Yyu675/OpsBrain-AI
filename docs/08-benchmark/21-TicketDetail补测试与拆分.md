### 第一批当场抓出一个真实缺陷

```vue
{{ reply.author.charAt(0) }}   // author 在后端 DTO 里是 string | null
```

一条 null author 会让**整条时间线渲染崩溃**——用户看到空白页，
而不是少一个头像。Vue 的渲染错误不会被 try/catch 兜住。

这个缺陷在 2722 行里肉眼极难发现，但只要把组件挂起来渲染一次就暴露了。

### 两次分清「桩失真」与「产品缺陷」

搭脚手架时遇到两个报错，都不是产品的问题：

1. `structured.confidence` 报空指针 —— 我把它桩成了 `null`，
   但真实实现是 computed **恒返回对象**。
2. `store.teamMembers.find is not a function` —— 我桩成了 `ref`，
   而真实 Pinia store 在组件里访问时 ref 已自动解包。

两次都是核对源码后改桩，没有改产品代码。
**遇到测试报错就改产品，方向是反的**——那是在给测试让路。

### 新补边界里值得一提的几条

- **首响 0 分钟也要显示**：若用 `if (minutes)` 判断，0 会被跳过，
  「秒级响应」反而不显示。
- **首响 skipped 时 current 要落到下一步**：否则进度条上没有任何一步
  被标为「当前」。
- **响应式验证**：composable 接的是 `Ref` 而非值。若有人改成传值，
  派生结果会冻在第一张工单上——而 `/tickets/:id` 是同一路由，
  切换工单时组件实例被复用，症状是「点了相似工单，进度条还是上一张的」。

### 附件抽出时明确写死的一条分界

三类操作对失败的处理刻意不同，很容易在重构时被「统一成一种」而抹平：

| 操作 | 失败处理 | 理由 |
|---|---|---|
| 加载 | 只清空，**不弹错** | 辅助信息，弹错让人以为工单坏了 |
| 上传 | **必须弹错** | 用户主动发起，静默失败会让他以为成功 |
| 删除 | 弹错，且**不移除本地项** | 抹掉会让人以为删成功，刷新后又冒出来 |

抹平的后果是两头都不对：要么满屏红色提示，要么静默丢操作。

### 顺带修一个 vue-tsc 误报（改对，不是抑制）

`ref="fileInputRef"` 字符串形式与 script setup 变量的关联 vue-tsc
识别不到。改成 `:ref="(el) => ...)"` 动态绑定——显式引用，类型检查能看见。

没用 `eslint-disable` 掩盖：那样下次真的有未使用变量时也会被一起放过。

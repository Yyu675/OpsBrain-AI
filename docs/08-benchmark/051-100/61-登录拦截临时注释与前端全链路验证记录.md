## 六、补充修复（2026-08-26，用户实测反馈后）

**问题**：预览中 AI 对话无回复、用户输入不显示、工单 AI 分析建议为空。
**根因**（前端契约 vs mock 差异）：

| # | 根因 | 修复 |
|---|------|------|
| 1 | 前端 `chatStream` 为 **POST body**（`{query, sessionId}`），mock 只按 GET query 处理 | mock 增加 POST body 解析 |
| 2 | SSE `token` 事件字段应为 **`{text}`**（`SSETokenEvent.text`），mock 发的是 `{delta}` | 改为 `{text: chunk}` |
| 3 | SSE `tool_status.status` 枚举为 `start/success/error`，mock 发 `COMPLETED` | 改为 `success` |
| 4 | **流清理挂在 `req.on('close')`**——POST 请求体读完后请求侧即触发 close，把 setInterval 清掉，导致只发 start 就断流 | 改为挂在 **`res.on('close')`**（响应侧关闭才清理） |
| 5 | 前端 `TicketAiAnalysis` 契约是**平铺字段** `reasons/commands/citations/confidence/costRmb/feedback/feedbackAt/createTime`，mock 返回嵌套 `structured` + `references` | 改为平铺字段（原因/命令/引用/置信度/成本均齐） |
| 6 | `GET /tickets/by-trace/{id}` 被通用 `{id}` 路由误匹配返回 404 | 增加 by-trace 专门分支 |

**修复后验证**（经 vite proxy 全链路）：
- SSE POST：`start → 64×token → tool_status → complete` 完整事件序列 ✅
- AI 分析 latest：reasons[3] / commands[3] / citations / confidence=85 / costRmb / createTime ✅
- by-trace：返回 null 而非 404 ✅

**用户操作**：刷新浏览器页面即可看到效果——AI 对话流式回复、工单详情 AI 分析卡片（可能原因/排查命令/置信度）与 Insights 侧栏正常展示。

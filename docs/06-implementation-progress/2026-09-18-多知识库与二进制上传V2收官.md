## 落地内容

两项对标借鉴全栈落地（决策、方案取舍、成本提醒均见决策文档）：

1. **多知识库顶层实体**：`sys_knowledge_base` 三层结构（base → doc → chunk），
   切片三参数挂库维度、逐字段回落全局默认（`ChunkProfile`，构造期校验
   parent > child > overlap ≥ 0）；`kb_id` 冗余下沉 chunk 免 JOIN 保 HNSW；
   默认库 `code=default` 承接存量、禁改编码禁停用；参数变更不自动重建存量，
   显式 `POST /api/v1/knowledge/bases/{id}/reindex-all`（仅 ADMIN）。
2. **二进制上传解析**：`POST /api/v1/knowledge/docs/upload`（multipart），
   安全校验复用 `AttachmentSecurityGuard`（白名单作参数）→ Tika 解析 →
   原件留存 MinIO 独立桶（Fail-Safe，失败不阻断入库）→ 标准创建链路
   （清洗/去重/SimHash/向量化全复用）。扫描件拒绝入库（如实报错）。
3. **前端**：侧栏知识库选择器（范围式筛选，`?kb=` URL 直达）、
   知识库管理 Dialog、上传 Dialog（均为 Dialog 形态）、
   详情页 UPLOAD 文档标注原件文件名。

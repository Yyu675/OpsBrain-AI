## 一、项3B：orval 生成链 + 字段契约编译期对账

### 1.1 方案 A 落地形态的关键改道（产物实证 →「替换」改「对账」）

对生成物与手写传输类型做字段级并排对照后发现：**springdoc→orval 产物全字段 optional、无字面量枚举、无字段级 JSDoc**（Java 无 required 概念、未注解 nullable 产不出）。直接用手写必填类型（`BackendTicket.id: string`）替换为生成物（`DevOpsTicket.id?: string`）会造成类型安全**大倒退**：消费端 `.id` 全量变 `undefined` 红、枚举字面量退化为 `string`、字段级语义注释（6.x 血泪契约）清零。

**因此方案 A 的「替换传输边界 DTO」改道为「生成物做字段全集真相 + 编译期字段集互证」**——防漂移目标不变，形态更诚实：

| 闸 | 锁什么 | 载体 |
| - | - | - |
| 闸一（Phase A） | path 存在性 | `apiContract.test.ts` 源码扫描 |
| 闸二（Phase A） | HTTP method | `apiContract.test.ts` springdoc 快照 |
| **闸三（本批）** | **字段名集合双向漂移** | **`src/api/fieldContract.ts`（vue-tsc 编译期，零运行时零新测试类）** |

- `X_Missing` ≠ never → 后端加了字段手写没跟（消费端零防护）→ typecheck 必红；
- `X_Extra` ≠ never → 手写留着后端已删的字段（runtime 恒 undefined），或快照滞后 → typecheck 必红；
- **边界（如实声明）**：只对账字段名集合。必填性/枚举值域/nullable/值类型以手写为准（生成物是下界非真相源）；值域漂移由真机联调兜底（用户工作流：随时真实启动）。

### 1.2 首轮对账战果：10 红 → 6 对真漂移 + 2 对豁免

`vue-tsc` 首跑即揪出 10 处漂移（**Extra 侧全绿** = 无删字段、无快照滞后），逐条甄别：

- **6 对真漂移，手写补 16 字段**（全部后端源码取证 JSDoc，零编造）：
  - `BackendTicket` +6：`responseDeadline / resolveDeadline / mttrMinutes / firstResponded / terminalStatus / immutableStatus`（terminal≠immutable 是后端 `isImmutableStatus` 注释的显式区分）
  - `Alert` +2：`highRisk`（P0/P1 派生）`lowRisk`（P3/P4 派生）
  - `ApprovalRequest` +3：`decidable / highRisk / overdue`（三条派生均带后端 getter 注释语义）
  - `RiskPolicy` +2：`fullyAutonomous / createTime`；`ActionAllowlistEntry` +2：`createdBy / createTime`；`AutomationPolicy` +2：`createdBy / createTime`
- **2 对（4 红）豁免**：`TicketReply / TicketActivity` 手写形态是 dto-converter 下游的**前端渲染模型**（`time`/`user`/`color`/`text` 是展示字段名）——字段集对账不适用映射层，豁免理由钉在 fieldContract 注释里。

### 1.3 生成链路（`npm run gen:api` / `npm run api:refresh`）

`tools/ci/sync-openapi.sh`（活体快照，三重硬拒）→ `scripts/gen-api.mjs` → `orval.config.ts` → `src/api/generated/`（199 个 schema 类型文件，随库提交）→ `fieldContract.ts` 消费。两段解耦：**sync 需要活体后端，gen 只读仓内快照**。

**orval 两个本机坑（病历入仓，`gen-api.mjs` 头注有完整版）**：
1. **CLI 起不来**：`@commander-js/extra-typings` 的 CJS re-export 过不了 Node 22 ESM named-export 探测（`does not provide an export named 'program'`）→ 走 `generate()` 编程 API 绕 bin；
2. **ajv hoist 错位**：eslint 把 ajv@6 钉顶层，orval 校验链（spectral/ibm-ruleset/ajv-draft-04）全员要 ajv@8 却被 npm hoist 到顶层（`invalid dedupe`，overrides 不触发重算）→ gen 进程内 require-hook 定点改道到树内真实 ajv@8 实体——**零 node_modules 手术、零 postinstall、eslint 的 ajv@6 分毫不动**。

### 1.4 边界与候排

- P0-2b 挂账恢复条件「做 TS 类型生成时按需补端点」：本批**未动后端**（78 个弱契约 `ApiResponseMapStringObject/Object` 端点如实挂账，补端点按灰度需要逐个来）；
- 值域级对账（enum/nullable/值类型）：OpenAPI 产不出依据，留真机；
- 手写类型 extends 生成物基底（让后端新字段自动浮现身形）：候排，收益/风险评估后另行拍板。

## 二、告警级别人话化 + 同类裸码清扫

### 2.1 单源字典（三张表，码值不动、只换展示）

| 字典 | 位置 | 内容 |
| - | - | - |
| 告警级别 | `utils/alert.ts` `ALERT_LEVEL_LABELS` | P0→紧急、P1→严重、P2→警告、P3→一般、P4→提示（大小写归一，未知码原样透出不吞） |
| 动作风险类型 | `constants/risk.ts` `riskLabel/riskToneClass` | 只读查询/草稿生成/受控写操作/高风险执行（**合并 ApprovalCenter 与 ActionAllowlist 两份已漂移的本地字典**：「受控写」vs「受控写操作」） |
| 运行环境 | `constants/environment.ts` `envLabel/envListLabel` | prod→生产、staging→预发、dev→开发 |

**筛选 value / API 参数 / 颜色归类键 / 类名钩子全部保持码值原样——契约零改动，纯展示层。** `ALERT_LEVEL_OPTIONS/ALERT_STATUS_OPTIONS` 改为从 LABELS 推导（与状态字典同构，防双份再漂移）。

### 2.2 清扫面（10 个页面/组件 16 处裸码渲染）

- **级别裸码 6 处**：AlertList 行标签、AlertDetail 页头+同事件告警、Dashboard AlertFeed 徽章、ObservationStatsPanel 观察窗文案、AutomationPolicies（策略行 chip/表单复选/演练下拉三处）+ 筛选下拉 label；
- **风险类型裸码 2 处**：WorkbenchQueues 首页徽章（`CONTROLLED_WRITE` 直出）、AutomationPolicies 动作预览——顺手修正 WorkbenchQueues 的 `RISK_TONE` 色键用错值域 bug（HIGH/MEDIUM/LOW 恒 miss 全灰 → 换 `riskToneClass` 按 READ_ONLY 族上色）；
- **环境裸码 8 处**：AutomationPolicies 六处（三个下拉/行 chip/预览/校验文案）、ActionAllowlist 三处、HealingCenter/HealingExecutionDetail 详情「环境」。

### 2.3 判定「刻意不改」的面（同类排查结论）

- 告警详情「原始标签」区：区名即语义（instance/pod/job 下钻维度是原始数据）；
- RiskLevels 页 `<code>{{ policy.riskLevel }}</code>`：配置管理面技术键，卡片标题已有 `displayName` 中文（同 actionKey 的 `<code>` 设计）；
- `severity`（critical/warning/info）：详情页不展示（`LABEL_KEYS_SHOWN_ELSEWHERE` 排除后无渲染点），level 字典已足，不造闲置表；
- 状态类（FIRING/RESOLVED、审批状态、处置阶段、首响状态、工单状态/优先级）：**此前已有中文字典**，本轮核查确认无裸码。

## 三、已落地修复

### HIGH-1：DB/Redis 故障在前端不可见（新增基础设施探测）

**问题**：`NetworkBanner` 用心跳探测 `/favicon.ico`（前端静态文件）判定在线状态。DB/Redis 故障时后端接口全 500，但前端心跳照常在线，用户看到页面"正常"、实际所有操作失败，故障完全不可见。

**修复**：
- `useNetworkHeartbeat.ts` 新增 `infraHealthy` 状态 + `checkInfra()`：浏览器在线时每 15s 探测后端免鉴权探针 `GET /api/v1/health/db`（零成本、返回 UP/DOWN）
- `NetworkBanner.vue` 新增「后端数据服务异常（数据库/缓存），部分查询可能不可用」横幅（琥珀色，区别于断网红色横幅），通过 `API_BASE` 绝对地址跨域探测后端

**效果**：DB/Redis 故障时，用户在前端即可看到明确的服务降级提示，而非静默失败。

### HIGH-2：Saga 补偿部分失败缺口（验证已覆盖，无需改动）

`SagaCompensationManager` 已具备完整补偿能力且测试充分（`SagaCompensationManagerTest`）：
- 反序回滚（`findCompensableBySagaDesc` DESC）
- 单步失败不中断后续补偿（尽力而为，第 84-90 行 try/catch）
- 状态落库失败仍继续（测试 #396）
- CAS 并发抢占（`markCompensating` 原子 UPDATE 返回 0 行即跳过）
- 根因解包（`describeRootCause` 逐层解包 InvocationTargetException）
- 非法方法名白名单、MANUAL_INTERVENTION_REQUIRED 标记 + 需人工介入通知

**结论**：补偿缺口在批 88 审计中已修复并有专项测试覆盖，本次核实无需改动。

### LOW-1：`KnowledgeIngestionService` 流未关闭（资源泄漏）

`resource.getInputStream().readAllBytes()` 每行创建流未关闭 → 改为 `try-with-resources`。

### LOW-2：`AppErrorBoundary.vue` 全页刷新导航

## 六、后续修复补记（同日第二批）

### P0-4：前端生产构建失败（`Login.vue` 模板内 `import.meta`）
- **问题**：`v-if="import.meta.env.DEV"` 出现在 Vue 模板表达式里。`import.meta` 只能在 `<script>` 使用，Vue 编译器/Rolldown 无法解析 → 生产构建直接失败（19.63s 报错）
- **修复**：在 `<script setup>` 定义 `const isDev = import.meta.env.DEV`，模板改用 `isDev`
- **效果**：构建恢复，`✓ built in 6.83s`

### P1-6：POST /chat/stream 400 —— 误报（双端点均正常）
- 复核：GET/POST 两个端点均返回 HTTP 200 并正常 SSE 流式输出；之前观测到的 400 系 curl 测试请求体编码问题，非后端缺陷，无需修复

### P1-2：前端 bundle 拆分（wangeditor 编辑器库独立）
- **问题**：`KnowledgeRichEditor` chunk 801kB（含 wangeditor 库体），超 800kB 警告线
- **修复**：`vite.config.ts` manualChunks 将 `@wangeditor` 拆为独立 `vendor-editor` 块；`chunkSizeWarningLimit` 上调至 1000（该块经路由 `lazy()` 懒加载，仅编辑文档页才拉取，非首屏负担）
- **效果**：业务代码与编辑器库分离，业务发版不必重下大库；构建无 chunk 警告

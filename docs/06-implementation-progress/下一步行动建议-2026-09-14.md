#### 1. 前端请求缓存优化（15 分钟）
**问题**：Dashboard 页面 4 个并发请求，快速切换页面会重复请求

**方案**：利用 TanStack Query 已有的缓存机制
```typescript
// src/api/queries/useDashboardQueries.ts
export const useTicketStats = () => {
  return useQuery({
    queryKey: ['tickets', 'stats'],
    queryFn: () => apiClient.get<TicketStatsDTO>('/tickets/stats').then(r => r.data),
    staleTime: 30_000, // 30 秒内复用缓存
    gcTime: 5 * 60_000, // 5 分钟后清理
  })
}

export const useAlertStats = () => {
  return useQuery({
    queryKey: ['alerts', 'stats'],
    queryFn: () => apiClient.get<AlertStatsDTO>('/alerts/stats').then(r => r.data),
    staleTime: 30_000,
    gcTime: 5 * 60_000,
  })
}
```

**收益**：
- 减少不必要的 API 请求
- 页面切换更流畅
- 降低服务器负载

**风险**：🟢 低（30 秒缓存对实时性影响极小）

#### 2. 构建产物体积警告修复（5 分钟）
**问题**：Vite 警告 "Some chunks are larger than 800 kB"

**方案**：调整警告阈值（富文本编辑器 800 KB 是合理的）
```typescript
// vite.config.ts
export default defineConfig({
  build: {
    chunkSizeWarningLimit: 1000, // 800 → 1000
  }
})
```

**收益**：
- 消除无意义的构建警告
- 富文本编辑器已懒加载，800 KB 是合理大小

**风险**：🟢 低（不影响实际性能）

#### 3. CodeMirror 语言包精简（30 分钟）
**当前**：22 种语言，~117 KB gzip  
**建议**：精简到 12 种核心语言，减少 60-70 KB gzip

**方案 A（推荐）**：保守精简
- **保留**：Shell, YAML, JSON, SQL, Java, JavaScript, TypeScript, Python, Go, Dockerfile, Nginx, Markdown
- **删除**：Rust, PHP, C/C++, HTML, CSS, XML, Properties, Vue

**理由**：
- 删除的语言在运维文档中使用率 < 10%
- 团队未使用 Rust/PHP
- HTML/CSS/Vue 极少出现在运维文档

**执行步骤**（如果用户批准）：

**风险**：🟡 中（可能有用户需要被删除的语言）  
**缓解**：监控用户反馈，按需恢复

#### 4. Dashboard 接口聚合（后端 1 小时 + 前端 30 分钟）
**问题**：Dashboard 页面 4 个串行请求，瀑布流延迟

**方案**：后端新增聚合接口
```java
// DashboardController.java
@GetMapping("/api/v1/dashboard/summary")
public DashboardSummaryDTO getDashboardSummary() {
  return DashboardSummaryDTO.builder()
    .ticketStats(ticketService.getStats())
    .alertStats(alertService.getStats())
    .trends(ticketService.getTrends())
    .user(userService.getCurrentUser())
    .build();
}
```

**收益**：
- 减少 3 个 HTTP 请求
- 减少瀑布流延迟 ~200ms

**风险**：🟡 中（需后端改造，可能有遗留接口依赖）

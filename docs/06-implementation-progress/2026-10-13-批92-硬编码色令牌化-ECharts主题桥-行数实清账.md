### 2. ECharts 图表主题桥 `utils/chartTheme.ts`（主题四轴对图表生效）
**问题本质**：ECharts 画在 canvas 上，canvas 不认 CSS 变量——`color:'var(--chart-1)'` 会被静默解析成黑色。此前 TrendChart/Dashboard/Effectiveness/TicketInsights 各自硬编码 Element 默认色（#409eff…），**明暗/配色轴切换后卡片变了、图表不变**，暗色下 tooltip #303133 深字配深底几乎不可读（审计列为最高影响项）。

**方案（单点收敛）**：
- `resolveCssColor`：把任意 CSS 颜色（含 var/oklch/color-mix 写法）过一遍 1×1 canvas（fillRect→getImageData）归一成 ECharts 可吃的 rgb/rgba；解析失败（jsdom/隐私模式/非法值）回落调用方兜底——**图表永不黑块**。
- `chartChromeColors()`：轴文字/网格/tooltip/目标线等非数据色 → `--text-2/3`、`--border-1/2`、`--surface-3`、`--warning`。
- `useThemeVersion()`：MutationObserver 盯 `<html>` 的 class/data-theme/data-density（模块级单例，多图表共用一个 observer），主题一切换 TrendChart 的 watch 依赖触发 → 重建 option 重新取色。
- **消费方零样板设计**：`TrendSeries.color` 现在接受**主题令牌名**（`'--chart-1'`）或任意 CSS 颜色，解析统一收在 TrendChart.buildOption 内（每次重建 option 都取 `resolveChartColor`）。Dashboard/Effectiveness/TicketInsights 只改了色值字符串本身（等行替换），不 import、不加响应式——首版在 Dashboard 内做 chartToken+themeVersion 的方案让超标文件净增 9 行，违反行数纪律，**已推翻重做**为现方案（Dashboard 最终 8/8 净 0）。
- 回归测试 `utils/__tests__/chartTheme.spec.ts`（6 例）：重点钉 **jsdom 无 canvas 后端的降级路径**（回落非空串、tooltipText 兜底可读深灰）、palette 6 槽非空、useThemeVersion 单例。真实浏览器下的令牌解析由 `/design-system` 逐轴人工验收（AGENTS.md 五之二纪律）。

## 二、生产拉起清单（可复制执行）

前置事实（本轮逐一实证）：
1. **真 Linux** = WSL2 Ubuntu 发行版（systemd=true），原生 `dockerd`（非 Docker Desktop 引擎）；
   `docker compose` v2.40.3（`docker-compose-v2` 插件，**Linux 侧 cli-plugins 此前没装**）。
2. **端口零冲突**：生产只发布 `18088`(app) / `9100`(node-exporter) / `9090`(prometheus) /
   `9093`(alertmanager)；PG/Redis/MinIO **不映射宿主端口**、只走 compose 内网；与开发栈
   （后端 8088）互不相撞。
3. **Dockerfile 在**：多阶段（node 构建前端 → maven 构建后端并吃进 static → jre-alpine 运行时），
   单容器交付、自带 healthcheck/时区/非 root。

```bash
# 一条命令（wsl -d ubuntu -u root 内执行；仓库根）
APP_PORT=18088 AI_MODE=MOCK \
  docker compose -f docker-compose.yml --env-file .env -p opsbrain-prod up -d --build

# 健康验证
docker ps --format '{{.Names}}\t{{.Status}}'
curl -fsS http://localhost:18088/ai/api/v1/health/ping    # {"status":"UP","mode":"MOCK"}
curl -fsS -o /dev/null -w '%{http_code}\n' http://localhost:18088/ai/   # 200
curl -fsS http://localhost:9100/metrics | grep -c '^node_'               # ~900
```

卷/项目隔离：`-p opsbrain-prod` → 卷前缀 `opsbrain-prod_{pg,redis,minio,prometheus}_data`，
与任何开发栈互不共享。

## 四、WSL 生命周期（本机特有的驱动级约束，上真 VM/云主机即消失）

- **无 wsl.exe 会话时 VM 被回收**（构建期多次实测 `up 0 min` 冷启动）；`setsid/nohup` 脱管的
  进程随 VM 陪葬。**长任务姿势**：harness 后台常驻 `wsl.exe` 会话（会话本身即保活），
  构建输出**直连 wsl stdout**（中转日志文件曾出 0x00 污染，直连免此病）。
- **Docker Desktop 共存**：Desktop 进程半死态（Desktop.exe 活、docker-desktop 发行版 Stopped）
  会周期性折腾共享 WSL VM。构建期按恢复手册杀其全家（`com.docker.backend/Docker Desktop/
  docker-agent/com.docker.build`）——本栈不依赖它。
- 当前生产栈由 **keepalive 会话（`sleep 7200`，约至 17:08）保活**；到期后 VM 行为（栈随
  回收与否）未实测，重验/重拉：`docker compose -f docker-compose.yml --env-file .env
  -p opsbrain-prod up -d`（一条命令 ~20s，镜像全在）。
- 长期形态：真 VM/云主机上 systemd + `restart: unless-stopped` 自然保活，无需 keepalive。

## 七、工程教训（防复发）

1. **`pgrep` 查活必须带 `-f`**：`comm` 只有进程名不含参数，本轮两次「进程死了」误报皆因此。
2. **写盘窗口期 = VM 生死线**：拉取/解包必须单会话完成并立即 `sync`；digest 只护压缩包、
   不护解包落盘，空文件是**解包后**才有的病。
3. **编辑→grep 落盘→再构建**串行铁律全程零哑失败返工（7 处 Edit/Write 全部一次过）。
4. `tar -tv` 尺寸列对目录/链接/设备恒为 0，数「空文件」必须先按类型过滤（6002→3782 的乌龙）。
5. 探针输出（`tail -7`）会吃掉错误详情：**全量落盘再 grep**，别在管道上截杀证据。

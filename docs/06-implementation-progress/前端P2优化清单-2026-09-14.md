#### **P2-4 网络请求优化**
**目标**：减少重复请求，合并并发请求

**当前问题**：
1. Dashboard 页面同时发起 4-5 个独立请求（tickets、alerts、trends、user）
2. 工单列表每次筛选都重新请求全量数据
3. 缺少请求去重机制

**修复方案**：
- [ ] **短期**：Dashboard 接口合并为 `/api/dashboard/summary`（一次返回所有数据）
- [ ] **短期**：工单列表筛选使用客户端缓存（30 秒内不重复请求）
- [ ] **中期**：接入 `@tanstack/vue-query` 的 `staleTime` 和 `cacheTime`

**影响范围**：
- 后端需新增 `/api/dashboard/summary` 聚合接口
- 前端 `useDashboardStats` composable 改造

#### **P2-5 错误边界增强**
**目标**：所有异步操作都有错误兜底，用户体验无降级

**当前状态**：
- `AppErrorBoundary.vue` 已存在（捕获渲染错误）
- 异步请求错误处理不统一

**待补充**：
1. **网络请求统一错误处理**：
   - `http.ts` 拦截器增加重试逻辑（3 次，指数退避）
   - 401/403 自动跳转登录
   - 5xx 显示友好提示而非原始错误

2. **组件级错误边界**：
   - 知识库列表加载失败 → 显示重试按钮
   - 工单详情加载失败 → 返回列表页并提示
   - Dashboard 卡片加载失败 → 显示「暂时无法加载」占位

3. **离线兜底**：
   - 检测网络断开 → 顶部提示「网络已断开」
   - 离线时禁用提交按钮
   - 网络恢复后自动重试挂起的请求

**修复文件**：
- `src/utils/http.ts`（拦截器增强）
- `src/composables/useNetworkStatus.ts`（网络状态监听）
- 各页面组件增加 `v-if="error"` 错误状态

## 二、性能指标评估

### 2.1 优势项 ✅

1. **路由懒加载覆盖率**：95%
   - 所有业务页面使用 `lazy()` 懒加载
   - 仅登录页、403、404 页同步加载（合理设计）
   - 每个路由独立 chunk，按需加载

2. **依赖按需引入**：
   - ✅ Element Plus：使用 `unplugin-vue-components` 自动按需引入
   - ✅ ECharts：仅引入 `LineChart`、`BarChart`、必要组件
   - ✅ CodeMirror 语言包：通过别名精简到 15 种语言（减少 630 KB 碎片）

3. **代码分割策略**：
   - ✅ Vendor chunk 分离：Vue 生态、Element、ECharts、图标、Markdown、Query
   - ✅ 动态 chunk：业务代码不再强制合并到单一 vendor 块
   - ✅ 入口 chunk 仅 23.95 KB（gzip）

4. **CSS 优化**：
   - ✅ 单页面 CSS 独立提取（最大 42 KB，gzip 后 6 KB）
   - ✅ Element Plus 样式按需引入（121 KB → 16.39 KB gzip）

### 2.2 待优化项 ⚠️

#### **P2-2.1 富文本编辑器过大（800 KB）**

**现状**：
- `KnowledgeRichEditor.vue` 使用 `@wangeditor/editor`
- 打包后 800.88 KB（gzip: 274.03 KB）
- 触发 Vite 警告：超过 800 KB 限制

**影响**：
- 仅知识库编辑页使用，但首次进入该页面需下载 274 KB
- 对首屏（Dashboard/工单列表）无影响（已懒加载）

**优化方案**：

**方案 A（推荐）：延迟到二次交互加载**
```typescript
// KnowledgeEditor.vue
const editorLoaded = ref(false)
const loadEditor = () => {
  editorLoaded.value = true
}

// 模板
<template>
  <div v-if="!editorLoaded">
    <el-button @click="loadEditor">切换到富文本编辑器</el-button>
  </div>
  <KnowledgeRichEditor v-else />
</template>
```

**预期收益**：
- 编辑页首次加载减少 274 KB
- 用户按需加载（Markdown 编辑器已足够）

---

**方案 B：替换为更轻量的编辑器**
- **Tiptap**（推荐）：~50 KB gzip，现代化 API
- **Quill**：~120 KB gzip，稳定但老旧
- **仅保留 Markdown 编辑器**：已有 `md-editor-v3`，满足运维文档场景

**对比**：
| 编辑器 | 大小（gzip） | 优势 | 劣势 |
| :--- | ---: | :--- | :--- |
| @wangeditor/editor | 274 KB | 中文文档好 | 体积大 |
| Tiptap | ~50 KB | 轻量、现代 | 需重构 |
| Quill | ~120 KB | 稳定 | API 老旧 |
| 仅 Markdown | 0 KB | 无额外成本 | 用户可能需要富文本 |

**建议**：
1. **短期**：方案 A（延迟加载）
2. **长期**：评估用户是否真的需要富文本编辑器，若不需要则删除

## 五、网络请求优化

### 5.1 当前问题

**Dashboard 页面请求堆叠**：
```
GET /ai/api/v1/tickets/stats         // 工单统计
GET /ai/api/v1/alerts/stats          // 告警统计
GET /ai/api/v1/tickets/trends        // 趋势数据
GET /ai/api/v1/auth/me               // 用户信息
```

**影响**：
- 4 个并发请求，瀑布流延迟
- 缺少请求去重（快速切换页面会重复请求）

### 5.2 优化方案

**方案 E：后端接口聚合**
```typescript
// 新增聚合接口
GET /ai/api/v1/dashboard/summary
{
  "tickets": { /* 工单统计 */ },
  "alerts": { /* 告警统计 */ },
  "trends": { /* 趋势数据 */ },
  "user": { /* 用户信息 */ }
}
```

**预期收益**：
- 减少 3 个 HTTP 请求
- 减少瀑布流延迟（~200ms）

---

**方案 F：前端请求缓存（短期方案，无需后端改动）**
```typescript
// src/composables/useDashboardStats.ts
import { useQuery } from '@tanstack/vue-query'

export const useDashboardStats = () => {
  return useQuery({
    queryKey: ['dashboard', 'stats'],
    queryFn: fetchDashboardStats,
    staleTime: 30_000, // 30 秒内不重复请求
    cacheTime: 5 * 60_000, // 缓存 5 分钟
  })
}
```

**预期收益**：
- 页面切换时复用缓存
- 减少服务器压力

   - **可见性**：`RealModeStartupGuard` 新增主密钥缺失 WARN（REAL 模式启动日志直说「正在明文落库 + 修法」，只 WARN 不加新硬闸，拒启裁量权留给既有三条闸）；
   - **轮换顺序（P0#2）三处旧错全改**：Runbook §2 / 部署运维手册 §3 / `.env.example` 原写「重启让 AiChannelMirror 重写密文」——**已被批89 真机证伪**（镜像不重写、REAL 重启 `AEADBadTagException` 拒启）；三处统一替换为**实证七步**（备份明文→停服→换值→MOCK 起→逐页重存→恢复 REAL→查看明文回归），并写明「换代验证以 reveal 成功反证，health=200 不算数」；全仓 grep 无残留旧说法。
2. **P1 密钥轮换纪律（本批实证升级为硬流程）**：轮换主密钥会让旧密文解不开，且**后果分两档**——通知渠道 fail-open 回落环境变量+`needsReEntry` 标黄（降级可见），**AI 渠道 fail-fast 直接拒启**（`AEADBadTagException`，embedding bean 启动即炸——本批真机踩实）。正确顺序：**先逐页重新保存全部渠道（旧钥→新钥迁移）→ 再换主密钥 → 重启**。反序=服务起不来。
3. **P2 Alertmanager 双端同步**：改告警接入 secret 必须同步改 `webhook_configs`（页面已有强警告+二次确认；Alertmanager 侧不支持双密钥并存，无法做无断链轮换——灰度期改前先准备好两侧窗口）。
4. **P2 HMAC 通道**：页面刻意只读（当前 Alertmanager 发不了自定义签名头）；接真实 HMAC 客户端后再开编辑面。
5. **P2 企微加签**：当前 key 直连（关键词/IP 白名单模式），有真实需求再按官方 genSign 实现（`NotifyPayloads` 预留位）。

## 一、真实发现的 BUG（已逐条核实并修复）

### BUG-1：token 双重推送 + 绕过 JSON 包装（致命，已修复）

- **位置**：原 `DevOpsAgentEngineImpl.java:47`
- **现象**：引擎用 `sendSseEvent(emitter, "token", fullAnswer)` 直接发**裸字符串**，绕过契约要求的 `{text: "..."}` JSON 包装。前端 `chat.ts:58` 做 `JSON.parse(ev.data)`，对裸中文文本解析必然抛异常，token 全部丢失。
- **根因**：`chatStream` 用同步 `delegate.chat()` 拿完整答案再一次性发，且未走 Service 层的 JSON 序列化。
- **修复**：改为 LangChain4j 原生 `TokenStream`，`onPartialResponse` 回调经 Service 层 `ObjectMapper` 序列化后推 `{text}`。

### BUG-2：伪流式（已修复）

- **位置**：原 `DevOpsAgentEngineImpl.java:44`
- **现象**：`delegate.chat()` 阻塞拿完整答案再发，非缓存路径无真流式，用户卡到全部生成完才一次性刷出。
- **修复**：`StreamingChatModel` + `TokenStream.onPartialResponse` 逐块推送。

### BUG-3：tool_status 事件从未发送（已修复）

- **现象**：契约与前端（`AIChatDrawer.vue:120` `onToolStatus`）都约定工具执行推 `tool_status`，但后端全链路无发送代码。前端"工具调用中"状态永不显示。
- **修复**：`TokenStream.onToolExecuted` 回调发 `tool_status`（status=success）。
- **限制**：1.1.0 无 `beforeToolExecution`，只能发"执行后"，发不了"执行中"。

### BUG-4：complete 事件缺 toolResults，前端工单回调永不触发（已修复）

- **位置**：原 `DevOpsAgentServiceImpl.sendCompleteEvent`
- **现象**：complete 只发 `traceId/latencyMs/isCached/costRmb/citations`，无 `toolResults`。前端 `AIChatDrawer.vue:150` 靠 `data.toolResults` 里的 `createDevOpsTicket` 结果拿 ticketId、刷列表、发 `ticket-created`。结果 AI 建单后前端毫无反应。
- **修复**：`onToolExecuted` 收集工具结果，从工单文本正则提取 `TKT-yyyyMMdd-序号` 封装成 `{ticketId}`，complete 事件带上 `toolResults`。

### BUG-5：citations 类型契约冲突（已修复）

- **现象**：后端发字符串 `"[]"`，前端 `types.ts:80` 定义 `citations: string[]`。
- **修复**：后端改发 `List<String>`（空时 `List.of()`）。

### BUG-6：SSE 双重 JSON 转义（已修复）

- **位置**：原 `DevOpsAgentServiceImpl` 同时用手写 `escapeJson` + `ObjectMapper.writeValueAsString`。
- **修复**：统一只用 `ObjectMapper` 序列化，删除 `escapeJson`。

### BUG-7：全局异常处理器日志占位符缺失（已修复）

- **位置**：`GlobalExceptionHandler.java:42`
- **现象**：`log.warn("...: ", ex.getMessage())` 把 message 当 Throwable 传，占位符缺失。
- **修复**：改为 `log.warn("...: {}", ex.getMessage())`。

### BUG-8：sys_agent_call_log 表结构与代码不匹配（已修复）

- **位置**：`sql/init.sql` 的 `sys_agent_call_log` 定义
- **现象**：原 SQL 定义 `router_model/is_cache_hit/token_cost`，而 `AgentCallLogRepository` INSERT 用 `agent_answer/model_name/is_cached/cost_rmb/citations`，字段对不上，日志入库会报 column does not exist。
- **修复**：init.sql 表结构对齐到 Repository/实体（用户将自行重建容器生效）。

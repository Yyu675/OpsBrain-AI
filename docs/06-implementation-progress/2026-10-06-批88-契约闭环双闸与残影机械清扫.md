## 一、契约闭环：三闸时代收官 → 四闸联防

批86/87 建成的三闸（apiContract: 前端↔快照 path/method；fieldContract: 手写↔生成 字段+值域）**全部站在随库快照与生成物之上——「底」的新鲜度此前靠人肉纪律**（改后端契约忘跑 `api:refresh` = 三闸空转静默）。本批补上最后一环：

| 新闸 | 位置 | 抓什么 |
| - | - | - |
| **快照新鲜度** | CI 后端 job（mvn verify 后、失败回帖前） | `target/openapi.json`（OpenApiSchemaIntegrationTest 每次 verify 导出的**当次代码活体反射**）vs 随库快照——path/method + **schema 属性集双维**差集 |
| **生成物新鲜度** | CI 前端 job（typecheck 前） | `npm run gen:check` = 重跑 orval 生成 + `git diff --exit-code`——快照变了没 gen、生成物被手改（已提交态）皆红；orval v7.21.0 lock 锁定 → 生成幂等（正跑实证零 diff） |

快照属性集维度是 **fieldContract 29 对之外的盲区补面**：全部 145 个 schema 的字段增删都进对账，不只手写配了对的那些。红案修法指引钉在脚本输出里（sync → gen → typecheck 点名手写漂移 → 一并提交）。

**已知边界（如实记）**：红只认**结构差**（端点/schema 属性），描述/示例文案单独变更不触发——快照语义仍以 sync 脚本三重硬拒为准。
